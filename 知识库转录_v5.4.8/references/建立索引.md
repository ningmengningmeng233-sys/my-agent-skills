# 建立索引：执行协议 v5.0

> **何时读取**：进入“建库”“追更/重建”“运维（体检/删除/重命名/迁移）”分支时读取本文件对应小节。
> **执行原则**：精准可溯、有据可查；每一步都产生可核对证据；未通过门禁一律标注 `BLOCKED` 或 `NEEDS_REVIEW`。

## 0. 共享约定

- `<技能目录>` = 本技能 `SKILL.md` 所在目录；`<知识库>` = `<技能目录>/.env` 的 `INDEX_LIB_DIR`，为空则默认为 `<技能目录>/索引库`。
- 标准三目录固定为：`原文/`、`段索引/`、`书导航/`。
- 资料形态：
  - **长书**（主要）：长篇专著/书籍，单文件一书，具有章节层级，归档于 `原文/<书名-作者>/`。
  - **独立文档**（补充）：文章/笔记/技术文档/白皮书，单文件一文，通过 `--doc` 统一并入虚拟书「独立文档集」，归档于 `原文/独立文档集/`。
- 索引 frontmatter 的 `源文件` 必须是相对 `<知识库>` 的合法路径，严禁越界路径。
- 运行清单严格记录状态、资料名、源文件 hash、段数、验证码，不得输出 API key。

## 1. 建库流程：ROUTE → PREFLIGHT → PLAN → SPLIT → GENERATE → VERIFY → PUBLISH

### 1.1 ROUTE / INTAKE：确认资料类型

确认并记录：
1. 源文件**绝对路径**（支持 `.txt` / `.md` / `.pdf` / `.docx` / `.epub`；非 txt/md 文件由 `convert_docs.py` 自动前置转为标准 txt）；
2. 资料性质：长篇专著（长书）还是单篇独立文档；
3. 书名/资料名与作者（独立文档默认归入虚拟书《独立文档集》，作者可缺省或填“佚名”）；
4. `<知识库>` 位置及写入确认。

> **多格式自动解析转换管线（ADR-001）**：
> 若源文件为 PDF、Word（.docx）或 EPUB，执行前置结构化清洗转换（复杂版式/扫描件需人工复核）：
> ```text
> uv run python "<技能目录>/scripts/convert_docs.py" "<源文件路径>" --output "<转换后txt路径>"
> ```
> 转换后自动进入后续长书/独立文档切段流程。

### 1.2 PREFLIGHT：环境与数据预检

- 源文件存在、可读；
- `.env` 中 `OPENAI_API_KEY` 已配置（仅报告已配置/未配置）；
- 知识库三目录（`原文`、`段索引`、`书导航`）存在或可创建；
- 若已有同名资料，对比 hash 确认是追加续更、单篇增补还是覆盖重建。

### 1.3 PLAN：切分方案规划

- **长书**：
  - 章节结构识别（`chapter_patterns.py` 同源规则）；
  - 默认每 5 章一段；无章节时按约 1 万字符一段。
- **独立文档**：
  - 单文档独立成段（或按大节/万字分段），指定 `--doc` 标记。

### 1.4 SPLIT：切分并生成段文件

**长书命令**：
```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/split_segments.py" "<源文件>" --novel "书名" --author "作者" --lib "<知识库>"
```
追更追加 `--append`，多卷追加 `--volume "第X卷"`。

**独立文档命令**：
```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/split_segments.py" "<源文件>" --novel "文档名" --doc --lib "<知识库>"
```
段文件将安全归集至 `<知识库>/原文/独立文档集/`。

### 1.5 GENERATE：生成段索引（知识提取卡）

#### direct 模式（默认高性能模式）
```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_segment_index.py" "<知识库>/原文/<资料目录>/" --lib "<知识库>" --workers 32
```
脚本调用 LLM 严格依据《段索引模板》抽取知识提取卡，每段包含：本段概况、带类型与精确行号的知识点条目、逐字关键引用、实体、交叉引用与通用标签。自动进行两层行号校准与一致性检验。

**多节点 API 故障转移（v5.4.1）**：LLM 由 `llm_nodes.json` 定义的节点池提供，数组顺序即消耗优先级。前一个节点额度耗尽（401/402/403/404 或 429+额度关键词）时自动顺切下一个，无需人工干预；瞬时错误（5xx/超时）在同节点退避重试。建库前建议先体检：

```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/probe_pool.py"
```
全部节点耗尽时脚本明确报错并保留断点，补足额度后重跑同一命令即可续传。

#### 离线拔线演练（不依赖真实密钥）

「主节点 key 失效 → 自动顺切下一节点 → 日志留痕」这条链路可以在**完全离线**的环境里复验：

```text
python "<技能目录>/scripts/failover_drill.py"             # 人读报告；返回码 0 = 顺切按预期成立
python "<技能目录>/scripts/failover_drill.py --kill-all"  # 演练「全部节点失效」必须显式报错
python "<技能目录>/scripts/failover_drill.py --json"      # 机器可读结论（可重复比对）
```

脚本用内置假密钥搭一个三顺位合成节点池（主力 OpenAI / 次选 Anthropic / 兜底 OpenAI），用假传输接管 HTTP 层，
并额外熔断真实出网（`offline_lockdown`）；一次演练同时验证：401 归类为额度耗尽、跨协议 SSE 解析、
思考块剥离、止于首个健康节点（兜底节点零消耗）、坏节点不被回撞、`.api_pool_events.log` 事件留痕。
对应测试：`tests/test_failover_drill.py`（含变异用例——若顺切失效演练会判红）。

> ⚠️ **真实环境拔线演练尚未执行**（待办）。离线演练只证明调度逻辑正确，不证明六家厂商的真实额度、
> 鉴权行为与流式契约。首次实跑前的三步确认：① 在 `llm_nodes.json` 填入各节点真实密钥（六个 key 若仍是
> 同一占位符，建库与体检都会直接 `BLOCKED` 并点名节点，不发一次外呼）；② `probe_pool.py` 六节点全部返回可用；
> ③ 用 3 篇小样本实跑，跑完在 `<索引库>/.api_pool_events.log` 里确认出现 `EXHAUSTED → SERVED` 顺切记录。

### 1.6 VERIFY：结构、行号与内容门禁

按顺序严格执行三重校验（必须全部返回码 0）：

```text
# 1. 结构与编号连续性检验
uv run --with requests --with python-dotenv python "<技能目录>/scripts/_验证批次.py" --lib "<知识库>"

# 2. 关键引用与行号校准校验
uv run --with requests --with python-dotenv python "<技能目录>/scripts/verify_and_fix_lines.py" "<知识库>/段索引" --lib "<知识库>"

# 3. 行号体检与越界探测
uv run --with requests --with python-dotenv python "<技能目录>/scripts/check_line_refs.py" --lib "<知识库>" --detail
```

门禁要求：严格模式返回码为 0，无倒序、无越界、无待核引用。任一失败阻止进入 PUBLISH。

### 1.7 PUBLISH：生成/刷新书导航与本地向量索引

验证通过后执行：
```text
# 1. 生成书导航（长书 / 独立文档集）
uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_novel_index.py" --novel "书名-作者" --lib "<知识库>" --force

# 2. 生成/增量更新本地免Token语义向量索引（ADR-001）
uv run python "<技能目录>/scripts/semantic_index.py" --build --lib "<知识库>"
```
生成包含全局概况、段索引导航表、核心概念与知识关联链的综合书导航，并同步构建本地语义向量库（支持自然语言意境秒级召回）。

**向量模型与硬件自适配**：`semantic_index.py` 构建前会按 `.env` 的 `INDEX_EMBEDDING_MODEL` 选型；该项留空时自动按本机算力适配（探测 nvidia-smi 显存与系统内存，并优先复用 Ollama 已装模型，避免强制下载大模型）。查看本机推荐：

```text
python "<技能目录>/scripts/hardware_profile.py"
```

分档规则：显存 ≥6GB → `qwen3-embedding:8b`；≥3.5GB → `4b`；其余或纯 CPU → `0.6b`。

**前置条件**：Ollama 不会开机自启。脚本已内置**自愈**：检测到本机 Ollama 未运行时会自动执行 `ollama serve` 并等待就绪，无需人工干预。仅当自愈失败（未安装 Ollama 等）才回退到 sentence-transformers（manifest 的 `engine` 字段会如实标注，维度变化将触发全量重建）。

**判定当前生效模型**：查看 `<知识库>/.semantic_index/manifest.json` 的 `engine` 与 `dimension`——`ollama` + `1024` 表示用 qwen3-embedding:0.6b；`sentencetransformer` + `384` 表示回退到了 MiniLM。

## 2. 追更与重建

1. **长书追更**：使用 `split_segments.py --append`，仅对新增段或变更段重新调用 `build_segment_index.py`，完整执行 VERIFY 后刷新书导航。
2. **独立文档增补**：直接对新文档执行 `split_segments.py --doc`，生成该文档段索引，通过 VERIFY 后重新发布 `独立文档集` 书导航。

## 3. 运维协议：两级删除与旧库迁移

### 3.1 两级删除规范（宋氏思考决议 5）

删除属于高危操作，严格区分两级：
1. **单篇独立文档删除**：
   - 目标：删除虚拟书《独立文档集》中的某一篇文档。
   - 命令：`python "<技能目录>/scripts/delete_novel.py" "独立文档集" --doc "单篇文档名" --lib "<知识库>"`
   - 行为：仅清除该文档对应的原文段文件与段索引文件，并自动刷新《独立文档集》书导航。
2. **整集 / 整书删除**：
   - 目标：彻底删除整部著作或整套独立文档集。
   - 命令：`python "<技能目录>/scripts/delete_novel.py" "书名-作者" --lib "<知识库>"`
   - 行为：高危双重确认（Double Confirm），清空该书原文、所有段索引、书导航及断点记录。

### 3.2 旧库自动迁移

若存在 v4.x 旧版本小说索引库，使用迁移脚本自动升级：
```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/migrate_library.py" "<旧库路径>" "<新库路径>"
```
脚本将自动将旧目录（小说原文/章节索引/小说索引）重命名为（原文/段索引/书导航），并批量升级 frontmatter 字段与路径。
