# 知识库转录 v5.4.6：编排器协议

## 概述（核心原则）

与 **成人文学索引_v4.8.3** 是共用同名 `scripts/*.py` 索引内核的双胞胎配对（分叉登记见第 6 节）：本仓是内核主干（`twin_role: trunk`），`原文/段索引/书导航` 三目录升级、api_pool 多节点池、独立文档集入库分支都长在这里；对端是定制侧（风格卡/文风蒸馏独有）。
核心原则：**精度优先，回答必带精准出处（文件名+行号）**。所有分支均以**证据收口**：路径、命令返回码、统计指标；未过门禁标 `BLOCKED` 或 `NEEDS_REVIEW`。无法唯一确认的行号不得标记为 `DONE`。

## -1. 技能边界

### 负责

- 管理以长篇专著为主体、以独立文档为补充的混合知识库。
- 执行资料导入、格式转换、章节/字数切段、知识提取卡生成、书导航构建、增量重建与一致性校验。
- 基于已索引资料执行带文件名、原文行号和逐字引用的精准问答与知识创作。
- 提供索引库状态监控、行号校准、两级删除、重命名、迁移和本地 Web 管理。

### 不负责

- 不承担小说创作、续写、改写、爽点/伏笔分析、文风蒸馏或小说标签生产。
- 不把未经导入并完成验收的外部资料当作知识库事实回答。
- 不替用户决定超出授权预算的原文读取范围；超限时先暂停并请求确认。
- 不读取知识库工作区之外的文件，不把向量召回结果单独当作最终证据。

### 输入与输出边界

- 输入：TXT、Markdown，以及已安装依赖支持的 PDF、Word、EPUB；长书使用书名/作者标识，独立文档进入虚拟书「独立文档集」。
- 输出：`原文/`、`段索引/`、`书导航/` 三目录及可复核的交付卡；每个完成分支都必须有验证命令和返回码。
- 证据：问答结论优先引用段索引，关键结论必须回读原文并给出文件名与行号。

### 0.2 启动检查（四项必须有结论）

- `llm_nodes.json`：检测多节点 API 故障转移池配置是否存在（仅报告已配置/未配置，严禁输出或回显 Key 内容）；未配置或仍为占位符则在建库执行前置 `BLOCKED`。建议先跑 `python scripts/probe_pool.py` 做六节点连通性体检。
- `<知识库>`：读取 `.env` 的 `INDEX_LIB_DIR`，为空则默认为 `<技能目录>\索引库`；全系统使用标准三目录：`原文`、`段索引`、`书导航`。
- 库内现状：列出 `书导航\*.md` 资料名，或运行 `orchestrate.py --lib "<知识库>" status`。
- 运行模式：`INDEX_EXECUTOR`（direct / subagent）、`INDEX_ENABLE_SEMANTIC`（向量辅助召回开关）。
- 向量模型（硬件自适配）：`INDEX_EMBEDDING_MODEL` 留空时，系统按本机算力自动选型（探测 nvidia-smi 显存 + 系统内存，优先复用 Ollama 已装模型）。查看本机结果：`python scripts/hardware_profile.py`。分档：显存≥6GB → `qwen3-embedding:8b`；≥3.5GB → `4b`；其余/无 GPU → `0.6b`。用户显式配置优先于自适配。

## 1. 路由：核心四分支与创作

| 分支 | 识别语境 | 立即读取 | 最终交付（完成标准） |
|---|---|---|---|
| 建库 | 从长篇著作或单篇独立文档建立知识索引库 | `references/建立索引.md` 建库小节 | 原文分段 + 段索引(知识提取卡) + 书导航 + 验收摘要；VERIFY 全部返回 0 |
| 追更·重建 | 源文件更新、增补章节或需对特定段重新提取 | `references/建立索引.md` 追更/重建小节 | 受影响段索引更新 + 刷新书导航 + 增量验收；完整 VERIFY 通过 |
| 问答(核心) | 基于知识库提问、查证概念原理、追溯数据结论 | `references/索引内容.md` 问答协议 | 针对性答案 + 精准出处（源文件+精确行号）+ 关键逐字引用；遵循授权预算 |
| 运维 | 库状态、行号体检修复、整库/单篇两级删除、重命名、旧库迁移 | `references/建立索引.md` 运维小节 | 操作前后状态对比 + 执行返回码 + 二次确认记录 |
| 知识创作 | 基于知识库提取核心观点、生成技术大纲或综述报告 | `references/索引内容.md` 创作小节 | 知识产物 + 引用资料出处清单 |
| Web控制台 | 启动知识库图形管理界面、交互式卡片流检索 | 启动脚本 `scripts/start_web.py` | 启动本地服务（默认监听 127.0.0.1:5888），返回访问链接及状态卡片 |

## 2. 问答授权与预算协议（核心纪律）

1. **概括性授权**：用户提出问答请求，默认构成对知识库已索引内容的检索及原文核对授权。
2. **精度优先**：答案宁精勿泛，必须回答到点子上，结论必须有知识点条目或关键引用支撑。
3. **核对预算上限**：一次回答中，最深可调阅原文核对的预算上限为 **前 3 个最相关段落原文** 或 **累计 30,000 行原文**。
4. **超限熔断汇报**：当问题覆盖范围过大、涉及段落超过预算时，编排器必须核对最相关的 3 个段落后暂停，并以固定句式向用户汇报并请示：
   > 「涉及 N 个段落，已核对最相关的 3 个，继续读完吗？」
5. **绝对禁止越界**：严禁读取知识库工作区外的任何文件。

## 3. 不变量与结构约定

- 知识库标准三目录：
  - `原文/`：存放分段后的原文文件，长书按 `<书名-作者>/` 子目录归档，独立文档放入 `原文/独立文档集/`。
  - `段索引/`：存放全量提取卡文件（`*-idx.md`），`索引类型: 段索引`。
  - `书导航/`：存放各长书及虚拟书《独立文档集》的全局导航文件，`索引类型: 书导航`。
- 提取卡标准结构：
  - `### 本段概要`
  - `### 知识点条目`（带 `[概念]` / `[方法]` / `[数据]` / `[观点]` 标记与精确行号）
  - `### 关键引用`（逐字摘录 + 精确行号）
  - `### 实体`、`### 交叉引用`、`### 标签`
- 脚本统一调用方式：
  ```text
  uv run --with requests --with python-dotenv python "<技能目录>/scripts/脚本.py" ...
  ```

## 4. 交付契约（证据收口）

每个操作分支结尾必须输出交付卡，`DONE` 状态必须有检验绿灯实据：

```text
状态：DONE / BLOCKED / NEEDS_REVIEW
范围：本次操作的书名/文档名/章节范围/问答主题
读取/生成：实际涉及与产出的文件清单
验证：命令返回码（如 verify_and_fix_lines / _验证批次 返回 0）、行号校验统计
失败项：无（或明确列出具体失败原因）
恢复/下一步：明确下一步动作
```

改 `scripts/*.py` 前先看登记簿 `<工作区根>/schemas/twin-kernel.json` 里该文件的 `status`：`identical` 必须两侧同步改、`trunk-ahead` 只改本仓再回填对端、`customized` 禁止跨仓覆盖、`pending-rebase` 先判归属。自检：`PYTHONIOENCODING=utf-8 python schemas/contract_check.py`（报 `TWIN_UNEXPLAINED_DRIFT` / `TWIN_REGISTRY_STALE` 即为登记失效）。
