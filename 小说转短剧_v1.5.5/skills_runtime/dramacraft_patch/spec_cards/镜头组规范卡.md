# 镜头组规范卡（下游工人用）

把定稿剧本与导演规划件转成**镜头组**。默认产物是**机读镜头组 JSON 件**（落盘 `state/shotgroups/ep{NNN}.json`，入库后由系统导出 Markdown 文档供人审读），不是逐条单镜头分镜表（:19）。

- 对视频：一个镜头组通常对应一个可生成/可剪辑的视频段落，含 1-6 个连续动作节拍。
- 单镜头只在镜头组内部用于说明动作节拍、信息点与剪辑顺序；**不要把「逐个镜头生成」当默认目标**（:25）。

## 核心目标（:27-33）

- 每个镜头组承担一个明确叙事任务，而不是只追求镜号细碎完整。
- 组内节拍要短、清楚、可视、可听，但不要求为每个节拍单独生成。
- **输出必须保留剧情顺序、连续性和人物数量**；参考资产、生成风险提示等只在明确要求完整导演说明书时加入。

## 输入处理原则（:35-43）

1. 原文已有场次/镜号/对白编号/页码时，保留其顺序，但重新组织为镜头组。
2. 原文没有结构时，按地点、时间、动作目标、情绪转折、信息释放与生成单位主动拆组。
3. **不虚构关键剧情，不改变人物关系、事件顺序和核心设定。**
4. 可以补充必要镜头节拍、景别、动作、声音、转场与生成注意事项，但补充必须服务原文意图。
5. 缺失信息不影响拆组时保守补全；会改变剧情事实时标注待确认或询问用户。
6. **不把抽象心理直接写成画面**；要转成观众能看见或听见的动作、表情、道具、空间和声音。

## 极简镜头组规则（:45-55）

每个镜头组**只保留五字段**：

- `编号`：如 `EP36-SG01`。
- `时长建议`：只写 4-15s 范围内的建议时长，如 `6-8s`、`8-12s`、`10-15s`；**不要写 `00:00-00:25` 这种绝对时间段**。
- `场景`：地点和必要空间状态。
- `人物`：本组出现的人物；**无人物写「无」**。
- `内容`：用最简洁的语言写发生了什么，什么人说了什么话。

**不要保留**导演总判断、节奏结构、叙事任务、参考资产、画面内容、组内节拍、声音/台词栏、生成用途、导演校验、压缩方案、后续派生提醒、制作备注等 boilerplate（:55）。不要把每集硬套成「开场钩子 / 人物进入 / 核心冲突 / 精神落点 / 结尾钩子」；只有源剧本自然如此时才沿用。

## 镜头组机读结构（落盘 `state/shotgroups/ep{NNN}.json`）

```json
{
  "ep": 1,
  "schemaVersion": 1,
  "groups": [
    {
      "gid": "EP01-SG01",
      "secs": "11-13",
      "scene": "顾家客厅·暴雨压城",
      "cast": ["C01", "C02"],
      "content": "顾天明推门而入，冷眼扫视屋内；林管家退后半步低下头。",
      "planSceneId": "Sc1"
    }
  ]
}
```
- `secs` 只写 4-15 秒区间（如 `11-13`）或单值（如 `12`），带不带上 `s` 都行；**禁** `00:00-00:25`。
- `cast` 写角色码数组；无人物写 `[]`（导出会渲染成「无」）。
- `planSceneId` 是这一组承载的规划场次号（SG4 强校验，不许自造）。
- 全集合计：各组中值之和要落在目标秒数 ±15% 内（SG3）。

## 推荐文档结构（:57-71）

```markdown
# 《标题》镜头组

## EP01-SG01：<短标题>

- 编号：EP01-SG01
- 时长建议：6-8s
- 场景：<地点和必要空间状态>
- 人物：<本组出现的人物；无人物写无>
- 内容：<最简洁地写发生了什么，什么人说了什么话。>
```

默认只保留五字段；除非明确要求导演说明书/资产计划/生成提示词，不要追加其他字段（:71）。映射信息（`planSceneId`）只存在机读件里；导出的 Markdown 文档只保留五字段。

## 镜头组拆分标准（:73-92）

优先按「叙事任务」拆组，不按摄影机每次变化拆镜头。

**适合拆成新镜头组**：地点或时间明显变化 / 角色目标改变 / 情绪进入新阶段 / 观众需要获得一个新关键信息 / 动作进入新的因果段落 / 后续生成需要一张新关键帧、新视频片段或新一页 / 视觉基调发生变化（参考资产、人物状态、场景空间）。

**不需要拆**：只是同一动作的不同景别 / 只是一个人说话另一人反应 / 只是同一空间内的连续小动作 / 只是模型能在同一段视频或同一页里完成的连续节拍。

## 组内节拍规则（:94-103）

- 视频镜头组：通常 1-6 个节拍；复杂动作优先压缩成 3-5 个关键节拍。
- 动作戏：拆短、拆清楚，避免一个节拍里塞多个敌人、多个动作和多句台词。
- 对话戏：按情绪变化和信息释放组织，不必每句对白一格/一镜。
- 氛围戏：可以少节拍，但必须写清空间、主体、动作和情绪推进。

## 可视化写法（:137-152）

**避免**：「表现紧张」「气氛很好」「人物很震惊」「命运感很强」「主角内心复杂」等抽象词——词表见代码常量 `dramacraft.shot_lint.ABSTRACT_PSY_LEXICON`（本卡不复制第二份）。

**改成**具体可感：如「角色攥紧手机，屏幕冷光映在发白的脸上」「她读完纸条后抬头，嘴唇微张，手指停在纸角」。

## 常见反模式（:154-174）

1. **逐镜头过度拆碎**：每个推拉摇移都变成一行 → 先合并为镜头组，只保留关键节拍。
2. **一组塞完整场戏**：地点/目标/情绪都变了 → 按叙事任务拆成多个镜头组。
3. **只写漂亮画面、不写任务** → 每组的内容要能看出它在推进什么。
4. **为了生成好看而新增不属于原文的桥段** → 镜头组只服务源文档。

## 完成标准清单（原文「输出前检查」逐条转抄，:182-193）

- [ ] 先组织为镜头组，而不是默认逐镜头表。
- [ ] 极简模式下只保留 `编号`、`时长建议`、`场景`、`人物`、`内容`。
- [ ] `时长建议` 是 4-15s 范围内的建议时长，**不是绝对时间段**。
- [ ] `内容` 只写发生了什么和谁说了什么，没有制作说明或导演判断。
- [ ] 若明确要求完整导演说明书，才加入叙事任务、组内节拍、生成用途、导演校验等扩展字段。
- [ ] 剧情顺序没有被打乱；人物身份、人数、场景、道具和状态没有漂移。
- [ ] 台词、旁白、音效没有混在一起。
- [ ] 补充节拍没有改变原文剧情事实。

## 机器门族对应（交件前机器会逐条查）

SG1 编号连续（形如 `EP01-SG01`，组号从 01 起连续、无洞无重、集号对得上）｜SG2 单组时长可解析且端点 4~15s（禁绝对时间段）｜SG3 全集中值合计 ∈ 目标 ±15%｜SG4 规划件每一场都有组承载｜SG5 人物 ⊆ 本集登记｜SG6 五字段齐（人物可为空 = 无人物）｜SG7 引用的 `F###`/`C##` 编号必须能解析｜W2 抽象心理词告警。
