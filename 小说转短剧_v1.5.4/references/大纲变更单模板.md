# 大纲变更单模板（OC-001）

> 血统：照搬 fbs `outline-freeze.md` 变更单最小模板全字段，域换为短剧（章→集、字数→时长）。
> 用途：**大纲修改后必须留下痕迹**——缓存安检按大纲哈希对账，哈希一变旧集全部作废（`--stale-cache` 处置）。
> 变更单不强制门禁，但强烈建议每次结构性改动（集数、人物表、节拍）都登记一张，交付时随生产记录一并给用户。

---

## 1. 「冻结」的含义

- **冻结**：剧集总数、逐集钩子/卡点、人物表与节拍归属已与用户确认并写入 `outline.json`。
- **冻结之后**：不得静默改口径；任何结构变化都要走**变更单**登记，再重跑。

## 2. 变更单表（复制即用）

| 字段 | 填写 |
|------|------|
| 变更 ID | OC-001 |
| 日期 | ISO（如 2026-09-22） |
| 原因 | 用户 / 市场 / 事实约束（一句话） |
| 变更前 | 集数 / 标题摘要 |
| 变更后 | 集数 / 标题摘要 |
| 对全剧统一时长的影响 | 增 / 减 / 不变（秒数与受影响集号） |
| 对人物表的影响 | 新增 / 删除 / 改名（角色 ID 与旧名 → 新名） |
| 对伏笔账的影响 | 新增伏笔 / 计划回收集改动 / 作废伏笔（伏笔 ID 列表） |
| 是否已更新大纲文件 | 是 / 否 |
| 是否已处置旧缓存 | ask / redo / trust（对应 `--stale-cache`） |
| 是否重算大纲哈希 | 是 / 否 |
| 用户确认 | 已确认 / 待确认 |

> 建议把变更单追加到生产记录目录（`<workdir>/output/`）或单独存 `outline-change-YYYYMMDD.md`。

## 3. 与跑批的关系

1. 改完大纲 → 登记变更单 → 跑批时缓存安检会报「大纲哈希失配」；
2. 按变更单「是否已处置旧缓存」一栏选择 `--stale-cache redo`（改动大，推荐重产）或 `trust`（仅文案微调，沿用旧稿）；
3. 伏笔账本的 `pay` 事件按**有效缓存集**重放——被 `redo` 删掉的集，其认领自动作废、伏笔自然回 `open`，无需手工回滚。
