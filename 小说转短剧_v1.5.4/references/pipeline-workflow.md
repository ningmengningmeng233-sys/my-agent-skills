# SKILL.md 产线工作流（原文全文）

> 归属：`小说转短剧_v1.5.2`（dramacraft）技能仓 SKILL.md「SKILL.md 产线工作流」段，governance 第2轮 REFACTOR 自 SKILL.md 整体逐字挪入（一字未改），SKILL.md 原位留指针。

---

除既有 CLI（`run_batch.py`，只产 01 剧本，本机断点续跑、人可随时接管）之外，v1.5.0 起多一条**命名工作流**形态：
在 ZCode 里跑 `dramacraft-pipeline`（小说 → 剧本 → 导演规划 → 镜头组 → 逐集监督 → 终验导出），
工人（写手/导演/镜头组/监督）由子代理担任，确定性执法仍全在 python 门族 + `validate.mjs` 上。

- **两形态边界**：工作流吃会话额度、适合整条产线无人值守跑批；CLI 吃模型节点池额度、适合单点重跑与人工盯稿。
- **工人的作业规范**：五张规范卡在 `skills_runtime/dramacraft_patch/spec_cards/`（导演规划 / 镜头组 / 监督·成片层 / 监督·大纲层 / 会议机制）。
  卡头标注原件出处与行号，派活时**整卡交给工人**，不要凭记忆复述规则。
- **人的位置**：读者会与评审会默认开启；熔断升级、P0 问题、监督红线、会议拍板这四类只递给你拍板，机器不替你决定。
- **起跑前三条**（装包实验实测，见 `references/WORKFLOW.md` §15.6）：① 引擎自己找得到——不要求拿技能目录当工作区，也最好显式传 `engineRoot` 指认是哪一份；② `outlinePath` 与 `workdir` 必须在 ZCode 工作区内（工作区外的绝对路径会被世界读层直接拒），原著可以放工作区外；③ 原著 GBK/GB18030 不用预处理，工作流自己转 UTF-8 参考件。
