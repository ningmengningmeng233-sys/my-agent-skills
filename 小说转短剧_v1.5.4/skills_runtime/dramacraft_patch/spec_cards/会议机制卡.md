# 会议机制卡（读者会 / 评审会 / 对抗会用）

## 会议时长上限（防卡顿）（:11-23）

| 会议 | 正常时长 | 上限 | 超时行为 |
|------|---------|------|---------|
| 创意会 | 10-15 分钟 | 20 分钟 | 协调者强制输出 2 个方向，人类立即选（**已归并 v1.2.5 选题会**，本流水线不单独召） |
| 读者会 | 5-10 分钟 | 15 分钟 | 强制输出关切清单，不等三方充分讨论 |
| 对抗会 | 10-15 分钟 | 20 分钟 | 综合者强制给出加固表述，人类二选一 |
| 评审会 | 15-20 分钟 | 30 分钟 | 强制输出 P0 问题清单，跳过 P1/P2 |

**人类决策节点不超时**：等待用户选择方向时不设时间限制，但 AI 只提供**有限选项**（2-3 个），不开放式等待。

## 会议简报（每次会议前必做）（:25-38）

召集任何会议前，**协调者**先产出会议简报（约 500 字），作为所有参会 Agent 的统一上下文输入。参会 Agent **只读简报**，不直接读全部项目文件，避免重复 token 消耗与上下文污染。

```
━━ 会议简报 · {会议类型} ━━
剧名：{剧名}
主题：{一句话核心主张}
体裁与读者：{简述}
当前状态：{当前所在阶段及已完成的关键产出物}
本次目标：{这次会议要产出什么，一句话}
关键背景（≤300字）：{从大纲/情报/原料中提炼的最关键信息}
━━━━━━━━━━━━━━━━━━
```

## 发散 → 收束两阶段原则（:40-45）

所有会议均采用两阶段结构，防止「框架锁定效应」（太早收束导致可能性丧失）：

- **第一阶段（发散）**：各角色独立表达，不打断、不批评对方。
- **第二阶段（收束）**：在发散结果基础上碰撞，找出最有力的综合方案。

## 心理契约（评审类会议前必问）（:47-58）

**读者会、对抗会、评审会**开始前，AI 向用户确认：

> 「这次会议会提出质疑和问题。你希望侧重什么？
> ①「发现问题」——尽量多找毛病
> ②「均衡」——问题和亮点并重
> ③「确认亮点」——以鼓励为主，问题点到为止」

用户选择后，会议强度按选项调整。**默认为 ②均衡**。

## 会议纪要格式（所有会议共用尾部格式）（:60-72）

```
━━ 会议纪要 · {会议类型} · {日期} ━━
核心结论：{一句话}
关键决策：{列出 1-3 条}
被放弃的方向：{列出，附原因}
待人类确认的问题：{列出}
下一步：{立即要做的事}
━━━━━━━━━━━━━━━━━━
```

落盘位置：`<workdir>/state/meetings/minutes-<会议类型>.md`（只写纪要尾部，不写全程记录）。机读校验见 `dramacraft.meeting_pack`（`append_minutes` 只认上面这五个字段 + 会议类型 + 日期，缺字段即拒收）。

## 各会定位速查

- **读者会**：站在观众视角挑「看不看得懂、想不想追下去」，产出**关切清单**（每条关切必须有决议行才算闭环——见 `meeting_pack.reader_closure_open`）。
- **评审会**：站在专业视角挑硬伤，产出 **P0/P1/P2 分级问题清单**；P0 会拦住交付。
- **对抗会**：站在反方立场攻击方案，产出加固表述与二选一。

## 完成标准清单（每次会前会后打勾）

- [ ] 开会前产出了简报（≤500 字），参会方只读简报
- [ ] 评审类会前问过心理契约，用户未选时按「均衡」执行
- [ ] 过程分「发散 / 收束」两阶段，发散期不打断不批评
- [ ] 到点即按超时行为收束（读者会交关切清单、评审会交 P0 清单），不等充分讨论
- [ ] 会后按五字段纪要格式落盘；读者的每条关切都有决议行（接受/部分接受/驳回 + 理由）
- [ ] 人类决策处只给 2-3 个有限选项，不开放式提问
