# 视觉生产契约（按需加载）

> 由 `SKILL.md` 主体下沉（阶段 8 工单 8.1，渐进披露）。**只有启用视觉生产时才需要读本文件**；核心资产反推不依赖本文件。

适用范围：三种视觉模式（`data_only` / `prompt_only` / `direct_generate`）、自动生成与手工任务包两条路径、视觉交付门与状态、权威风格包与安装、输入格式与依赖、画风库维护。硬规则与路由见 `SKILL.md`。

## 可选视觉生产：自动 Gemini 与手工任务包两条路径（v2.15.0-rc.2）

**前提**：视觉生产是可选下游模块，不参与、也不阻塞资料交付。没有 Gemini 密钥时，
核心反推流程照常完成并签发「资产资料已交付」；视觉线单独记为未启用。

**一条链，两种执行方式**：自动生成与手工导出共用同一条编译链
（任务事实 → 参考路由 → 路径/哈希/MIME 校验 → 最小发送编译），
因此两条路径产生的提示词、负面提示词与参考图职责完全一致。

### 路径 A：自动调用 Gemini（需密钥）

```powershell
# 1) 体检：配置、SDK、模型、权威包与参考图解析（零收费调用）
python scripts\maintenance.py visual-doctor --lib <资产库> --json

# 2) 规划视觉任务（TOML 是唯一机器事实源）
python scripts\maintenance.py visual-plan --lib <资产库> --style 仙侠国风电影CG

# 3) 生成（只生成依赖已通过的任务；未通过上游会被拒绝）
python scripts\visual_production.py run --lib <资产库> --task <任务ID>
```

配置（任选其一，加载顺序为：进程环境 → `ASSET_ENV_PATH` 指定文件 → 技能目录 `.env` → `~/.asset-extract/.env`）：

| 变量 | 作用 | 默认 |
|---|---|---|
| `GEMINI_API_KEY` | 必填，自动生成唯一凭据 | 无（缺失即改用手工路径） |
| `GEMINI_IMAGE_MODEL` | 生图模型 | `gemini-3-pro-image` |
| `GEMINI_QC_MODEL` | 质检模型（需支持图像输入 + 文本输出） | `gemini-3.1-pro-preview` |

依赖：`pip install google-genai`（仅自动路径需要；核心链路与手工路径都不依赖它）。

### 路径 B：手工任务包（无密钥可用，可跨机转交 Codex/其他生图工具）

```powershell
python scripts\visual_production.py export --lib <资产库> --task <任务ID>
python scripts\visual_production.py import --lib <资产库> --task <任务ID> --image <生成结果.png>
python scripts\visual_production.py check  --lib <资产库> --task <任务ID> --qc <结构化检查.json>
```

导出目录**自包含**，复制到另一台机器后无需访问原资产库：

```
视觉资产/任务包/<任务ID>/
├── 请求.json          # 最小发送清单：参考图相对路径 / 职责 / 哈希 / MIME / 字节数
├── 提示词.md          # 正向与负面提示词
├── 参考图清单.md      # 逐张职责与包内相对路径
├── 参考图/            # 实际选中的图片本体（01-风格.png、02-身份.png …）
└── 任务包清单.json    # 每个文件的 SHA-256 / 字节数 / MIME / 职责 / 来源
```

### 视觉交付门与状态

```powershell
python scripts\maintenance.py verify-visual --lib <资产库> --json
```

退出码：`0` 仅当视觉交付**已签发**（DELIVERED）；`3` = `VISUAL_NOT_ENABLED`（尚未创建视觉计划，
视觉未启用是合法状态，但**不等于**视觉交付通过）；`1` = `BLOCKED`（有计划但未完成，或权威包缺失/
产物失效）。资料交付线（`maintenance.py verify`）与视觉交付线完全独立，互不影响。

### 权威风格包与安装

新视觉任务的**唯一**风格源是 `references/styles/仙侠国风电影CG/1.0.0/private`（58 文件、32 张参考图）。
旧 `H7` 卡片仅保留迁移兼容，**不参与**新任务提示词编译。

权威参考图体积较大且被 `.gitignore` 排除，因此 **Git 检出不是完整视觉安装**。要获得完整视觉包：

```powershell
# 从本地私有 zip 安装（不自动从网络下载）
python scripts\install_stylepack.py --from <私有包.zip> --style 仙侠国风电影CG --version 1.0.0
# 校验已安装的包（缺图/漂移逐文件报告）
python scripts\install_stylepack.py --verify --style 仙侠国风电影CG --json
```

### 输入格式与依赖

正式输入：`.txt`、`.md`、`.docx`、`.epub` 与多文件项目（可用顺序清单显式指定次序）。
DOCX 依赖 `python-docx`，EPUB 依赖 `ebooklib` + `beautifulsoup4`（见 `requirements.txt`）。
**PDF 明确不支持**（不做 OCR）：以 PDF 为输入会以 `UNSUPPORTED_SOURCE_FORMAT` 拒绝。

## 画风库维护（新增画风 / 组装画风）

**新增画风**：用户要求加新画风时——照 `references/画风卡片模板.md` 填写卡片（当前 H 系已有 H1-H7，新卡从下一个连续 H 编号开始，勿用 A-G；「X. 渲染层」分节 = 定妆注入开关）→（可选）在 `references/题材-画风映射.md` 加行 → 跑 `scripts/check_style_lib.py` 自检，0 错误即完成（ADR-0005）。

**组装画风**：用户要求按剧本类型组合混合风格（如「仙侠奇幻三维渲染」）时——查 `references/风格组装参考.md`（内容×渲染×色调组件表）起草一张 H 卡 → **必须向用户展示卡片全文并等待确认**（不允许静默落库）→ 确认后写入画风库 →（可选）映射加行 → 自检（ADR-0005 决策 7）。
