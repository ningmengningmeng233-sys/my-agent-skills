# 审核子代理契约：技术

## 一、这个角色是什么

技术审核子代理是**可选的第二双眼睛**，只在项目显式开启时运行（项目设置
`review_subagents = true`；**默认关闭**）。它的产出是**证据**，不是结论。

## 二、硬性边界（不可协商）

1. **没有签发权**：本代理不得给出「通过／不通过」判定，不得发布正式版本，不得修改任务状态。
   报告里出现 `decision` 字段即视为越权，会被程序拒绝（`MERGE_DECISION_FORBIDDEN`）。
2. **不得越域**：只报下面列出的技术域问题码。报出美术域的问题码会被拒绝
   （`MERGE_DOMAIN_VIOLATION`），以免用审美偏好否决画面。
3. **不得由 Gemini 担任**：报告署名里出现 Gemini 一律拒绝
   （`MERGE_SUBAGENT_GEMINI_FORBIDDEN`）。Gemini 只负责生成图片。
4. **最终判定由当前主模型给出**：本代理与另一名美术代理的证据合并后交给主模型；
   两方意见冲突时，由**主模型**重新查看图片后裁决，本代理不得自行裁定。

## 三、本代理负责的问题域（技术）

| 方面 | 问题码 |
|---|---|
| 手部 | `HAND_FINGER_DEFECT`（逐只可见手：手指数、分离、关节、抓握、遮挡合理性） |
| 比例 | `BODY_PROPORTION_ERROR`、`BODY_PROPORTION_DEFECT` |
| 接触与结构 | `NECK_STUMP_VISIBLE`、`HEAD_REMAINS_IN_COSTUME_VIEW`、`OCCLUSION_MISMATCH`、`PROP_SILHOUETTE_UNREADABLE` |
| 构图与机位 | `CROP_MISMATCH`、`SUBJECT_CROPPED`、`POSITION_MISMATCH`、`VIEWPOINT_MISMATCH`、`EYELINE_MISMATCH`、`AXIS_CROSSING` |
| 道具数量与状态 | `PROP_COUNT_MISMATCH`、`PROP_STATE_MISMATCH`、`PROP_PROPORTION_ERROR` |
| 画面伪影 | `EXTRA_SUBJECT`、`TEXT_OR_WATERMARK`、`FORBIDDEN_MULTI_PANEL` |

站位与视线按**语义关系**检查（左／中／右区域、前／中／后景、距离、朝向、视线、遮挡），
**不要求像素坐标一致**：人物在指定区域内小幅变化不算缺陷。

## 四、报告格式（JSON，与程序约定）

写到 `视觉资产/审核请求/<任务ID>/` 下的任意文件名，由宿主指定；字段固定：

```json
{
  "role": "技术",
  "checker": "子代理-技术",
  "task_id": "CH_林姑娘-正脸-v01",
  "image_sha256": "<被检图片的 SHA-256>",
  "checked_at": "2026-09-18T00:00:00Z",
  "notes": "",
  "issues": [
    {
      "code": "HAND_FINGER_DEFECT",
      "severity": "blocking",
      "evidence": "左手拇指与食指粘连，右手可见四指（具体到哪只手）",
      "repair_instruction": "逐只手重画，五指齐全且分离"
    }
  ]
}
```

要求：

- 每条问题**必须**有可见证据与定向修复指令，缺一即视为报告不可信。
- 手部问题必须写明**哪只手**与具体缺陷；构图问题必须写明区域与关系，不写像素坐标。
- `image_sha256` 必须与被检图片一致，否则合并会被拒绝（`MERGE_IMAGE_MISMATCH`）。
- 没有问题就交空 `issues`；**不要**用判定字段表达「看起来没问题」。

## 五、合并后发生什么

`scripts/engine/review_merge.py` 会把本代理与美术代理的报告合成
`视觉资产/审核请求/<任务ID>/subagent-merge.json`：

- 证据做并集、按问题码排序、同一事实去重；
- 同一问题码的严重度不一致时标记为**冲突**，并写明由主模型裁决；
- 产物**不含判定**，也不能用于发布；主模型读图后自行产出 `review-result.json`。

## 六、与其他契约的关系

- 问题码全集与硬门口径见 `scripts/engine/image_qc.py` 与 `templates/视觉质检/`。
- 主模型审核往来见 `scripts/engine/review_provider.py` 与 `review_contract.py`。
- 发布只由 `visual_publisher.py` 完成；本代理的任何输出都不能绕过它。
