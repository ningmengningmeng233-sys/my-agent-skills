# 资产提取流水线（纯国漫三维）

国漫三维资产提取流水线的术语表。本流水线从小说/剧本自动反推资产表并生成人物/场景/道具的提示词。v2 架构引入直调引擎后，本节为词表，实现细节见 `docs/adr/` 与 `SKILL.md`。

## 执行器

**直调引擎（Direct Engine）**:
Python 脚本并行直调 LLM API 的执行器（ThreadPoolExecutor 并发 + 429 退避重试 + SQLite 断点），替代子代理派发。
_Avoid_: 子代理、多代理并行

**子代理派发（Subagent Dispatch）**:
编排器派发子代理逐任务执行的模式，设计备选。当前版本未提供实现（直调引擎为唯一执行路径；无 API key 时按 SKILL.md 错误处理矩阵处理）。
_Avoid_: 直调（当指子代理时）

**断点续跑（Checkpoint Resume）**:
段级任务状态落盘（SQLite/文件清单），中断后重跑只执行未完成段，已完成段零浪费跳过。
_Avoid_: 重跑、从零开始

**输入哈希断点（Input-Fingerprint Checkpoint）**:
跳过判断以源内容哈希为准（段文件/候选表/合并对/裁决块），源内容变化自动重跑对应任务，追更 `--append` 改写末段后不会漏跑。
_Avoid_: 只看输出文件是否存在

## 分段

**段文件（Segment File）**:
源文件按 5章/段（无章节时 1万字/段）切分的独立处理单元，带 frontmatter（章节范围/对应索引/分段方式），是行号与出处的锚点。
_Avoid_: 章节块、切块

**结构摸底（Structure Survey）**:
执行器运行前对源文件统计行数、提取章节标题、识别非标准章节的过程，产出分段方案。
_Avoid_: 预处理、探查

## 提取

**段级提取（Segment Extraction）**:
每段一次直调的任务，只产出本段出现的"资产出现记录"（名称/别名/出现章节/原文摘句/行号），不做全局表和视觉描述。
_Avoid_: 全量提取、8模块输出

**资产出现记录（Asset Occurrence Record）**:
段级提取的最小产物单元：一个资产在某段的一次登记，必须含原文出处。
_Avoid_: 资产条目（无出处时）

**原文出处（Source Citation）**:
资产记录的三元组 {出现章节, 原文摘句, 段内行号}，是资产存在性的唯一证据。
_Avoid_: 出处说明、来源标注

**出处强制（Citation Mandate）**:
规则：正式资产表每条必须有原文出处；出处无法通过摘句匹配验证的资产降入"待确认附录"，不进入正式表。
_Avoid_: 推测即建档

**主名规则（Primary Name Rule）**:
规则：资产主名必须以原文词汇为准（取全局首次出现/最频繁称呼），术语化重命名（如"音响"→"加强混音器"）视为违规，合并时自动退回原文称呼。
_Avoid_: 规范名、专业名、美化名

## 全局登记

**精确优先（Precision First）**:
流水线一切设计权衡中，资产识别/命名/合并的精确性优先于 token 成本与速度；任何"省 token"手段不得以牺牲精确性为代价。
_Avoid_: 省 token 优先、粗放提取

**全局资产登记表（Global Asset Registry）**:
全书的资产主名共识表，由候选遍并行直调 + 分层两两合并生成（轮数 ≈ log₂(段数)，每轮并行），键为主名（原文词汇），带别名/首现章/一句定性。段级提取与聚合裁决的锚点：段级记录必须引用登记表主名，疑似新资产须申报。
_Avoid_: 规范名表、全局资产清单（混淆时）

**候选主名表（Candidate Name Table）**:
候选遍（全局扫描第一遍）每段独立输出的本段候选资产清单（主名/别名/首现章/一句定性），是分层聚合的输入。
_Avoid_: 候选草稿（未经合并的）

**登记表锚点（Registry Anchor）**:
段级提取与聚合裁决时注入的全局登记表（主名/别名/首现章/一句定性精简行）：登记表已有资产必须用主名，禁止另起名。
_Avoid_: 无锚点提取（命名漂移的根源）

**严格申报（Strict Claim）**:
疑似新资产进登记表的唯一通道：段级提取标 `[新增]` 必须附原文摘句+行号，对账层验证（摘句真在原文、登记表查无、无别名冲突）通过才可并入登记表；未通过降级待确认附录。
_Avoid_: 自由申报、模型说新就加

## 聚合与规范化索引

**聚合裁决（Aggregation Adjudication）**:
跨段合并的两段式处理：脚本预聚合（词面匹配+出处校验）+ LLM 裁决（语义合并/主名/等级/出现位置拼接），产出最终反推文件。
_Avoid_: 草稿合并、共识表决

**规范化资产索引（Normalized Asset Index）**:
`<资产库>/.process/资产索引.json`，四类资产的统一结构化数据契约，记录稳定实体键（`stable_key`）、旧 ID 兼容映射、四级事实等级、生产优先级、原文证据链及显式依赖网络。
_Avoid_: 仅依赖 Markdown 表格解析

**实体稳定键（Stable Key）**:
格式如 `CHR:00001:1`，按实体类别与首次验证出现位置有序分配并持久化，跨段改名或前置插入章节不改变已分配资产键。
_Avoid_: 易受行号移动影响的临时索引

**四级事实等级（Four-Tier Fact Levels）**:
剧本事实（字面原文出处且已验证）、强推断（两处以上逻辑线索闭环）、制作提案（填补空白的美术/制作建议）、待定冲突（前后矛盾或存疑项，阻断提示词生成）。
_Avoid_: 脑补设定冒充原著事实

**生产优先级（Production Priority）**:
P0（后续资产所依赖的被依赖实体）、P1（核心资产）、P2（辅助资产）、P3（文字已足够明确，无需独立基础提示词，有跳过记录）。区别于叙事等级 S/A/B/C。
_Avoid_: 将重要度等级 S 直接等同于生产顺序 P0

**显式资产关系（Explicit Asset Relations）**:
严格定义的 5 类资产网络：`WEARS`（人物穿戴服装）、`APPEARS_IN`（人物/道具出现于场景）、`LOCATED_IN`（道具定位于场景）、`CONNECTS_TO`（场景出入口双向连通）、`STATE_OF`（变体属于母资产）。
_Avoid_: 基于名称相似性盲猜关联

**场景空间母版（Scene Continuity Master）**:
`<资产库>/连续性/场景母版.md`，记录场景的物理空间结构、固定视觉锚点、出入口、连接点、材质光源与明确标注的“未说明”盲区。视角派生产物强制继承母版。
_Avoid_: 自由编造未记载的空间结构

**摘句重叠（Quote Overlap）**:
不同分组间摘句互为子串的现象（去标点后 ≥4 字），是名称漂移（音响→加强混音器）的脚本级合并信号——同实异名的两组必然摘句相同。
_Avoid_: 语义猜测

**补建（Backfill）**:
交叉校验发现的漏提资产，由 LLM 裁决时补入正式表（标记"交叉校验补建"，出现位置按章节摘要统计）；证据不足的漏提候选进待确认附录。
_Avoid_: 自动补录（不经过裁决时）

**分块裁决（Chunked Adjudication）**:
聚合裁决按资产类型拆分为多次独立 LLM 调用（人物/场景/道具/服装 + 项目基础信息），规避单次调用的输出规模上限，失败只重跑单块。
_Avoid_: 单次全量裁决

**过程归档（.process Archive）**:
裁决输入/裁决块/登记表对账报告等过程文件的归档目录（`<资产库>/.process/`），断点依赖、不进入交付视图，资产库根目录只留登记表 + 反推_最终.md + 断点库。
_Avoid_: 根目录堆过程文件

**待确认附录（Pending Appendix）**:
反推文件末尾的附录区，收纳出处无法验证或单段孤证的疑似资产，不参与正式表与下游生成。
_Avoid_: 待定资产（混淆时）

## 启动

**开始界面（Start Panel）**:
步骤 0 的强制 Markdown 确认面板，固定展示输入源、画风确认、需要强调的部分、输出位置（含缓存位置）。首次完整确认；断点续跑/追更快速确认；单步入口也必须先确认。不确认不写盘。
_Avoid_: 跳过确认直接跑、只确认部分参数

**强调清单（Emphasis List）**:
`<资产库>/强调清单.md`，仅读取 `## 必须强化` 与 `## 必须避免` 两个分区，每行 `- `；缺失视为无额外强调。只影响 描述/基础/衍生/服饰设计，不影响 提取/聚合/登记表。
_Avoid_: 把强调清单当作事实层输入

**服装强化方向（Costume Enhancement Directives）**:
描述补全阶段按角色身份/重要等级/服装妆造表/场合/原文自动输出的具象指令，例如“至少两层：内搭 + 外袍”“装饰：鎏金、宝石、刺绣 2-4 种”“材质：丝绸 + 金属 + 纱/皮革”。基础/衍生/服饰设计逐字继承。
_Avoid_: 用“华丽度中高低”等抽象分级

**人物精美强化方向（Character Refinement Directives）**:
描述补全阶段自动输出的具象指令，例如“眼睛大而清亮、瞳孔高光、眼线睫毛精细”“皮肤柔滑瓷感、通透有光泽”“发丝根根分明、发丝高光”。基础/衍生逐字继承。
_Avoid_: 抽象词“精美程度中”

**自动推测强化（Automatic Enhancement Inference）**:
技能默认根据剧本/身份/场合自动选择固定可执行强化指令，不需要用户手动强调；强调清单只作为用户额外覆盖。
_Avoid_: 把强化责任推给用户逐项填写

**启动状态文件（Start State）**:
`<资产库>/.start-state.json`，保存 input_source/genre/style/emphasis_hash/output_root/last_confirmed_at；断点续跑/追更时用于快速确认，强调清单变化后需重新确认。
_Avoid_: 每次重复完整确认



**调度清单（Schedule Manifest）**:
由分集使用表派生的衍生变体清单（每角色×造型、每场景×时段/天候、每道具×状态），`generate_prompts.py --deriv` 按此逐变体生成，每个变体恰好生成一次。
_Avoid_: 衍生方案、变体列表

**基础提示词（Base Prompt）**:
每个资产恰好生成一次的基础形象/主视图/设定图提示词（直调引擎按资产并行）。
_Avoid_: 草稿（多份待合并的）

**三格图板（Three-Panel Board）**:
人物基础/衍生提示词的视图契约：一张图三格——左面一格人物正面特写（头顶到锁骨，全脸清晰）+ 右面上下两格正视图（全身）与后视图（全身），两格等大、身高比例一致；默认 full 右面两格保留头部，crop 裁头版右面两格头部与面部一律裁除不入画、脸的唯一真相是左面正面特写。
_Avoid_: 双图拼贴、四视图拼图、裁头版右面格出现面部

**镜头填空体系（Shot Fill System）**:
场景提示词必须写明的四要素：景别（八级）、角度（七种）、布光（光名+方向+时间）、环境具体化（时间+地点+可测量尺度）；辅以材质四件套与「一个镜头一个变化」。
_Avoid_: 空泛形容词、无景别无布光

**描写铁律（Description Laws）**:
只写可观测特征、写肌肉动作不写情绪标签、材质四件套（基材+粗糙度/光泽+使用痕迹+边缘）、一切以原文为准禁止乱填。
_Avoid_: 好看/漂亮/帅气/电影感等无效词

**衍生提示词（Derivative Prompt）**:
每个调度清单变体恰好生成一次的服化叠加/场景变体/道具状态提示词。
_Avoid_: 衍生草稿

**三类型合并文档（Type-Merged Document）**:
人物/场景/道具三层产物各一个文档（描述：人物描述.md|场景描述.md|道具描述.md；基础/衍生：人物提示词.md（默认不裁头）|人物提示词_裁头版.md（结算确认后可选）|场景提示词.md|道具提示词.md），按 `## 001.` 序号分节；旧单文件首次运行自动迁移并入后删除。
_Avoid_: 每资产一个文件

## 画风

**高精度三维国漫设定集风（斗罗/玄机风格）**:
用户确认的目标画风：以用户提供的参考图为唯一基准，源自斗罗大陆/玄机科技/腾讯动漫的高精度三维国漫角色设定图。核心特征：纯白/浅灰纯色摄影棚背景、写实成人比例、物理渲染金属/丝绸/皮革/宝石材质、华丽鎏金/浮雕/刺绣/宝石装饰、蓝金/紫青/玉清/粉白等幻想配色、边缘光 + 柔和主光、无赛璐璐/非写实渲染/平涂/粗描边/二维平面感。输出形式为角色设定集：同一画面三格图板——左面人物正面特写，右面正视图与后视图，两格等大、身高比例一致、全身完整入画；不裁头版右面两格保留头部，裁头版右面两格头部与面部裁除、脸的唯一真相是左面特写。适用于玄幻/仙侠/神魔/奇幻题材的主角与重要角色，也可扩展到同宇宙下不同服饰风格（西装、皮革、蒸汽朋克元素等）的角色，只要渲染层保持一致。**本画风为当前技能包最高优先级画风基准；任何模板、默认兜底、描述补全层出现与此矛盾的 NPR/赛璐璐/卡通渲染/硬边阴影色块表述，都必须按本定义清理。**
_Avoid_: 低模、哑光布衣、非写实卡通、二维平面感、NPR/赛璐璐/硬边阴影色块、卡通描边

**角色设定集输出规范（三格图板，双版）**:
高精度三维国漫设定集风的角色输出必须严格遵循三格图板：左面一格人物正面特写（头顶到锁骨、全脸清晰）；右面上下两格正视图（全身）与后视图（全身），两格等大、身高比例一致、全身立像从头到脚完整入画，严禁裁切脚部。背景为纯白或浅灰高调纯色摄影棚背景，突出角色主体与材质细节。默认 full 版右面两格保留头部；用户结算确认后生成 crop 版，右面两格头部与面部一律裁除不入画、脸的唯一真相是左面正面特写。本规范在人物基础/衍生提示词模板中强制执行，check_schedule 合规检查将其列为必守关键词。
_Avoid_: 单视图、半身裁切、缺头缺脚、三格身份/发型/服装不一致、裁头版右面格出现面部、带场景/背景/道具干扰、带文字/水印

**画风卡片（Style Card）**:
`references/画风库.md` 中一张风格定义（`### {ID}. 名称` + 中文定性 + 英文标签块 + 负面词），`--style` 名称触发与画风注入的单元；v2.6.1 起英文标签块仅作内部索引，不注入提示词。**新增风格 = 新增卡片**（照 `references/画风卡片模板.md` 填写），零改代码。
_Avoid_: 风格预设、画风模板（混淆时）

**分层卡（Layered Style Card）**:
画风卡新格式（ADR-0076）：四层渲染锁定（建模层/渲染层/场景背景/镜头）为必选基线，可选挂「风格包指针」提供视图层/材质层/共享不变量/负面词；无风格包的老卡继续可用（渲染层兜底：无分层时注入中文定性第一段）。
_Avoid_: 一句氛围词卡（当指无分层老卡时）

**风格包（Style Pack）**:
`references/stylepacks/<画风ID>/` 的纯中文定性素材目录（脸部/全身/环境/物件四视图 + 16 类材质定性 + 共享不变量 + 负面词），由分层卡指针引用；英文原文仅作内部索引，绝不注入提示词。新增画风蒸馏卡 = 复制 `_模板/` 填中文定性 → 画风库挂指针 → 自检，零改代码。
_Avoid_: 外部英文技能直连、现场翻译注入

**验证收口（Verify Command）**:
`python scripts/maintenance.py verify --lib <资产库>` 一键跑 check_schedule/check_final/check_costumes 并输出「验证/状态判定」结论（ADR-0080）；交付契约「验证」栏的唯一机械来源，编排器不得手写验证数字。`--style` 未传时自动沿用启动状态文件。
_Avoid_: 手写验证结论、静默跳过画风检查

**AI味拦截（AI-Flavor Gate）**:
check_schedule 的机械文风检查（ADR-0080，词表借「去AI味」技能）：禁用起手式与翻案腔句式→「AI味措辞」，非负面行顿号≥10→「顿号罗列过密」；覆盖描述/基础/衍生全部文档。负面提示词行豁免顿号密度（合法顿号链）。
_Avoid_: AI 腔起手式、满篇顿号罗列、翻案腔句式

**交付契约（Delivery Contract）**:
步骤 8 的证据收口协议（ADR-0079）：状态（DONE/BLOCKED/NEEDS_REVIEW）+ 范围/读取与生成/验证/失败项/下一步六栏；DONE 只能与验证通过同时出现，数字一律取自脚本 stdout 汇总行；完成后主动给出 2-3 个可执行下一步选项。
_Avoid_: 无状态判定的流水账报告、编造统计数字

**运维脚本（Maintenance Script）**:
`scripts/maintenance.py` 的 status/init/backup/restore/verify/migrate 命令（ADR-0079/0084）：status 按断点定位表判定已完成步骤与产物统计；init 手动初始化（原子写 `.start-state.json`，E2）；backup 打包时间戳 zip；restore 带 zip-slip 防护、非空目标覆盖须 --force；verify 一键收口且签发门要求启动证据可核验（E1）；migrate 老库迁移。
_Avoid_: 手工拷贝备份、无防护的覆盖恢复

**签发门（Signing Gate，E1/v2.14.0）**:
`maintenance.py verify` 签发交付清单前的证据核验：`.start-state.json` 缺失/不可解析、其 `input_source` 不存在、或显式画风与启动状态画风不是同一张画风卡时，非零退出并拒绝生成 `交付清单.json`，原因码 `SOURCE_UNVERIFIABLE` / `STYLE_UNVERIFIABLE` / `STYLE_MISMATCH` 写入 `.process/验证报告.md`；等价别名（`A2` ≡「仙侠奇幻风」）不算冲突。源或画风变化后 `status --json` 立即脱离 `DELIVERED`。
_Avoid_: 缺源仍判 DELIVERED、把编号与卡名当不同画风、裸 `--style` 绕过启动状态画风

**手动初始化（Manual Init，E2）**:
`python scripts/maintenance.py init --lib <资产库> --input-source <原始txt/md> --genre <题材> --style <画风>`：非交互宿主写 `.start-state.json` 的入口（字段与开始界面一致，原子替换写入）；`--style` 未命中画风卡时显眼提示并降级自由描述模式；已存在且参数不同须 `--force`。
_Avoid_: 手写状态文件字段缺失、预支不存在的源证据、静默覆盖已有状态

**道具审美骨架（Prop Aesthetic Skeleton）**:
道具模板级静物组织必守七条（ADR-0078）：剪影可读、边缘层级（仅一处焦点轮廓锐利）、干燥表面反应、材质靠光学表达、功能性痕迹（只在接触点/把手/开合处）、构造感（细节解释形体或功能）、落地稳固；与物件视图定性（画风个性）互补。
_Avoid_: 满版做旧、全件均匀锐边、无意义装饰、道具正文跨资产雷同

**视图定性注入（View Qualitative Injection）**:
画风包四份视图定性（脸部/全身/环境/物件）按资产类型路由逐字注入提示词「视图基调：」段：人物=脸部+全身、场景=环境、道具=物件（ADR-0077）；与模板级「环境审美骨架」（剪影/三层景深/明度组织/留白/远景简化）互补——骨架管共性、视图定性管画风个性。
_Avoid_: 视图文件零注入、场景层次跨场景套话雷同

**材质路由（Material Routing）**:
生成时按资产类型与画面实际材质从风格包选取对应材质定性并入材质四件套（人物=皮肤/头发/布料/金属/皮革/妆面，场景=石/木/植被等，道具按材质表）；物件图不读角色视图，空场景不读角色文件，不全量注入。
_Avoid_: 全量材质注入、跨类型材质混入

**题材挂钩（Genre Mapping）**:
`references/题材-画风映射.md` 的一行（题材 → 默认画风 ID），是「按题材自动命中画风」的唯一入口；无挂钩的卡片只能 `--style` 手动触发。卡片内「适用」字段仅为备注，不生效。
_Avoid_: 卡片「适用」字段（当指题材挂钩时）

**风格组装（Style Assembly）**:
按剧本类型组合混合风格的机制：`references/风格组装参考.md` 组件表（内容/渲染/色调/氛围四维，措辞取自画风库原卡）→ 编排器起草 H 卡 → **用户确认后落库**。混合风格经常使用时落成 H 卡（稳定资产），而非每次临时自由描述。
_Avoid_: 临时自由描述（当指长期使用的混合风格时）

## 输出约定

**纯中文输出（Pure Chinese Output）**:
视觉描述、基础/衍生提示词、服饰设计角色条目与生图提示词正文全程纯中文；唯一例外为十六进制色值（如 `#E63946`）与数字比例（16:9、6.5 头身）。连续 2 个以上英文字母由 check_schedule 机械校验拦截。
_Avoid_: 中英混排、英文标签注入

## v2.16.0 术语补充

- **三种视觉模式**：`data_only`（只反推，不建计划）/ `prompt_only`（只出提示词任务包，零网络）/ `direct_generate`（调引擎生成）。
- **六项审核绑定**：任务编号 + 图片 SHA-256 + 提示词哈希 + 参考集哈希 + 画风包哈希 + 构图卡哈希；任一变化审核失效。
- **硬门（hard gate）**：16 个一票否决的问题码，存在任一即不得「通过」或「通过但有备注」。
- **四种判定**：通过 / 通过但有备注 / 需要返工 / 无法判断（需要人工决定）；`QC_UNTRUSTWORTHY` 只表示检查本身不可信。
- **单写者协调器**：唯一可以写 `视觉资产/计划.toml` 的角色；工作器只返回事件。
- **事件日志（写前日志）**：`.process/视觉事件.jsonl`，先落事件再写计划，用于崩溃恢复。
- **revision**：计划每次提交 +1，用于识别并避免覆盖他人更新。
- **审核子代理**：可选的美术/技术两个只提供证据的角色，默认关闭，没有签发权。
- **导演构图卡**：景别/视角/机位/站位/视线/遮挡/道具/锚点/禁止项的结构化卡片，进提示词编译。
- **场景站位图**：场景的锚点、出入口、可站立区域、行动轴线与不可穿越区域。
- **迁移提案**：旧库只读扫描的产物，含每张图片的路径/哈希/尺寸与每项任务的候选匹配分数。

## v2.17.0 术语补充

- **源事实库**：`.process/source-facts.jsonl`，从原文确定性扫描出的带出处事实，是总账的上游。
- **类型化资产总账**：`.process/asset-ledger.json`，机器层唯一库存源（人物/场景/道具/服装/后期元素），
  每条带 `ledger_status` / `narrative_importance` / `production_mode` / `required_outputs`；旧四表由它渲染。
- **数量守恒**：`正式资产 = 已产基础提示词 + 明确待审 + 明确阻断`；既无产物又无原因即违规。
- **依赖图**：`.process/artifact-graph.json`，边语义 `src → dst 表示 dst 依赖 src`：
  源事实 → 总账项 → 提示词 → 图片任务 → 审核结果，另有共享的「项目美术总则」节点。
- **内容寻址缓存**：按输入指纹复用产物；指纹相同但载荷不同时报「指纹碰撞」，不静默沿用旧内容。
- **确定性编译**：提示词由九分区 IR 按固定顺序渲染，相同输入两次编译逐字节一致；模型只补审美候选与歧义裁决。
- **shadow / apply**：`compile-prompts` 的两种模式。shadow 只写差异报告、不覆盖正式产物；apply 才并入并先备份。
- **规则优先级**：`用户明确要求 > Omni标准 > 原文事实 > 项目美术总则 > 唯一主风格包 > 类型模板 > 必要补全`。
- **项目美术总则**：`.process/项目美术总则.json`，带内容指纹；文件缺失＝未设定，指纹不符＝显式失败。
- **编译链八段**：事实库 → 总账 → 提示词 → 图片计划 → 生成 → 审核 → 返工 → 签发（`status --json` 的 `compiler_stages`）。
- **视觉阶段**：`PLANNED / GENERATING / REVIEWING / REWORK / SIGNED`；最新失败立即撤销实时交付。
- **九项签发契约**：`check_schedule` / `check_final` / `check_asset_index` / `check_asset_coverage` /
  `check_art_constitution` / `check_artifact_graph` / `check_required_prompts` /
  `check_visual_review`（仅产品结果含生图时参与）/ `check_package_files`。
- **交付清单历史**：`<资产库>/交付清单历史/<时间戳>.json`，只作留档，永不作为当前有效依据。
