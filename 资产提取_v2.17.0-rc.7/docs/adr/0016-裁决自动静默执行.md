# ADR-0016: 裁决自动静默执行，不向用户罗列裁决过程

- 状态: Accepted
- 日期: 2026-08-19

## 背景

聚合裁决阶段会产出 `裁决输入_<块>.md`、`裁决_<块>.md`（5 块）、登记表对账报告等过程文件，脚本 stdout 也逐组打印预聚合结果。编排器据此向用户转述大量裁决细节，用户反馈「给我那么多裁决是什么意思，裁决部分能不能自动，不需要列给我看」。

## 决策

**裁决全程自动静默执行：脚本默认精简输出，编排器不向用户展示裁决过程文件；仅在有错误或需要人工决策时汇报一行摘要。**

1. `aggregate.py` 默认精简输出（过程明细需显式 `--verbose`）：只打印段产物统计、预聚合分组数、对账三项计数、分块裁决完成数、最终反推文件与正式/附录计数；预聚合逐组、补入摘要逐条、对账逐条、逐块完成日志仅在 `--verbose` 下输出。
2. 编排器只静默核验：退出码为 0、反推文件重建成功、无「裁决解析丢弃」阻断；核验通过直接进入下一步。
3. 仅以下情况向用户汇报：脚本返回非 0（贴错误行）；待确认附录非空（名称/类型/原因，每项一行）；对账漂移/幻觉项（只报数量，明细指向 `登记表对账报告.md`）。
4. 过程文件仍全部落盘（供调试与人工修正），只是不再作为对用户的默认汇报内容。

## 权衡

| 备选 | 优点 | 缺点 |
|---|---|---|
| A. 逐块展示裁决供用户确认 | 用户掌控每个合并/等级决策 | 信息过载，违背自动化初衷 |
| B. 自动静默 + 异常/附录摘要（选定） | 流程快、用户只看结论与人工决策项 | 用户无法逐条干预裁决（有异议时仍可打开过程文件人工修正） |

## 影响

- `scripts/aggregate.py` 增加 `--verbose`；`SKILL.md` 步骤 3 与完成报告的汇报口径同步修改。
