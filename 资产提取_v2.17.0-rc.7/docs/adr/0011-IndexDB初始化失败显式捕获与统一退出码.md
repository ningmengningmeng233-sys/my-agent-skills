# ADR-0011: IndexDB 初始化失败显式捕获与统一退出码

- 状态: Accepted
- 日期: 2026-08-18

## 背景

`scripts/engine/index_db.py` 中的 `IndexDB` 类负责管理 SQLite 状态数据库（`.asset_state.db`），支撑断点续跑。其 `__init__` 方法目前直接调用 `sqlite3.connect(...)` 并执行建表语句，未显式处理连接失败、磁盘只读、目录不存在或 SQL 异常等情况。一旦初始化失败，异常会向上抛到调用脚本，可能让调用脚本以不可控的堆栈退出，干扰自动化与 e2e 测试的退出码判断。

## 决策

1. 在 `IndexDB.__init__` 中显式捕获初始化异常（连接失败、建表失败、`sqlite3.Error` 等），打印可读的失败原因与涉及文件路径。
2. 设置实例标志 `self.ready = False`；后续所有修改型方法在 `ready == False` 时直接返回，避免在无效连接上继续操作。
3. 调用方脚本在发现 `index_db.ready == False` 时，统一以 `exit(1)` 退出；同时保证脚本入口的 `sys.exit(main())` 能正确传播非零退出码，使 CI/e2e 能识别失败。
4. 保留 `read_text_auto()` 等现有逻辑不变，仅增强初始化阶段的健壮性。

## 权衡

| 备选 | 优点 | 缺点 |
|---|---|---|
| A. 不处理，继续向上抛异常 | 改动最小 | 退出码不可控，自动化复验无法稳定判定失败；错误信息不友好 |
| B. 捕获异常后继续尝试降级（如内存数据库） | 流程不中断 | 破坏断点续跑语义，用户可能误以为已保存状态 |
| C. 显式捕获并标记不可用，调用方统一退出（选定） | 错误清晰、退出码一致、不破坏状态语义 | 需要修改所有调用 `IndexDB` 的入口点 |

选择 C 是因为断点续跑依赖持久化 SQLite，降级内存数据库会引入隐式数据丢失；统一退出码则是自动化测试与 CI 的基本要求。

## 影响

- 修改 `scripts/engine/index_db.py`：`IndexDB.__init__` 增加异常捕获、`self.ready` 标志；修改型方法增加 `ready` 检查。
- 修改调用 `IndexDB` 的入口脚本（如 `extract_segments.py`、`aggregate.py` 等），在初始化后检查 `ready`，失败时 `sys.exit(1)`。
- e2e 复验与 CI 可以依赖稳定的非零退出码判断初始化失败类错误。
