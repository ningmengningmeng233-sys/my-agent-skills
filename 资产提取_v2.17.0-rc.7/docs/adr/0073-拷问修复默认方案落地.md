# ADR-0073: 拷问修复默认方案落地（题材显式化/清单追加/纯幻想内容语言/裁头硬阻断）

- 状态: Accepted
- 日期: 2026-08-19

## 背景

上一轮拷问列出的残余策略点，经用户确认按默认方案执行：自动化管道不应静默默认题材；追更需要不覆盖手工编辑的清单追加能力；H7 内容语言在混合题材下不应误伤；裁头版不应在 full 缺失时继续生成。

## 决策

1. **`--yes` 必须显式 `--genre`**：与 `--style` 同等硬校验，禁止自动化管道静默默认古风；手动交互仍可不传（步骤 0 已确认题材）。
2. **`--init-schedule --append`**：清单已存在时按「类型/资产/变体」去重追加默认新行，保留手工编辑；`--force` 仍全量重建；无 `--append` 保持跳过保护。
3. **内容语言只对纯幻想题材必查**：题材去掉 玄幻/仙侠/神魔/修真/奇幻 词后无残留才算纯幻想；「都市玄幻」「古代仙侠」等混合题材只查渲染四层，不强制内容语言。
4. **裁头版硬阻断**：`--view-mode crop` 时若 `提示词/基础/人物提示词.md` 不存在，直接报错退出，必须先跑 `--base --view-mode full`。
5. **H7 锁定集成回归**：新增 `测试/unit/test_h7_lock_integration.py`，真实调用 `check_schedule --style H7`，覆盖缺层、缺内容语言、混合题材不误伤、全量通过。
6. **描述模板去花括号占位**：输出示例不再使用 `{{名称}}` 等双花括号占位，减少 LLM 原样输出占位符的风险。

- `scripts/check_schedule.py`（is_pure_fantasy）
- `templates/描述补全模板.md`
