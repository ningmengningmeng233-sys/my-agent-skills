# 直调引擎与出处强制架构

v1 流水线用 26 个子代理做同质重复任务（5 代理各读全文提取、每类 3 代理重复生成提示词），速度慢、token 爆炸，且"宁可多提取"的激励导致幻觉资产泛滥、资产名被 LLM 术语化漂移（音响→加强混音器）。v2 改为：全文拆段（5章/段）后**每段只处理一次**，Python 直调引擎 32 路并行直调 LLM（复用索引v3 的断点/流式/退避框架），每资产/每变体恰好生成一次；并引入**出处强制**（资产必须带原文摘句+行号，聚合时脚本去标点匹配验证，失败进附录）与**主名规则**（资产名必须是原文词汇，违规名剔除）。总阅读量从"代理数×全文"降为"1×全文"，500 章全流程约 **25-35 分钟**（拆段后：登记表候选遍 + 段级提取各处理一次、分层聚合 ≈log₂(段数) 轮、32 路并行、SQLite 断点续跑；启用 `--overlap 1` 时 token 约 +20%）。

> ⚠️ 更新（2026-08-16）：原预估「20 分钟内」为登记表候选遍引入前的数字，现统一为 25-35 分钟（与 SKILL.md 一致）。

Status: accepted

Considered Options:
- 子代理按段分工（免 API key、落地快，但每段有子代理启动开销，并发约 10，速度低一档）→ 保留为降级备选，未实现
- 多代理共识表决（v1 方案，5 代理同 prompt 会产生趋同幻觉，"≥3 次确认"反而给幻觉发合格证）→ 弃用
- 纯脚本聚合（无 LLM 裁决，名称语义合并不可靠）→ 采用脚本预聚合 + 一次 LLM 裁决的混合

Consequences:
- 流水线依赖 OpenAI 兼容 API key（.env），无 key 时不可运行直调部分
- 提示词质量从"多代理择优"变为"单次生成 + 模板约束"，依赖模板质量与生成器能力
- 旧 v1 手册归档于 references/legacy/，仅作参考
