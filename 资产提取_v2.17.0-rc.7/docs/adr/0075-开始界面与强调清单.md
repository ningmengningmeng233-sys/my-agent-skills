# ADR-0075: 开始界面 + 强调清单 + 服装/人物自动强化指令

- 状态: Accepted
- 日期: 2026-08-20

## 背景

用户要求流程启动时必须有明确的“开始界面”，且要解决“服装更华丽、人物更精美”但用户不想手动逐项强调的问题。拷问确认：开始界面固定展示输入源/画风/需要强调的部分/输出位置；强调清单作为可选补充；华丽/精美由技能根据身份/服装/场合/原文自动输出具象指令，不用“中高低”抽象分级。

## 决策

1. **开始界面（步骤 0）**：固定 Markdown 面板，展示输入源、画风确认、需要强调的部分、输出位置（含缓存位置）。首次完整确认；断点续跑/追更快速确认；单步入口也必须先确认。不确认不写盘。
2. **参数持久化**：`<资产库>/.start-state.json` 保存 input_source/genre/style/emphasis_hash/output_root/last_confirmed_at；强调清单内容变化用 emphasis_hash 检测，变化后需重新确认。
3. **强调清单**：`<资产库>/强调清单.md`，仅读取 `## 必须强化` 与 `## 必须避免` 两个分区，每行 `- `；缺失视为无额外强调。只影响 描述/基础/衍生/服饰设计，不影响 提取/聚合/登记表。
4. **自动强化指令**：描述补全阶段根据角色身份、重要等级、服装妆造表、剧本场合、原文线索自动输出“服装强化方向 / 人物精美强化方向”两组具象指令；基础/衍生/服饰设计逐字继承。不使用“华丽度中高低”等抽象词。
5. **强化指令模板**：按 if-then 选择固定可执行文字（主角/重要角色高华丽、日常精致、平民干净、战斗让位于状态），不依赖用户手动强调。
6. **软引导不硬检查**：check_schedule 不新增“必须出现华丽”类硬检查；只校验强调清单格式（若存在）和状态文件字段（若存在），避免误杀平民/朴素角色。

## 影响

- `SKILL.md` 步骤 0 重写为 Markdown 开始界面
- `CONTEXT.md` 新增术语
- `templates/描述补全模板.md`、`templates/基础提示词模板-人物.md`、`基础提示词模板-场景.md`、`基础提示词模板-道具.md`、`templates/衍生提示词模板.md`
- `scripts/generate_prompts.py` 读取强调清单并注入模板
- `scripts/check_schedule.py` 校验强调清单格式
