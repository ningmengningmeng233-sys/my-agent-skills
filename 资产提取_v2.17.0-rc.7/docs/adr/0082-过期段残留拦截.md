# ADR-0082: 拆段过期段残留拦截

- 状态: Accepted
- 日期: 2026-09-06

## 背景

第二轮冒烟测试发现：源文件章节范围变化（如 5 章删改成 2 章）后再跑拆段，新段文件名（章节范围命名）与旧段不同名，同名冲突检测永不触发——**旧段文件静默残留**在 `原文段/` 中，后续登记表/提取/聚合会把过期章节当有效数据处理。

## 决策

1. `split_by_chapters` / `split_by_chars` 返回本次分段方案的 `planned_names`（含跳过/冲突的全部计划段名）。
2. 全量模式（非 `--append`）跑完全部源文件后，比对段目录已有文件与计划名单：
   - 差集非空且带 `--force` → 自动删除过期段并报告「🗑️ 已清理」；
   - 差集非空且无 `--force` → **rc=1 拦截**，列出到期段并提示两条出路（确认后 --force 自动清理 / 改用 --append 增量模式）——降级必须可见。
3. `--append` 增量模式不受影响（末段并入机制保持原段名，无过期概念）。

## 被放弃的备选

- **只警告不拦截**：警告会被忽略，过期数据照常流入后续步骤——与防偷懒原则（ADR-0080）冲突，选择 rc=1 硬拦。
- **自动无差别清理**：无 --force 时静默删文件违反「破坏性操作需确认」，选择须显式 --force。

## 影响

- `scripts/split_segments.py`（planned_names + 过期段拦截/清理）
- `测试/unit/test_split_segments.py`（TestStaleSegmentGate 2 用例：范围变化拦截+force清理、幂等重跑）
- 版本 v2.11.6
