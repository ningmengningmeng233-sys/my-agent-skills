# 0084. 跨平台状态机与资产关系 (Cross-Platform Pipeline State & Asset Relations)

- **状态**: 采纳（含 v2.13.1 可靠性修复说明，见文末）
- **日期**: 2026-09-13
- **版本**: v2.13.0（修复版 v2.13.1）
- **作者**: 柠檬才不萌

## 背景与问题

资产提取流水线在 v2.12.0 阶段已具备纯中文画风分层卡、风格包注入、SQLite 任务断点续跑和多任务并发调度。然而，在小说/剧本向三维资产深水区演进的过程中，暴露出四个维度的结构性瓶颈：

1. **项目状态判断偏乐观且平台依赖**：
   - 现有 `maintenance.py status` 主要基于段文件数量、目录存在性与提示词分节数判断。即便部分批处理任务失败或文件解析异常，依然可能显示偏乐观的“已完成”。
   - 缺少平台无关、结合物理源文件指纹与任务库状态的统一单源状态机，缺乏 `--json` 机读输出能力。
2. **事实等级与证据边界模糊**：
   - 原文事实、强推断与制作方创意设定混杂在描述字段中。没有事实等级标记导致无法区分哪些细节来自小说原著，哪些来自模型补全或美术提案。
3. **资产关系网络缺失与服装/变体紧耦合**：
   - 人物身份与服装状态绑定依靠名称推断，跨段更名容易丢失稳定关联；同名异物缺乏实体主键（`stable_key`）；缺少显式关系支持（`WEARS`, `APPEARS_IN`, `LOCATED_IN`, `CONNECTS_TO`, `STATE_OF`）。
4. **场景空间连续性缺乏母版约束**：
   - 场景变体虽支持时段与天候，但视角派生缺乏基线母版卡（空间结构、固定锚点、出入口、连接点、未知项）；模型容易将未说明细节（如门把手方向）幻化为固定事实，导致不同镜头间空间逻辑冲突。

## 决策

升级资产提取流水线至 **v2.13.0**，全面贯彻以下决策：

### 1. 严格四类资产边界与具象子类
- 保持当前四类资产大类不变：**人物、场景、道具、服装**。
- 生物、神兽、机械兽归入现有“人物”或“道具”的具象子类（`subtype`）；载具归入“道具”；不引入第五、第六条大类管线，下游解析器与旧 ID 体系保持兼容。
- 视觉 DNA 作为项目级文本配置，不作为需要独立生图的实体。

### 2. 规范化资产索引与四级事实等级
- 聚合裁决产物在保持 `反推_最终.md` 旧 Markdown 四表与旧 ID（`CH_*`, `SC_*`, `PR_*`, `CO_*`）格式不变的前提下，新增 `<资产库>/.process/资产索引.json`。
- 引入实体主键 `stable_key`（按类型与首次出处排序分配并持久化映射），确保同名异物不混淆、前序插入章节不破坏后续资产标识。
- 引入严格的四级事实等级（`fact_level`）：
  - **剧本事实**：必须有一字不差且已验证的原文摘句与行号。
  - **强推断**：具备 2 条以上明确线索或闭环推导句。
  - **制作提案**：纯视觉填空或美术创意，严禁提升至“原文事实”。
  - **待定冲突**：存在前后文矛盾或无证据事实，阻断受影响提示词生成并进入附录。
- 引入生产顺序优先级（`P0/P1/P2/P3`）：P0 为被依赖项，P1 为核心资产，P2 为辅助资产，P3 为文字足够/无需独立基础提示词（记录跳过原因）。

### 3. 五种显式关系与实体解耦
- 索引仅维护五类核心关系：
  - `WEARS`：服装 → 人物（边落在服装侧；同本文 §影响 的关系矩阵与 `asset_schema.RELATION_MATRIX`）
  - `APPEARS_IN`：人物/道具 → 场景
  - `LOCATED_IN`：道具 → 场景
  - `CONNECTS_TO`：场景 ↔ 场景（门槛/出入口双向对齐）
  - `STATE_OF`：变体 → 母资产
- 人物身份字段（骨相、生物特征）与服装状态字段解耦，严禁因换装导致身份锁漂移。

### 4. 场景空间母版与视角继承
- 新增 `<资产库>/连续性/场景母版.md`：记录空间结构、固定锚点、出入口、连接点、材质光源与未知项。
- 原文未提及的空间细节一律填写 **“未说明”**，严禁脑补填空。
- `提示词/调度清单.md` 增加 `母版ID` 与 `仅允许变化` 两列。视角派生提示词必须继承母版已确认锚点。

### 5. 八阶段统一跨平台状态机与交付清单
- 新增 `scripts/engine/pipeline_state.py`，由物理产物、指纹哈希和 `.asset_state.db` 推导 8 大主状态：
  `SOURCE_READY` → `SEGMENTED` → `REGISTERED` → `EXTRACTED` → `CATALOGED` → `PROMPTS_READY` → `VERIFIED` → `DELIVERED`。
  包含 4 个判定状态：`WAITING_INPUT`, `BLOCKED`, `NEEDS_REVIEW`, `NEEDS_CONFIG`。
- `maintenance.py status --json` 提供机器可读状态。
- `maintenance.py verify` 通过后生成 `<资产库>/交付清单.json`；任何源、风格或产物指纹改变自动回退。
- `maintenance.py migrate --lib <资产库>` 实现老项目安全无损迁移（自动时间戳 zip 备份）。

## 结果与影响

- **向上兼容**：旧版 Markdown 表格与提示词格式不变，旧 ID 继续作为展示与解析键。
- **机械自洽**：通过证据校验、关系网络闭环与母版锚点检查，根除了命名漂移与空间逻辑冲突。
- **跨平台可靠**：完全基于 Python 3 与标准库，可在 Windows/Linux/macOS 宿主无缝运行，不依赖专有宿主指令。

## v2.13.1 可靠性修复说明（2026-09-13，不扩类只修闭环）

- **编码**：全部子进程调用显式 `encoding="utf-8", errors="replace"`，默认 Windows GBK 下质量门全绿，不依赖 `PYTHONUTF8`。
- **状态机**：`status` 未传即时验证时读已签发清单，有效即 `DELIVERED`；文本 `已完成步骤/下一步` 与 JSON 同源；源指纹绑定原始输入文件+段清单；画风指纹含卡片分层与风格包内容，调度清单纳入产物指纹；清单 `status/checks` 缺失或失败不得为 `DELIVERED`。
- **母版**：正常聚合写完索引后安全合并母版（保留人工字段，冲突写 `母版冲突待审.md`）；默认调度场景行自动填母版 ID；派生请求注入已确认锚点+未变约束+仅允许变化；`CONNECTS_TO` 查双向对称与场景类型，母版漂移查锚点改写，派生正文查锚点保留。
- **索引**：`needs` 改显式参数；悬空关系进 `unresolved_relations` 并阻断；`stable_key_mapping` 与资产同一次分配；别名多命中抛冲突；假摘句（quote 不在段文件中）阻断；关系类型矩阵为代码唯一来源（`WEARS: 服装→人物`、`APPEARS_IN: 人物→场景`、`LOCATED_IN: 道具→场景`、`CONNECTS_TO: 场景↔场景`、`STATE_OF: 变体→母资产`）。
- **回归**：`run_all_checks.py` 纳入 `run_fresh_v2131.py`（临时库聚合→索引→母版→调度→清单→回退矩阵）；真实 API 抽样未执行，标记为离线功能完成。

## v2.13.1 R1–R4 契约修正说明（2026-09-13，修到"可签发交付"）

- **R1 引用名解析**：摘要回填名（`（脚本补入）`后缀）必须先剥标记再剥未配对括号；成对括号是名字本身。主名/别名命中多个实体时一律记 `unresolved_relations` 待审（`场景名歧义，需人工裁决`），禁止静默映射到任一实体；字符串包含不做模糊绑定。叙述句、未登记场景保持未解析并阻断签发。
- **R1/R4a 分配器复用域**：别名唯一复用只针对**外部传入的历史映射**（老库续跑）；同一构建内两个新实体共享别名不得互相吞并 stable_key。
- **R2/R3 交付签发契约**：fresh 正例必须走真实命令链（e2e_flow 步骤 7.5 `verify` 签发、7.6 `status --json` 达 `DELIVERED/DELIVERY_VALID`）；交付清单必需检查集合为 `check_schedule/check_final/check_asset_index`（`REQUIRED_DELIVERY_CHECKS`，服饰检查按触发附加），缺任一即 `DELIVERY_CHECKS_INCOMPLETE`。签发后变化矩阵：改源（`SOURCE_CHANGED`）、删必需基础节、删调度行、删关系端点、改母版、画风卡内容变化（隔离技能包副本验证内容敏感指纹）都必须脱离 `DELIVERED`；`verify` 失败不覆盖历史清单。
- **R4a 索引 mapping**：`build_asset_index` 显式返回 `stable_key_mapping`（与 assets 同一次分配），废除 `last_allocator` 函数对象侧信道与 `engine/asset_index_keys.py` 的"缺键补记"回退；并发构建不再可能串库。
- **R4b STATE_OF 契约**：四类资产下不存在独立变体节点——变体需求一律记入资产级 `variant_needs`（`需求`/`章节`），不再制造母资产 `STATE_OF` 自环。`RELATION_MATRIX` 移至 `asset_schema.py` 为单一真相，validator 与 continuity 共用；旧索引中的自环**显式报错**（要求重跑聚合），不得默默重解释；自环与跨类型 `STATE_OF` 均为签发阻断项。
