# ADR-0010: 单元测试优先覆盖章节识别

- 状态: Accepted
- 日期: 2026-08-18

## 背景

当前技能测试以端到端（e2e）快照复验为主，覆盖整体流程，但对关键纯函数缺乏快速回归的单元测试。特别是 `split_segments.py` 中的章节识别与中文数字转换逻辑：

- `cn2ar()` 负责中文章号到阿拉伯数字的转换，直接影响段文件名和章节范围标签；
- `find_chapter_lines()` 负责从正文中识别章节标题，是流水线的入口；
- `range_label()` 负责处理乱序章节等边界情况下的范围显示。

这些函数一旦回归，会导致拆段错误、段号错乱、章节范围标签倒挂等问题，修复代价远高于早期发现。

## 决策

新增 `测试/unit/` 目录，使用 Python 标准库 `unittest`（不引入 pytest 等外部依赖）编写单元测试，**优先覆盖章节识别相关函数**：

1. `cn2ar()`：覆盖个位、十位、百位、千位、万位、混合格式、年份位值写法等。
2. `find_chapter_lines()`：覆盖标准章、回、卷、话、集，千/万级章号，序章/楔子/番外，行首数字列表不误识别等。
3. `range_label()`：覆盖正序、倒序、单章等场景。
4. 后续再逐步扩展至 `parse_frontmatter()`、`safe_name()`、`split_template()`、`parse_verdict()` 等函数。

## 权衡

| 备选 | 优点 | 缺点 |
|---|---|---|
| A. 继续只依赖 e2e 快照 | 测试贴近真实流程 | 回归定位慢，拆段错误需跑完整流程才能发现 |
| B. 引入 pytest + 大量单元测试 | 生态丰富，断言表达力强 | 增加外部依赖，与技能包轻量目标冲突 |
| C. unittest 优先覆盖核心入口函数（选定） | 无新依赖，回归快速，聚焦高风险函数 | 覆盖范围有限，需持续补充 |

选择 C 是因为技能包应尽量保持依赖最小化，而 `unittest` 已足够支持纯函数回归测试。章节识别是流水线入口，优先覆盖收益最高。

## 影响

- 新增目录 `测试/unit/`。
- 在 `测试/run_e2e_check.py` 中追加对单元测试的调用，使其成为 e2e 复验的前置步骤。
- 后续新增或修改拆段逻辑时，必须同步补充/更新对应单元测试。
