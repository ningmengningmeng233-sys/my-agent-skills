# 0085. 核心反推与可选视觉边界 (Narrative Extraction Core & Optional Visual Boundary)

- **状态**: 采纳
- **日期**: 2026-09-16
- **版本**: v2.15.0-rc.1
- **作者**: 柠檬才不萌

## 背景与问题

资产提取技能的首要职责是**从叙事文本中反推生产资产**：人物、场景、道具、服装四类，以及原文证据、稳定编号、关系、连续性、优先级与冲突裁决。视觉生产（生图提示词、参考图、生成与质检）是它的下游消费者，不是它的替代品。

随着画风库、风格包、三格图板视图模式与生图提示词模板不断增重，出现三类偏离风险：

1. **边界倒置**：视觉侧的新概念（结构图、材质参考、图板格数）开始决定反推侧的数据形态，反向污染事实判断与稳定编号。
2. **可选依赖硬化**：生成类配置（API 密钥）与视觉资产缺失，可能让「资料已交付」这一本可独立成立的状态无法签发。
3. **输入格式窄化**：只支持 TXT/Markdown 会把剧本（DOCX）与电子书（EPUB）挡在门外，而为了兼容 PDF 又容易滑向 OCR 建设。

## 决策

### 1. 双交付状态线（规格 9）

`collect_pipeline_state(lib)` 在原有状态机上增量返回两条互不阻塞的状态线：

- `data_delivery`：镜像核心状态机，取值与顶层 `state` 一致。
- `visual_delivery`：独立推导，未创建视觉计划时为 `NOT_ENABLED`（`VISUAL_OPTION_NOT_ENABLED`），**这是合法状态而非失败**。

顶层 `state` / `reason_code` / `evidence_path` / `next_command` 逐字保留，旧调用者不受影响。核心流程不得导入 Gemini SDK、不得要求任何生成类密钥、不得因为视觉任务未完成而拒绝资料签发。

### 2. 输入规范化层（规格 4）

新增 `scripts/engine/source_normalizer.py` 作为唯一入口 `normalize_sources(paths, order_file=None) -> NormalizedSource`：

- 统一中间产物为 UTF-8 Markdown，每个来源前写不可变来源注释（文件名、SHA-256、顺序）。
- 每个 `SourceUnit` 可追溯到原文件、文件哈希、顺序、卷/章/集/场与段落序号、原文摘句。
- 编码只做显式探测（UTF-8 BOM / UTF-8 / GB18030），无法解码即 `SOURCE_DECODE_FAILED`，**绝不 `errors="ignore"` 静默丢字**。
- 多文件项目：显式顺序清单优先（重复/缺失/越界分别报 `SOURCE_ORDER_DUPLICATE`/`SOURCE_ORDER_MISSING`/`SOURCE_ORDER_OUTSIDE_ROOT`），未提供清单时自然排序并把排序来源写入来源清单。
- 原文件只读，产物写资产库 `.process/normalized_sources/`。

### 3. 正式输入格式与拒绝面（规格 2.2、非目标）

- 正式支持：TXT、Markdown、DOCX、EPUB、多文件项目。
- DOCX：按正文文档顺序读标题层级、正文段落与表格文本，**只遍历 body 直接子元素**，页眉页脚天然不进正文；locator 轴为 `{标题}/段落N` 与 `表格N/行M`。
- EPUB：按 spine 顺序读章节（不按文件名排序），剔除 `nav`/`script`/`style`；locator 轴为 `{章节文件}#段落N`。
- PDF：在读取内容之前以 `UNSUPPORTED_SOURCE_FORMAT` 拒绝，并提示先转 TXT/Markdown/DOCX/EPUB。**不支持 PDF，不建设 OCR。**

### 4. 四类资产不变，扩展靠子类型与视觉需求（规格 2.1）

顶层类型永远只有四类。新增中文子类型枚举 `ASSET_SUBTYPES` 与归一函数 `normalize_subtype(asset_type, raw)`：

- 已知同义词归一（怪物/妖兽/神兽 → 人物·非人角色；马车/舟船 → 道具·载具；宫殿/楼阁 → 场景·建筑；盔甲/铠甲 → 服装·甲胄）。
- 未知值归入「其他」并由 `subtype_with_raw` 保留原标签；空标签为「未细分」（旧记录默认）。
- 单字别名只做精确匹配，避免「林府」被误判为自然环境。

法术、天气、特效等感受性需求以 `visual_needs` 表达：必须绑定已有资产或场景（`validate_visual_needs` 拒绝悬空引用）、种类限定在 `VISUAL_NEED_KINDS`、事实等级为「剧本事实」时必须带原文摘句。`need_id` 前缀为 `VN_`，明确不是资产 ID。索引校验器继续拒绝任何第五类顶层类型。

### 5. 剧本场次识别

拆段层的章节正则纳入「第N场」，但**要求场后跟空白/标点/行尾**：`第一场 茶楼` 是场次标题，`第一场雪落了下来` 是散文。这条闸门同时防住了小说正文里的「第一场雪」。

### 6. 源指纹覆盖全部原始来源

规范化项目的 `.start-state.json` 记录 `source_manifest_path` / `source_manifest_hash` / `source_order_file`。资料清单的源指纹因此覆盖：全部原文件哈希、顺序清单哈希、规范化原文哈希与来源清单哈希。任一原始源变化 → 立即脱离 `DELIVERED`（`SOURCE_CHANGED`）；任一原始源或顺序清单缺失 → 启动证据不可核验（`SOURCE_UNVERIFIABLE`），拒签。

## 后果与权衡

**收益**

- 视觉模块失败、暂停或未启用时，资产资料交付仍然成立；两条状态线可在 `status --json` 中分别读出。
- DOCX 剧本与 EPUB 电子书进入正式输入面，且每个段落都能回查原始文件与位置。
- 四类顶层资产契约不动，旧 Markdown 四表、旧 `CH_/SC_/PR_/CO_` 编号、旧列表全兼容。

**代价**

- 新增运行时依赖 `python-docx`、`EbookLib`、`beautifulsoup4`（仅 DOCX/EPUB 输入路径需要；TXT/Markdown 单文件仍走既有直读路径，不产生中间产物）。
- 规范化项目多一层中间产物，源变化的影响面扩大到原文件本身（这是有意为之：源变了就不该继续算已交付）。
- 「第N场」进入章节识别后，理论上存在散文误判可能，用分隔符前瞻把风险压到可接受范围，并有正反两例测试钉死。

**未做（本轮非目标）**

- 不重新蒸馏旧风格；不把技能改造成纯生图工具。
- 不自动删除任何用户旧图片、旧提示词或旧风格包。
- 不用机器检查冒充尚未完成的人工审美验收。
