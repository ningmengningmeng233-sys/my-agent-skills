# ADR-0009: 交叉校验补建双保险机制

- 状态: Accepted
- 日期: 2026-08-18

## 背景

聚合阶段的「漏提候选补建」依赖章节摘要表：当段级提取的章节摘要漏写了某个资产时，交叉校验就无法发现该资产，导致补建遗漏。由于章节摘要由 LLM 生成，仅靠 prompt 约束难以保证 100% 完整。

## 决策

采用**双保险**机制，确保记录表与摘要表的一致性：

1. **Prompt 层反向自检**：在 `templates/段级提取模板.md` 的「章节摘要表规则」中增加一条——模型输出摘要表后，必须反向扫描记录表，确认每个已登记资产都出现在对应章节的摘要中；若缺失，强制补齐。
2. **脚本层硬校验兜底**：在 `aggregate.py` 的交叉校验阶段，脚本直接比较「记录表中的资产名称集合」与「各章节摘要中的名称集合」。若发现某资产在记录表中有出处记录但对应章节摘要中未出现，自动将该资产补入摘要字段，并标记为「脚本补入摘要」，再参与后续漏提补建逻辑。

## 权衡

| 备选 | 优点 | 缺点 |
|---|---|---|
| A. 仅 Prompt 层自检 | 实现简单，不改动脚本 | LLM 可能不严格遵守，漏提风险仍在 |
| B. 仅脚本层硬校验 | 兜底可靠 | 需要在聚合阶段解析记录表与摘要，增加脚本复杂度 |
| C. Prompt + 脚本双保险（选定） | 两层约束，漏提概率最低 | 聚合逻辑变重，但可接受 |

选择 C 是因为资产不漏提是流水线的核心目标之一，两层约束的成本低于漏资产导致的后期补录成本。

## 影响

- 修改 `templates/段级提取模板.md`，增加摘要反向自检规则。
- 扩展 `aggregate.py` 的交叉校验逻辑：解析记录表资产 → 按章节分组 → 与摘要字段比较 → 缺失则补入并打标。
- 补建资产的出现位置以记录表中的实际出处为准，比纯摘要补建更精确。
