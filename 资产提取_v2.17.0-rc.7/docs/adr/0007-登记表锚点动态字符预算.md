# ADR-0007: 登记表锚点动态字符预算

- 状态: Accepted
- 日期: 2026-08-18

## 背景

`extract_segments.py` 在段级提取前会将全局登记表注入 prompt 作为锚点，防止跨段命名漂移。v2.4 之前采用固定 800 行精简行的硬上限（`rows[:800]`）。

该上限对资产数适中的项目足够，但遇到超长篇网络小说（3000+ 资产、千章以上）时，后段资产会被截断，导致：
1. 后段提取时这些资产失去锚点，重新出现命名漂移；
2. 模型对同一资产反复标 `[新增]`，增加对账层负担；
3. 用户无法感知哪些资产未注入锚点，难以排查。

## 决策

将固定 800 行上限改为**动态字符预算截断**，默认预算 **12,000 字符**，并记录被截断的资产名。

具体行为：
1. 读取登记表精简行后，按字符数累计；累计超过 12,000 字符时停止注入。
2. 注入顺序保留「首现章升序 + 名称长度升序」，确保早期出现、名称简短的资产优先进入锚点（这些资产最可能被后文引用并产生漂移）。
3. 超出预算时被截断的资产主名列表写入 `registry_anchor_truncated.log`，供用户与对账报告参考。
4. 预算值可通过环境变量 `ASSET_REGISTRY_ANCHOR_BUDGET` 或命令行参数覆盖，默认 12,000 字符不变。

## 权衡

| 备选 | 优点 | 缺点 |
|---|---|---|
| A. 保留 800 行硬上限 | 实现简单，已验证 | 超长篇后段资产锚点丢失 |
| B. 按 token 预算（tiktoken） | 精确，适配不同模型 | 引入额外依赖；OpenAI 兼容接口的 tokenizer 不一定一致 |
| C. 按字符预算 + 日志（选定） | 无新依赖、可控、可观测 | 字符数与 token 数非线性相关，预算偏保守 |

选择 C 是因为本流水线已经强依赖 Python 标准库与 `requests/python-dotenv`，避免再引入 tokenizer 依赖；12,000 字符在中文场景下约等于 3K–4K token，为段级原文 prompt 留出足够余量。

## 影响

- 修改 `scripts/extract_segments.py` 中登记表注入逻辑。
- 新增日志文件：`registry_anchor_truncated.log`（与 `.asset_state.db` 同级，过程文件，可清理）。
- 不影响现有中小规模项目（资产 ≤ 2000 通常不会触发截断）。
- 对账报告可引用该日志，提示用户后段资产可能需人工复核。
