# ADR-0006: 服饰设计融合（短剧服装设计模块接入）

- 状态: Accepted
- 日期: 2026-08-17

## 背景

v2 的服装资产链路是弱项：服装妆造表只有「造型名称/绑定人物/出现位置/等级」，无服饰元素规范（白名单/黑名单）、无配色板（hex）、无纹样母题、无服饰校验。用户提供已优化完整的「短剧服装设计」skill（drama-costume-studio，含 8 剧种服饰约束库、角色设计方法论 chunpu+omer-metin、check_costumes.py 校验脚本），要求整体融合吸收、不破坏其完整性、保证正常触发。

## 决策

1. **模块整体迁入**：短剧服装设计完整迁入 `服饰设计/` 子目录（内容零改动），原目录保留。融合 = 接入层，不重写内容。
2. **自动衔接**：v2 步骤 3（聚合裁决）产出反推文件后**直接接上服饰设计，不询问**（用户拍板：没必要询问）。
3. **桥接脚本**：`scripts/prepare_costume_input.py`——反推人物/服装表 → 角色清单（服饰设计 2.1 结构化输入格式）→ 落盘 `<lib>/服饰设计/<剧名>/`。
4. **题材 → 剧种换算**：`references/题材-剧种映射.md`——v2 题材 → 8 剧种；命中/近似（标注）不询问；**仅未命中才询问**（唯一询问例外）；混合题材（如「都市玄幻」）按主剧种（匹配位置靠前者）判定，白名单交集/黑名单并集（服饰设计 ADR-0002）。
5. **双约束注入**：服饰条目同时注入 v2 画风锁定块（画面渲染）与剧种服饰约束（角色穿着）——两条独立链路互不覆盖。
6. **校验闭环**：`check_costumes.py` 阻断/警告分级（服饰设计 ADR-0003），阻断清零才交付；沿用服饰设计「标准先行/单角色修订/全局复检/剧名持久化」工作流。

## 权衡

| 备选 | 结论 |
|---|---|
| 整体并入 vs 数据吸收 vs 独立共存 | 整体并入（v2 服装链路弱项整套补位；用户要求「融合吸收」） |
| 迁入 v2 目录 vs 原地引用 | 迁入（单包分发、路径稳定、内容零改动）；原目录保留作备份 |
| 自动衔接 vs 询问衔接 vs 独立触发 | 自动衔接 + 独立触发双入口（用户拍板：直接接上，不询问） |
| 剧种映射近似兜底 vs 扩展 8 剧种 | 近似兜底（不改已优化好的服饰设计内容；映射表放 v2 侧可扩展） |

## 影响

- 新增 `服饰设计/`（16 文件，短剧服装设计完整迁入）、`references/题材-剧种映射.md`、`scripts/prepare_costume_input.py`
- `SKILL.md` 新增步骤 3.6（自动衔接 + 独立触发）；description 补服饰触发词
- v2 既有画风库/流水线核心不受影响（模块化接入）

补充（2026-08-17）：**服装-人物绑定注入基础提示词**——实测发现「裁决出的正式服装未进入人物基础提示词」，模板默认基础服顶替（古风人物穿现代衬衫/素色古装，与裁决服装表脱节）。决策：`generate_prompts.py` 步骤 5 自动读取反推文件服装妆造表 → 人物→绑定造型映射 → 注入基础提示词「绑定服装」字段（模板强制：有绑定服装以其为打底服装，视觉描述冲突时服装优先）；人物衍生（步骤 6）注入对应基础提示词全文，禁止编造「原本的X」基础状态。人物基础提示词 = 人物信息 + 正式服装，作为一块资产交付。
