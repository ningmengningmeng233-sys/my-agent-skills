# ADR-0019: 登记表生成层按输入内容哈希断点

- 状态: Accepted
- 日期: 2026-08-19

## 背景

追更 `--append` 会把新增章节并入末段（文件名不变、内容变化），或新增段文件插入排序中。审查发现 `scan_registry.py` 两处断点只看输出文件是否存在：

1. 候选表 `candidate_one`：末段内容变化后仍直接跳过，新章节资产漏登记；
2. 合并层 `merge_pair`：输出名 `merge_r<轮>_<序>.md` 固定，新段插入后同名合并对可能对应新的输入对，但旧输出存在即跳过，新候选不参与合并。

## 决策

**候选表与合并层全部改为按输入内容哈希断点。**

1. 候选表复用 IndexDB `should_skip(seg_path, out_path, seg_hash)`：状态 done 且源段哈希一致才跳过；`--force` 忽略断点全量重跑。
2. 合并层给每个 `merge_r*.md` 写伴生 `.hash`，值 = 两个输入表文件哈希的拼接哈希；重跑时输入对变化即重合并，未变化即跳过。
3. 无哈希记录的旧产物采用保守跳过并打印提示（避免存量库突然全量重烧钱；需要追更安全时 `--force` 全量重跑）。

## 影响

- `scripts/scan_registry.py` 候选与合并逻辑；追更步骤说明与 e2e 相关行为。
