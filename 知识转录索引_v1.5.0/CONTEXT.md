# 转录索引

为 B站视频转录 TXT 知识库建立可详细检索的索引技能。源文档无章节结构、繁体无标点断行，索引以「知识单元条目 + 本地向量检索」实现详细检索。

## 术语表

**转录文档**：
B站视频转录的 TXT 文件，统一命名 `标题_作者_日期_BV号.txt`，放置于源目录。
_Avoid_: 视频文件、转录稿、文本文件

**源目录**：
用户固定放置转录文档的文件夹（当前为 Obsidian 归档目录），技能每次运行扫描此处发现新文件。
_Avoid_: 输入目录、素材库、数据目录

**校对版**：
规则脚本（繁转简 + 断行合并成段落）产出的规范简体阅读文本，与原始文件一一对应，存放于 `校对版/`，是检索的阅读终点。
_Avoid_: 修正版、清洗稿、精简版

**条目（索引条目）**：
索引的最小单位——一个「能独立回答一个问题的知识单元」，含条目名、一句话概要、摘录、主题标签、行号区间。条目数由内容结构自然决定，不设跳过阈值。
_Avoid_: 知识点、词条、片段、索引项

**摘录**：
条目内嵌的规范简体原文片段（约 100~300 字），由 LLM 在切条目时书写，用于检索命中后的快速理解。
_Avoid_: 摘要、引用、引文

**摘要（AI摘要）**：
转录文档头部已有的结构化摘要（核心观点/主要论点/关键结论），是速览层，独立于条目存在。注意与「摘录」区分。
_Avoid_: 概述、简介

**行号区间**：
条目在原始文件中的位置坐标（起止行号），检索后用于回查原文。
_Avoid_: 段落号、位置范围、坐标

**双坐标**：
条目同时记录校对版位置与原始文件行号区间两种引用，分别服务于阅读与回查。
_Avoid_: 双重定位、双索引

**台账（manifest）**：
`索引库/manifest.json`，记录每个文件「是否已索引 + 源文件内容 hash」，增量更新的依据：新增处理、未变跳过、变更重建。
_Avoid_: 状态文件、注册表、索引记录

**向量库**：
全部条目的本地 embedding 集合，检索时对查询做余弦相似度 top-K 召回，毫秒级且零 token 成本。
_Avoid_: 向量数据库、向量索引、嵌入库

**测试残留排除**：
按精确命名特征跳过测试残留文件（`BV_TEST`/`BVFULL`/`BVPATH`/`端到端验证`/`测试作者`），不为其建索引。
_Avoid_: 垃圾过滤、排除清单

**双路召回**：
检索时向量相似度与关键词规范化（繁简/同音）两条路径并行召回并合并结果，防单路漏命。
_Avoid_: 混合检索、双检

**文件级条目**：
每个文件的 AI 摘要（核心观点/主要论点/关键结论）生成的 1 条向量条目，带摘要原文与双坐标锚点，与主题条目混合召回，服务于「哪个视频讲了 XX」的文件级问题。
_Avoid_: 摘要条目、速览条目

**清单模式**：
检索主流程——向量召回后按主题聚类、按作者分组的候选清单（「该主题有谁讲过」），由用户选择「看某一家」或「对比全部」后，AI 才精读作答。单来源命中（≤2 条）时清单很短，AI 提示用户直接精读，不强制走选择环节。
_Avoid_: 直接回答、列表模式

**对比模式**：
用户选「对比全部」时，AI 精读同一主题全部命中条目，输出各家一致点与分歧点。
_Avoid_: 聚合回答、多源合并

**标签词表**：
切条目时约束主题标签的主词表——AI 优先从词表选标签，新概念才允许新增，定期归并近义标签。聚类依据统一词汇，「主题×作者清单」才有质量。
_Avoid_: 自由标签、随意标注

**速查清单**：
清单/素材类正文（音效标签、快捷键表、资源列表等）的兜底条目——切条目时 LLM 判 0 条或锚点无法匹配短词行时，脚本强制生成 1 条「速查清单」条目（整篇区间），落实「一视同仁」。
_Avoid_: 兜底条目、索引清单

**内容指纹**：
台账以文件内容 hash 为主键、文件名仅为映射——文件改名/移动只更新映射，索引零重建；同 BV 号的重复转录仅提示用户，不自动删改。
_Avoid_: 文件名主键、自动去重

**重复文件（多路径同内容）**：
同一内容（hash 相同）出现在多个路径时，只索引第一份、其余路径提示跳过（ADR-0009）——复制粘贴的重复文件不重复建索引，也不参与 moved 判定（避免交替重切烧 token）。
_Avoid_: 双份索引、全量索引

**增量更新**：
每次运行仅处理台账之外的新文件（或内容变更的已索引文件），已索引且未变的文件零成本跳过。
_Avoid_: 全量重建、差量同步
