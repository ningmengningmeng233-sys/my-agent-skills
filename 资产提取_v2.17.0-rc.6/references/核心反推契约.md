# 核心反推契约（按需加载）

> 由 `SKILL.md` 主体下沉（阶段 8 工单 8.1，渐进披露）。执行核心反推流程时读本文件；视觉规则见 `references/视觉生产契约.md`，审核硬门见 `references/Omni质量审核契约.md`。

## 核心与可选视觉的边界（v2.15.0，ADR-0085）

本技能的首要职责是**从叙事文本反推生产资产**（人物/场景/道具/服装 + 原文证据 + 稳定编号 + 关系 + 连续性 + 优先级 + 冲突裁决）。视觉提示词生产是可选下游模块。执行时必须守住四条：

1. **核心不依赖视觉**：核心链路不得导入 Gemini SDK、不得要求任何生图密钥、不得加载图片、**不得因为视觉任务未完成而拒绝资料签发**。
2. **双交付状态线**：`status --json` 同时给出 `data_delivery`（资产资料）与 `visual_delivery`（视觉资产）。视觉未启用显示「视觉生产：未启用」（合法状态，**不是失败**）；部分完成显示已通过/需修改/待生成数量。两条线互不阻塞。
3. **四类顶层资产不变**：顶层类型永远只有 人物、场景、道具、服装。细化靠**中文子类型**（人物·非人角色、道具·载具、场景·建筑、服装·甲胄…）与**视觉需求**；法术/天气/特效一律作为挂在已有资产或场景上的视觉需求（`[视觉需求:天候=雨]`），**不新增第五类资产**，索引校验器会拒绝第五类 ID。
4. **视觉不反向接管事实**：视觉模块不得改写原文事实判断、资产分类、稳定编号、关系、连续性和迁移。

## 前置

1. `.env` 已配置——复制 `.env.example` 填写（`OPENAI_API_KEY` / `SUMMARY_API_URL` / `SUMMARY_API_MODEL`）。真实 `.env` 放技能包外 `~/.asset-extract/.env`（推荐，防随包分发泄漏）或技能目录 `.env`，加载顺序：`ASSET_ENV_PATH` 环境变量 → 技能目录 `.env` → `~/.asset-extract/.env`；依赖 `pip install requests python-dotenv`
2. 用户提出"提取资产""资产反推"或明确要求启动流水线时启动

## 上下文与运行纪律（长期，唯一权威位置）

本节约束执行模型（无论跑一次提取还是按工单施工）的上下文用量，防止上下文膨胀与幻觉；
其他文档只链接本节，不重复抄写：

1. **按阶段最小加载**：开始任务只读 `SKILL.md` 与当前阶段所需的子文档，不在启动时读入整个
   `references/`；进入视觉/审核/迁移等阶段才读对应契约（见 `SKILL.md` 第七节路由）。
2. **长输部落盘，上下文只留结论**：命令的完整输出写入日志文件，当前上下文只保留结论、退出码
   与证据路径（如 `.process/日志/*`、验收目录、报告文件位置）。
3. **每阶段收口更新交接摘要**：`文档/柠檬/交接/当前执行摘要.md`（维护柜内部约定路径，不随包；收件人按自有交接位置记录）记录目标、提交、已完成阶段、
   修改文件、验证结果、未决项与下一条精确命令。
4. **安全边界再压缩**：上下文估计达约 70%–80% 时，在当前工单的安全边界（写完文件、跑完门禁、
   完成提交之后）建立检查点再压缩；禁止在写文件、提交或门禁运行中途压缩。
5. **靠物理事实恢复，不靠聊天记忆**：新会话以设计方案、实施计划、当前执行摘要与 Git 状态恢复。
6. **已完成阶段的工具输出不重复读入**：只引用其结论与证据路径。
7. **子代理只接收最小上下文**：给子代理的输入仅完成其任务所需；主模型只接收结构化结论、退出码
   与证据位置。

## 执行流程

**分步入口**：各步骤可独立执行——用户只要求某一步（如「只生成提示词」「只跑登记表」）时，直接从该步骤开始；前置产物缺失时按「断点定位」表提示先跑前置步骤并等待用户确认，不自动补齐前置步骤。

### 步骤 0：开始界面（阻塞式，强制确认）

每次进入任何生成步骤前，先展示以下 Markdown 开始界面。首次完整确认；断点续跑/追更时读取 `<资产库>/.start-state.json` 做快速确认；单步入口也必须先确认。不确认不写盘。

```markdown
## 🚀 资产提取 v2.13.1 开始界面

**输入源**
- 路径：<输入源路径>
- 存在：✅ / ❌

**画风确认**
- 题材：<题材>
- 默认画风：<画风卡 ID 名称>
- 状态：✅ 已确认 / 待确认

**需要强调的部分**
- <强调清单内容；无则显示“无额外强调（技能将根据剧本自动推测）”>

**输出位置**
- 资产库总目录：<ASSET_LIB_DIR>
- 最终产物：<ASSET_LIB_DIR>\描述、提示词\基础、提示词\衍生、服饰设计、连续性
- 缓存位置：<ASSET_LIB_DIR>\.process、各输出目录下 .<文件名>缓存
- 可写：✅ / ❌

**库内状态面板（ADR-0079/ADR-0084，按实际证据与状态机判定，不编造）**
- 流水线状态：<SOURCE_READY 至 DELIVERED，可用 `python scripts\maintenance.py status --lib <资产库> --json` 获取>
- 配置检查：.env ✅ 已加载 / ❌ 缺失（生成类步骤将被阻塞，先补配置）
- 断点定位：<按状态机判定的当前阶段与下一步；空库返回 WAITING_INPUT>
- 已有产物：<段文件数 / 登记表有无 / 资产索引与母版有无 / 描述·基础·衍生各节计数 / 交付清单状态>

**确认**
- [ ] 输入无误，开始执行
```

**强制校验项**：
1. 输入源存在；
2. 资产库目录可写；
3. 输出位置可写；
4. 缓存位置可写（目录不存在则尝试创建，已存在则检查 `os.access(path, os.W_OK)`，不创建临时文件）；
5. 画风已确认（沿用 `.start-state.json` 或本次重新确认）；
6. 强调清单非空，或用户明示“无特殊强调”；
7. `.env` 状态已展示（缺失时生成类步骤阻塞并提示配置位置，仅查看/备份类操作可继续）。

**强调清单**：自动读取 `<资产库>/强调清单.md`，仅使用 `## 必须强化` 与 `## 必须避免` 两个分区，每行 `- `；缺失视为无额外强调。强调清单只影响 描述/基础/衍生/服饰设计，不影响 提取/聚合/登记表。

**参数持久化**：确认后写入 `<资产库>/.start-state.json`，字段包括 `input_source` / `genre` / `style` / `emphasis_hash` / `output_root` / `last_confirmed_at`；强调清单内容变化时 `emphasis_hash` 变化，需重新确认。

**手动/非交互初始化（E2）**：无自动技能触发或手动执行时，用同一入口原子写入该文件（字段口径与开始界面一致，写出的证据可直接通过步骤 7 的签发门）：

```powershell
python scripts\maintenance.py init --lib <资产库> --input-source <原始txt/md> --genre <题材> --style <画风>
```

`--style` 用画风库编号或卡名（`A2` 与「仙侠奇幻风」等价）；未命中卡片会被**显眼提示**并降级为自由描述模式，不静默丢画风锁。原始输入必须是**真实存在**的文件并**留在原位**（步骤 7 的 `verify` 会重新核验源）；已存在且参数不同的状态文件需 `--force` 才覆盖。

**完成标准**：四项输入全部展示并确认；强制校验项全部通过；状态文件已写入或确认沿用。

### 步骤 1：摸底与拆段

```powershell
python scripts\split_segments.py "<源文件1>" ["<源文件2>"...] --novel 小说名 --author 作者 --lib <资产库> [--overlap 1] [--order-file <顺序清单>]
```

有章节 5 章/段、无章节 1 万字/段（段落边界切分），自动识别章节标题（含千/万级章号，如「第一千二百三十章」）。行首数字列表（如 `1. 他说……`）不会被当作章节；只有编号后仍带明确的章/回/卷/节或英文章节标记时才识别。**剧本场次「第N场」同样识别**（要求场后跟空白/标点/行尾：`第一场 茶楼` 是场次标题，`第一场雪落了下来` 是散文，不会被误判）。**推荐 `--overlap 1`**（ADR-0003：相邻段重叠 1 章，消灭段边界割裂；token 约 +20%，耗时不变；frontmatter 章节范围标注实际内容范围）。

**输入格式（v2.15.0，ADR-0085）**：正式支持 `.txt`、`.md`、`.docx`、`.epub` 与多文件项目。

- **单文件 TXT/Markdown**：走既有直读路径，行为与旧版完全一致，不产生中间产物。
- **DOCX / EPUB / 多文件 / 带 `--order-file`**：先经输入规范化层转成带来源定位的 UTF-8 Markdown，写入 `<资产库>\.process\normalized_sources\`（`规范化原文.md` + `来源清单.json`，原文件只读），再以规范化产物作为真实拆段输入；段 frontmatter 额外记录 `原始来源定位`（如 `卷1.txt: 文件1/段落3~文件1/段落9`）与 `来源清单`。
- **PDF 明确拒绝**：读取内容之前报 `UNSUPPORTED_SOURCE_FORMAT` 并提示先转 TXT/Markdown/DOCX/EPUB。**本技能不支持 PDF，也不建设文字识别。**
- 编码只做显式探测（UTF-8 BOM / UTF-8 / GB18030），无法解码报 `SOURCE_DECODE_FAILED`，**不会用忽略式解码吞掉乱码字**。
- 重复执行 `normalize_sources.py` 结果逐字节一致；**不要手工编辑规范化产物**。

```powershell
# 多文件项目：显式顺序清单（每行一个相对路径，相对清单所在目录）
python scripts\split_segments.py "卷1.txt" "卷2.txt" --novel 小说名 --author 作者 --lib <资产库> --order-file "顺序清单.txt"
# 只做规范化（不拆段），用于核对来源定位
python scripts\normalize_sources.py "剧本.docx" "小说.epub" --lib <资产库>
```

支持**多文件/分卷**（按顺序拆段，段号跨文件连续；注意：各文件章节号应连续，分卷重编号的文件需先合并）。段文件 → `<资产库>\原文段\<小说名>-<作者>\`。幂等 = **内容比对**：同名段内容一致跳过；同名但内容不同（源文件已变更/分卷重名）报冲突退出，确认后 `--force` 覆盖。

**完成标准**：分段方案已向用户汇报（汇报内容 = 段数 + 各段章节范围 + 预计耗时，跑完回读段文件列表获取，不得在跑前编造）；段文件全部生成或全部已存在且无冲突。方案不合意（如想改 3 章/段）→ 调整 `--chapters-per-seg` 后 `--force` 重跑。

### 步骤 1.5：全局登记表（ADR-0003，防命名漂移/跨段漏提/重复提取）

```powershell
python scripts\scan_registry.py "<资产库>\原文段\<小说名>-<作者>" --lib <资产库>
```

两遍直调：**候选遍**（每段并行，只输出候选主名表：主名/别名/首现章/一句定性/类别）→ **分层聚合**（两两并行合并，轮数 ≈ log₂(段数)，模型裁决同实异名/主名取舍/别名并入）。产出 **`<资产库>\<小说名>-<作者>-登记表.md`** —— 后续段级提取的全局锚点。

**完成标准**：登记表已产出；如无锚点（直接跑提取）则跳过本步骤，但会失去全局一致性保障。

### 步骤 2：段级提取（直调引擎）

```powershell
python scripts\extract_segments.py "<资产库>\原文段\<小说名>-<作者>" --lib <资产库>
```

每段一次直调（`templates/段级提取模板.md` 单源真相），N 段并行。**登记表锚点注入**：登记表已有资产必须用登记表主名（防命名漂移）；疑似新资产标 `[新增]` 必须附摘句+行号（严格申报）。产物 = 三张表：章节摘要表 + 资产出现记录表 + 变化需求记录表（**出处强制**：每记录带原文摘句+行号；**主名规则（分层）**：资产名=段内原文首次称呼）。断点续跑：重跑同一命令自动跳过已完成段。

**主名规则（分层）**：段级提取的资产名 = 段内**原文首次称呼**（逐字取自原文，不规范化）；全局主名由聚合裁决按**全库频次最高**的原文称呼裁定（步骤 3）。段级规则与全局规则的分工：段级保局部忠实，聚合保全局一致。

**完成标准**：全部段产物生成；失败段已在断点库记录且重试后仍失败数 ≤ 可接受值。

> 失败保护：连续失败 ≥3 次的段自动跳过（避免重复烧钱），`--force-retry` 强制重试；登记表候选遍同理（独立断点表 registry_tasks，与提取互不干扰）。

### 步骤 3：聚合裁决

```powershell
python scripts\aggregate.py "<资产库>\段产物\<小说名>-<作者>" "<资产库>\原文段\<小说名>-<作者>" --lib <资产库>
```

脚本：出处校验（摘句去标点匹配原文，失败进附录候选）→ 词面预聚合 + 主名规则（违规名剔除，候选主名=频次最高的原文称呼）→ 摘句重叠检测（同实异名提示合并）→ 交叉校验（防漏提）→ 需求出处校验（变化需求的摘句同样验证，失败丢弃）→ **登记表对账**（ADR-0003 决策4 四项：段记录↔登记表漂移预警、候选遍登记↔提取遍幻觉降级、`[新增]`申报出处验证、分集引用建档交 check_schedule；报告 → `.process\登记表对账报告.md`，只报不补）。LLM **分块裁决**（ADR-0002：人物/场景/道具/服装/基础信息 5 块并行，`templates/聚合裁决模板.md`，产物归档 `<资产库>\.process\裁决\裁决_<块>.md` 幂等断点，失败只重跑单块）：语义合并/主名/等级/漏提补建。**分块约定**：仅「基础信息」块输出项目基础信息表，人物/场景/道具/服装块只输出资产裁决+待确认（防 5 块重复输出同一基础信息）。输出 `反推_最终.md`（12 模块：8 核心模块 + 衍生需求汇总 + 合并统计 + 待确认附录 + **九、交付物说明**——区分「✅ 可直接使用」的提示词/服饰设计与「🔧 过程文件」的登记表/裁决，用户不迷失在中间产物里）。

**自动裁决与静默执行（v2.7.4，ADR-0016/0017）**：`aggregate.py` 默认精简输出，自动完成 5 块裁决、结构校验、对账与反推文件重建。编排器**不得**向用户罗列 `.process\裁决\裁决_<块>.md`、裁决输入、预聚合分组或对账明细（调试时用 `--verbose`）；这些过程文件自动归档到 `.process\`，用户日常完全看不到。编排器只静默核验三点：脚本退出码为 0；无反推文件重建失败；无「裁决解析丢弃」阻断。核验通过即直接进入下一步，不打扰用户。**只有出现以下情况才向用户汇报一行摘要**：①脚本返回非 0（贴出错误行）；②`待确认附录`非空（列出 名称/类型/原因，每条一行）；③对账报告有需要用户决策的漂移/幻觉项（只报数量，明细指向报告文件）。`反推_最终.md` 与 `.process\登记表对账报告.md` 落盘后均不逐条复述。

**完成标准**：`反推_最终.md` 已产出且自动核验通过；待确认附录项已在完成报告里按「名称/类型/原因」一行一条呈现（不再展示裁决过程文件）。

**步骤 3.5：对账闭环（[新增] 申报并入登记表）**

```powershell
python scripts\scan_registry.py --include-claims "<资产库>\.process\登记表对账报告.md" --lib <资产库>
```

把对账报告中「出处校验通过」的 `[新增]` 申报并入登记表（严格申报的落地，ADR-0003 闭环）；登记表已有同名自动跳过；出处未通过的申报留在待确认附录由人工复核。

**完成标准**：对账报告的通过申报已全部并入登记表（或报告无通过项）；未通过项已列入待确认附录待人工复核。

### 步骤 3.6：服饰设计（自动衔接，ADR-0006）

聚合产出反推文件后**自动衔接**「服饰设计」模块（`服饰设计/`，短剧服装设计——独立完整技能，本步骤只做数据衔接与驱动，**不改其内容**）：

```powershell
python scripts\prepare_costume_input.py "<资产库>\反推_最终.md" --genre <题材> --lib <资产库>
```

1. 桥接脚本：解析反推文件人物/服装妆造表 → 按 `references/题材-剧种映射.md` 判定主剧种（命中/近似标注；混合题材自动输出主副剧种，规则=白名单交集/黑名单并集/配色以主剧种为基准；**仅完全未命中才询问用户**）→ 生成 `<资产库>\服饰设计\<剧名>\角色清单.md`
2. 编排器按 `服饰设计/SKILL.md` 执行：标准先行（建/加载服饰标准库）→ 逐角色生成（定内核→落视觉→条目）→ 校验 → 落盘
3. 校验：`python 服饰设计\scripts\check_costumes.py <服饰标准库> <角色服饰标准表>`——阻断项清零才交付（服饰设计 ADR-0003 分级）
4. 落盘：`<资产库>\服饰设计\<剧名>\`（服饰标准库/角色服饰标准表/校验报告）——**覆写子模块默认的「当前工作目录\输出\<剧名>\」**（遵循 v2 数据外置原则：用户数据不进技能包）
5. **双约束注入**：角色条目同时注入 v2 画风锁定块（题材-画风映射）与剧种服饰约束（白/黑名单）——画风管「画面怎么渲染」、剧种管「角色穿什么」，两条独立链路互不覆盖

**完成标准**：角色清单生成；服饰标准库/角色条目/校验报告落盘；阻断项清零（或用户明确接受未修复阻断并显著标注）。

**独立触发**：用户单独说「设计服装」「服饰标准」「给角色穿搭」时，不重跑流水线，直接以现有反推文件（或用户提供角色清单）为输入执行本流程。

### 步骤 4：描述补全（每资产一次，推荐）

```powershell
python scripts\generate_prompts.py --enrich "<资产库>\反推_最终.md" --genre <题材> --lib <资产库> [--style <画风>]
```

每资产一次直调（`templates/描述补全模板.md`），产出 7 维度视觉描述；**人物/场景/道具各合并为一个文档**：`<资产库>\描述\人物描述.md`、`场景描述.md`、`道具描述.md`（ADR-0018），按 `## 001.` 序号分节。**画风倾向克制注入**（只影响色彩/氛围/材质倾向，遵循底层真实感）。

> **服装例外**：描述补全与基础提示词只处理 人物/场景/道具 三类（`generate_prompts.py` 按此三类解析资产表）；服装资产本身不走本步骤——但**服装必须与人物绑定**：步骤 5 生成人物基础提示词时，自动读取反推文件服装妆造表，把该人物绑定造型（如「囚衣」「灰蓝布衣」）注入「绑定服装」字段，作为人物基础提示词的打底服装（模板强制：有绑定服装以服装为准，杜绝模板默认基础服顶替）。衍生提示词（步骤 6）继续提供服装×造型变体。

**完成标准**：全部资产描述文件生成（或文件已存在跳过，`--force` 覆盖）；以 stdout 汇总行（「✅ 描述补全: 生成 N, 跳过 N, 失败 N」）核对失败数 = 0，有失败 → 重跑续传（断点跳过已完成项）。

### 步骤 5：基础提示词（每资产一次）

```powershell
python scripts\generate_prompts.py --base "<资产库>\反推_最终.md" --genre <题材> --lib <资产库> [--style <画风>] [--view-mode full]
```

每资产一次直调（基础提示词模板-人物/场景/道具）；**人物/场景/道具基础提示词各合并为一个文档**：`<资产库>\提示词\基础\人物提示词.md`、`场景提示词.md`、`道具提示词.md`（ADR-0015/0018）——每个资产一节 `## 001. 资产名`，序号与反推文件对应资产表顺序一致；旧 `人物_xxx.md` / `场景_xxx.md` / `道具_xxx.md` 单文件首次运行自动迁移并入合并文档并删除。描述已生成时自动注入，未生成时按名称/等级/题材推断。**服装-人物绑定**：人物基础提示词自动注入反推文件服装妆造表的绑定造型（「绑定服装」字段，模板强制以其为打底服装）——人物基础提示词 = 人物信息 + 正式服装，一块资产直接可用。**人物三格图板（ADR-0070，方案C）**：人物基础提示词固定为一张三格图板——左面一格=人物正面特写（头顶到锁骨，全脸清晰），右面上下两格=正视图（全身）+后视图（全身），两格等大、身高比例一致；`--view-mode full`（默认）=右面两格保留头部（不裁头），输出 `人物提示词.md`；`--view-mode crop`=右面两格头部与面部一律裁除不入画、脸的唯一真相是左面正面特写，输出独立文件 `人物提示词_裁头版.md`（**只在步骤 8 结算询问且用户确认后才生成**）。**画风注入**（ADR-0004 注入点决策）：人物全量注入画风锁定块（三格图板构图不变）、道具只注入渲染层（保持素灰/均匀柔光定妆规范，视图规划按剧本动态决定）、场景主视图全量注入（色调/氛围/镜头/渲染）。**纯中文**：所有基础提示词全程纯中文（色值代码除外）。生成前回显画风确认。

**完成标准**：`人物提示词.md` / `场景提示词.md` / `道具提示词.md` 各含全部资产节（`人物提示词_裁头版.md` 仅在步骤 8 结算确认后生成，同样按此核验）；以 stdout 汇总行核对失败数 = 0（同步骤 4）。

> 画风确认与自动化：步骤 0 已确认过画风时,`generate_prompts.py` 每次运行仍会再次回显确认（用户要求"使用什么画风必须向用户确认"）。**自动化/管道场景必须显式传 `--style` + `--genre` + `--yes`**；脚本强制校验——只传 `--yes` 不传 `--style` 或不传 `--genre` 会直接报错退出，不允许静默默认画风或题材。

### 步骤 6：衍生提示词（按调度清单，每变体一次）

```powershell
python scripts\generate_prompts.py --init-schedule "<资产库>\反推_最终.md" --genre <题材> --lib <资产库>
# 已存在清单时默认保留手工编辑；追更可用 --append 只追加默认新行，--force 全量重建
# （可选）编辑 <资产库>\提示词\调度清单.md：补场景时段/天候/角度变体、道具特殊状态、行级「画风」列
python scripts\generate_prompts.py --deriv --genre <题材> --lib <资产库> [--style <画风>] [--view-mode full]
```

默认清单 = 服装表（绑定人物×造型）+ **剧本驱动需求**（场景时段/天候/道具状态——来自反推文件的"衍生需求汇总"，每项需求都有原文摘句出处，剧本没说就不生成）。**场景角度/景别变体不自动进默认清单**（ADR-0057）：剧本明确出现「俯视全城」「仰视高塔」等分镜需求时，才作为角度/景别变体进清单（有出处）；其余手工加行，无原由补「（推断原由）」。**只生成需要的，不生成还没出现过的**：只生成清单里出现的变体，禁止自动扩展 人物×全部服装 全组合矩阵，禁止生成剧本尚未出现过的造型/状态。清单可手工增删（手工增行不强制写原由；生成时无原由的变体按题材物理逻辑补中性原由并标注「（推断原由）」，不得冒充剧本事实），**第 5 列「画风」可行级覆盖全局画风**（ADR-0004 决策 3）。**人物/场景/道具衍生提示词各合并为一个文档**：`<资产库>\提示词\衍生\人物提示词.md`、`场景提示词.md`、`道具提示词.md`（ADR-0015/0018），每变体一节 `## 001. 资产名（变体）`，序号与调度清单对应类型行顺序一致。**人物衍生与基础同版三格图板（ADR-0070）**：`--view-mode full` 写 `人物提示词.md`、`--view-mode crop` 写 `人物提示词_裁头版.md`；**人物/场景/道具衍生均自动注入对应基础提示词全文**——人物优先同版本基础文档对应节读取、裁头版基础缺失时回退 full 基础（身份锁同源）；场景/道具从同类型基础合并文档对应节读取；**任何类型基础缺失时该变体直接失败、不生成**（人物必须有「身份锁」原文、场景必须有「环境基线」原文、道具必须有「材质身份」原文）。模板强制：基础状态引用唯一依据是注入的基础提示词，未提供时禁止编造"原本的X"式对比——杜绝衍生提示词虚构基础状态。场景变体切换遵循**光影与色彩基线规则**（变化必须写明起因+方向+完成状态）。**纯中文**：所有衍生提示词全程纯中文（色值代码除外）。

**完成标准**：调度清单已生成并（如需）经用户编辑；三个衍生合并文档各含全部清单变体节；以 stdout 汇总行核对失败数 = 0（同步骤 4）。

### 步骤 7：完整性检查（只报不补）

```powershell
python scripts\check_schedule.py "<资产库>\反推_最终.md" --lib <资产库> [--style <画风>]
```

检查五项：分集表引用是否建档（附录资产会提示"见待确认附录"）、每资产是否有基础提示词（按类型查 人物/场景/道具 三个合并文档各节）、每清单变体是否有衍生提示词（按类型查三个衍生合并文档）、**提示词内容合规**（按类型查必守关键词——人物三格图板（正面特写+正视图+后视图）/素灰纯色背景/无文字/镜头体系（景别+角度+布光）/无人/单画面/道具三视图（正面图+侧面图+背面图），缺失即报"不合规·需重新生成"，防生成器偷懒输出敷衍文本）；`人物提示词_裁头版.md` 存在时同样逐节检查，且调度清单的人物变体必须同时有裁头版衍生，缺失与内容不合规一样报出。**纯中文合规**（连续 2 个以上英文字母即报"不合规·需重新生成"，色值代码除外；基础/衍生提示词与描述文档均逐节机械校验）。传 `--style`（与生成时一致）额外检查**画风锁定保留**：人物/场景按「建模层/渲染层/场景背景/镜头」四层逐层必查（缺一层即报「缺画风锁定段-层名」），道具只必查建模层/渲染层；纯幻想题材（题材仅由 玄幻/仙侠/神魔/修真/奇幻 组成，如「玄幻/仙侠」「仙侠奇幻」；「都市玄幻」等混合题材不算）的人物/场景另必查内容语言段（ADR-0046/0069），并检查基础/衍生全部合并文档保留画风必守词（缺失报「缺画风关键词·需重新生成」）；传 `--style-lib` 附带画风库健康自检（发现问题计入报告）。**只报缺失不代生成**——缺失项补跑（`--force` 覆盖不合规文件）或人工处理。

**防偷懒绕过（ADR-0080）**：未传 `--style` 时自动沿用 `<资产库>\.start-state.json` 的画风（stderr 提示「已沿用」）；两者皆无时显眼警告「画风锁定/关键词/负面项检查已跳过」——不允许静默降级。检查还包含 **AI 味拦截**（禁用起手式/翻案腔句式→「AI味措辞」；非负面行顿号≥10→「顿号罗列过密」）与**负面段画风项**（画风卡/风格包负面并集前 3 项任一必须出现在节内）。

**完成标准**：检查报告产出，全部缺失项已列出并决定处理方式。推荐用 `python scripts\maintenance.py verify --lib <资产库> [--style <画风>]` 一键收口（自动跑 check_schedule/check_final/check_asset_index/check_costumes 并输出状态判定）。

**签发门（E1，v2.14.0）**：`verify` 签发前先核验启动证据，任一项不成立即**非零退出且拒绝生成交付清单**，原因码写入 `.process\验证报告.md`（不覆盖历史有效清单）：

- `.start-state.json` 缺失/不可解析，或其中 `input_source` 指向的文件不存在 → `SOURCE_UNVERIFIABLE`；
- 状态文件未记录画风 → `STYLE_UNVERIFIABLE`；
- 显式 `--style` 与启动状态画风不是同一张画风卡 → `STYLE_MISMATCH`（`A2` 与「仙侠奇幻风」经 `scripts/engine/style.py` 判为等价别名，不算冲突）。

修复方式：确认原始输入仍在原位后重跑 `python scripts\maintenance.py init --lib <资产库> --input-source <原始文件> --genre <题材> --style <画风>`，再重跑 `verify`。**原始输入不可留在临时位置后删除**——源消失即视为交付不可核验。

### 步骤 8：完成报告（交付契约，ADR-0079 证据收口）

汇总（**数字一律取自上一步脚本 stdout 汇总行，禁止编造**：拆段 N 段取步骤 1 输出、提取取「📊 生成 N, 跳过 N, 失败 N」行、生成取「✅ 描述补全/基础提示词/衍生提示词: 生成 N, 跳过 N, 失败 N」行、正式资产 X + 附录 Y 取反推文件计数），并按以下**交付契约**结构输出（借鉴小说索引的证据收口协议）：

```markdown
## 📦 交付契约
- 状态：DONE（以 `maintenance.py status --json` 的 DELIVERED 与有效 `交付清单.json` 为准）/ BLOCKED（存在阻断项，如检查未通过且无法自动补齐）/ NEEDS_REVIEW（存在待确认附录或人工决策项）
- 范围：本次处理的输入源与章节范围
- 读取与生成：各产物路径清单 + 各步骤「生成 N, 跳过 N, 失败 N」汇总行
- 验证：check_schedule / check_final / check_asset_index / check_costumes 的返回码与缺失计数（原样引用，不修饰）
- 失败项：逐条列出（无则写「无」）
- 下一步（供用户选择 2-3 项）：
  - 生成裁头版人物提示词（结算询问，见下）
  - 某类产物审美/画风不满意 → 指定画风卡或行级覆盖后 --force 重生成对应类型
  - 备份本次资产库（`python scripts\maintenance.py backup --lib <资产库>`）
  - 交给生图模型 / 进入服饰设计微调
```

**结算询问（必须，ADR-0070 方案C）**：完成报告末尾必须询问用户——「是否同时需要裁头版人物提示词？（裁头版=右面两格全身头部与面部一律裁除不入画，脸的唯一真相是左面正面特写；默认不裁头版已生成）」默认不生成；仅当用户明确确认需要时，才补执行（**若尚未生成 full 版，crop 命令会硬阻断报错，必须先补 full**）：

```powershell
python scripts\generate_prompts.py --base "<资产库>\反推_最终.md" --genre <题材> --lib <资产库> [--style <画风>] --view-mode crop
python scripts\generate_prompts.py --deriv --genre <题材> --lib <资产库> [--style <画风>] --view-mode crop
python scripts\check_schedule.py "<资产库>\反推_最终.md" --lib <资产库> [--style <画风>]
```

补生成后向用户回执：新增 `提示词\基础\人物提示词_裁头版.md`；调度清单有人物变体时同步新增 `提示词\衍生\人物提示词_裁头版.md`，并复跑步骤 7 通过后才算完成；用户说不需要则保持只交付不裁头版。

**附录处置闭环**：补录 → 走步骤 3.5 申报通道（出处验证通过并入登记表），或人工编辑登记表/反推后重跑受影响步骤；删除 → 从反推文件移除该条后重跑受影响生成步骤（或仅保留在登记表不参与生成）。两种处置都必须向用户回执确认。

**完成标准**：交付契约六栏全部有实际内容（失败项可写「无」）；状态判定与验证证据一致（DONE 只能伴随检查通过）；附录项向用户完整呈现并给出处置回执；下一步选项已给出；裁头版结算询问已执行并按用户答复处理（不需要 → 保持只交付不裁头版；需要 → 补生成裁头版并复跑步骤 7 通过）。

277	> 产物存在 ≠ 步骤完成：存在但为空/损坏/抽查不过 → 状态机自动回退；每步完成后按「完成标准」核对，不得仅凭文件存在性放行。

## 追更（连载新增章节）

机制已内置（段文件 hash 检测），**按序重跑步骤 1-7 即可**，断点自动跳过已完成部分。各步骤注意点：

1. `split_segments.py`：**推荐 `--append` 增量模式**（新增章节：不足 5 章并入末段，否则新建段，编号=现有最大+1；段文件名保持原样防断点失效重跑全书）；不用 `--append` 时按全量重跑——源文件已变更的段报内容冲突，确认后 `--force`
2. `scan_registry.py`：重跑登记表（候选表/合并产物按输入内容哈希跳过，只有新增段/内容变更的段重跑，合并层只重跑输入对发生变化的合并；`--force` 全量重跑——对账 [新增] 申报并入的资产在全量重建时由候选遍自动重新登记）
3. `extract_segments.py`：只跑新段（断点跳过已完成段；登记表锚点随新表自动注入）
4. `aggregate.py`：重跑聚合（裁决块产物幂等——已完成的裁决块跳过，只补新裁决；反推文件整体重建；登记表对账重出）
5. `generate_prompts.py`：断点跳过已生成资产/变体，只生成新增（画风确认每次运行时进行）
6. `check_schedule.py`：完整核验（含画风锁定保留检查）
