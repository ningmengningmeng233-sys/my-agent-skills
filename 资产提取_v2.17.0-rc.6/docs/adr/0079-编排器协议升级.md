# ADR-0079: 编排器协议升级——状态面板、交付契约、运维脚本与渐进披露

- 状态: Accepted
- 日期: 2026-09-06

## 背景

对齐 CherryStudio 技能库（小说索引/creative-workflow/skill-creator）中的成熟方法，补资产提取流水线的编排层缺口：

1. **SKILL.md 历史噪声**：62 行旧版本日志每次触发都进上下文（skill-creator：SKILL.md 应精简、渐进披露）。
2. **开始界面不看库内现状**：断点续跑时用户看不到已完成到哪一步、有多少产物；`.env` 缺失也不展示（小说索引 0.1/0.2 欢迎菜单+启动检查）。
3. **完成报告无状态纪律**：没有 DONE/BLOCKED/NEEDS_REVIEW 判定、失败项收口与结构化证据（小说索引 §4 交付契约）。
4. **完成即终点**：不主动给下一步选项（creative-workflow 衔接模式）。
5. **缺运维能力**：资产库无 status/backup/restore（小说索引分支 6）。
6. **缺用户侧文档**：无 QUICKSTART/FAQ。
7. **description 触发场景不全**：审美优化/断点续跑/备份等语境缺失（skill-creator：description 是触发主机制）。

## 决策

1. **渐进披露**：v2.10.1 及更早的更新日志外移 `docs/CHANGELOG.md`；SKILL.md 仅保留 v2.11.x 三条 + 指针（297 行）。
2. **开始界面加「库内状态面板」**：配置检查（.env 状态展示，缺失时阻塞生成类步骤）+ 断点定位（按断点定位表判定）+ 已有产物统计（可用 `scripts/maintenance.py status` 获取）；新增强制校验项 7。
3. **步骤 8 改为交付契约**：状态（DONE/BLOCKED/NEEDS_REVIEW）/范围/读取与生成/验证/失败项/下一步六栏，全部证据收口（数字取自脚本 stdout 汇总行的既有规则不变）；下一步给用户 2-3 个可执行选项（裁头版/画风调整重生成/备份/交生图）。
4. **运维脚本 `scripts/maintenance.py`**：status（断点定位+产物统计）/ backup（时间戳 zip，排除 __pycache__）/ restore（zip-slip 防护 + 非空目标须 --force）。
5. **新建 `QUICKSTART.md`**（四步上手+位置速查+画风选择+维护三命令）与 **`FAQ.md`**（12 类常见报错与处理）。
6. **description 补触发场景**：画风不对/审美不好/定性不行要求优化、断点续跑/继续上次提取、追更资产、资产库备份/恢复/状态、不合规与雷同的修复重生成。

## 被放弃的备选

- **语义检索增强登记表**（小说索引 ADR-0004）：当前登记表规模下精确匹配+别名已足够，语义检索为可选重依赖，留作后续可选能力（`INDEX_ENABLE_SEMANTIC` 式开关）。
- **子代理编排模式**（rosalia-orchestrator）：直调引擎已是既定架构（ADR-0001），不改。

## 影响

- `SKILL.md`（description/步骤 0/步骤 8/资源指针/日志外移）
- `docs/CHANGELOG.md`（新增）、`QUICKSTART.md`（新增）、`FAQ.md`（新增）
- `scripts/maintenance.py`（新增）、`测试/unit/test_maintenance.py`（新增）
- 版本 v2.11.3
