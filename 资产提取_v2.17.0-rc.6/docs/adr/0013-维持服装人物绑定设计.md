# ADR-0013: 维持服装人物绑定设计

- 状态: Accepted
- 日期: 2026-08-18

## 背景

资产登记表中存在「服装」类别，其归属关系在模板与脚本层面存在两种设计可能：

1. **绑定到人物**：服装作为人物资产的一个字段（或一个专属子表），不独立出现在提示词入口；人物定妆/变体提示词生成时，自动将绑定服装合并到描述中。
2. **独立为资产入口**：服装与人物、场景、道具并列，生成独立的「服装提示词」，再由脚本或模板关联到对应人物。

审查中曾讨论是否应为服装创建独立提示词入口，以简化单个服装的复用与管理。

## 决策

**维持现有绑定设计：服装不独立作为提示词生成入口，而是绑定到人物资产。**

1. `templates/基础提示词模板-人物.md` 继续通过占位符（如 `{{服装}}`）接收服装描述。
2. `scripts/generate_prompts.py` 继续将人物与服装资产按名称/上下文绑定，合并后生成人物提示词。
3. 不新增「基础提示词模板-服装.md」或「衍生提示词模板-服装.md」。
4. 服装的出处、命名、修改仍需在资产登记表中独立记录，仅在提示词生成阶段合并到人物。

## 权衡

| 备选 | 优点 | 缺点 |
|---|---|---|
| A. 服装独立入口 | 复用清晰，单件服装可单独生成变体/衍生 | 增加提示词模板与生成脚本复杂度；同一人多服装时易出现绑定混乱；需要用户额外决定何时生成服装而非人物 |
| B. 服装绑定人物（选定） | 符合当前工作流，人物出场即带服装；模板与脚本改动最小；避免同人物多服装版本冲突 | 无法单独对一件服装做衍生；换装需生成新人物变体 |

选择 B 是因为当前用户工作流以「人物」为核心输出单位，服装作为人物的外观属性更符合实际使用习惯。独立入口带来的复用收益不足以抵消新增的维护与绑定复杂度。

## 影响

- `templates/` 与 `scripts/generate_prompts.py` 的服装相关逻辑不做结构性改动。
- 未来若出现大量「同人物多服装需要独立管理」的场景，再考虑在登记表中增加「服装别名」或「可独立生成」标志，但不改变默认绑定行为。
