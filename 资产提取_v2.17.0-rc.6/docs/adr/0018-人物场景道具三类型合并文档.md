# ADR-0018: 人物/场景/道具三类型各一个合并文档

- 状态: Accepted
- 日期: 2026-08-19

## 背景

v2.6.1 已把人物提示词合并为单一文档，但场景/道具仍每资产一个文件，描述层同样碎片化。用户反馈「角色、道具、场景信息分为三个文件，不要一堆文件放在一块」。

## 决策

**描述、基础提示词、衍生提示词三个层级，每层只保留 人物/场景/道具 三个合并文档。**

1. `描述/`：`人物描述.md`、`场景描述.md`、`道具描述.md`
2. `提示词/基础/`：`人物提示词.md`、`场景提示词.md`、`道具提示词.md`
3. `提示词/衍生/`：`人物提示词.md`、`场景提示词.md`、`道具提示词.md`
4. 每个文档按 `## 001.` 序号分节：基础/描述节标题 = 资产名（序号与反推文件对应资产表一致）；衍生节标题 = 资产名（变体）（序号与调度清单对应类型行一致）。
5. 断点续跑统一为「节级跳过 + 隐藏缓存目录恢复 + 旧单文件自动迁移」：旧 `人物_xxx.md` / `场景_xxx.md` / `道具_xxx.md` 首次运行并入合并文档后删除。
6. `check_schedule.py` 按类型逐节检查覆盖、合规、纯中文与画风；旧单文件保留兼容读取（存量资产库升级期不误报）。

## 权衡

| 备选 | 优点 | 缺点 |
|---|---|---|
| A. 每资产一文件 | 单文件易单独分发 | 文件碎片多，目录爆炸 |
| B. 三类型三文件（选定） | 一目了然、按类型连续阅读 | 单资产导出需从文档中摘节 |

## 影响

- `scripts/generate_prompts.py`、`scripts/check_schedule.py`、e2e 快照、`SKILL.md` 数据布局同步修改。
