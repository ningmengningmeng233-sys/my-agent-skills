# ADR-0017: 裁决中间文件归档到 .process（根目录只留交付物）

- 状态: Accepted
- 日期: 2026-08-19

## 背景

聚合裁决阶段会在资产库根目录留下大量中间文件：`裁决输入_<块>.md`、`裁决_<块>.md(+.hash)`（5 块共 15 个文件）与 `登记表对账报告.md`。用户反馈「裁决后不要把一堆文件放在文件夹下」，根目录应只保留可交付与索引文件。

## 决策

**裁决中间文件全部归档到 `<资产库>/.process/` 隐藏目录；根目录只保留 登记表、反推_最终.md 与断点库。**

1. 裁决输入/裁决块(+hash) → `<资产库>/.process/裁决/`；登记表对账报告 → `<资产库>/.process/登记表对账报告.md`。
2. `.process/` 是断点续跑与追更幂等的依赖（裁决块 hash 断点），不可在交付时删除；但它是隐藏目录，日常浏览不出现。
3. 兼容迁移：重跑 aggregate 时自动把旧根目录的裁决文件迁入 `.process/裁决/`（hash 匹配则复用，不匹配则废弃重裁），并删除根目录旧文件。
4. `反推_最终.md` 及其 `.hash` 仍保留根目录（hash 是反推文件自身的写入跳过锚点，也可随 `.process` 迁移？否——反推文件是主交付物，hash 保留在原位置以便 `--out` 场景统一判断）。

## 权衡

| 备选 | 优点 | 缺点 |
|---|---|---|
| A. 裁决后直接删除中间文件 | 根目录最干净 | 追更/重跑无法跳过已裁决块，重复烧钱 |
| B. 归档 .process（选定） | 根目录干净且断点能力完整 | 目录内多一层隐藏结构 |

## 影响

- `scripts/aggregate.py` 路径逻辑、`SKILL.md` 数据布局与错误矩阵、e2e 快照同步修改。
