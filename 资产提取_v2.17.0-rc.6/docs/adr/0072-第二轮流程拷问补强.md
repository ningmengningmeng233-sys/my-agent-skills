# ADR-0072: 第二轮流程拷问补强（衍生基础注入、force/清单防覆盖、检查全覆盖）

- 状态: Accepted
- 日期: 2026-08-19

## 背景

对 v2.9.41 再做端到端拷问，发现六类仍会造成偷懒、幻觉或数据损失的路径：场景/道具衍生没有注入基础提示词原文；`--init-schedule` 无条件覆盖手工编辑；`--force` 失败后旧内容仍残留在合并文档中伪装成已覆盖；多生成动作混跑时静默忽略参数；无分层老画风的道具渲染块是空标题；画风关键词检查不覆盖基础合并文档。

## 决策

1. **衍生提示词全类型强制注入基础原文**：人物/场景/道具衍生均读取同类型基础合并文档对应节（人物裁头版缺基础回退 full）；任何类型基础缺失，该变体在脚本层直接失败、不调用模型，杜绝无「环境基线/材质身份/身份锁」的自由发挥。
2. **`--init-schedule` 不覆盖既有清单**：清单已存在时保留手工编辑并提示；仅 `--force` 重建默认清单。
3. **`--force` 真覆盖语义**：重生成前先移除本次任务已有旧节；失败任务留空并计入失败，旧内容不得伪装成「已覆盖」。
4. **单次运行只允许一个生成动作**：`--base/--deriv/--enrich/--init-schedule` 混跑直接报错退出；`--view-mode crop` 只允许配合 `--base/--deriv`。
5. **无分层老画风的渲染块回退中文定性**：A2 等无编号分层卡片的 `build_render_block` 不再返回空标题，而是注入中文定性第一段；道具模板不再拿空画风块。
6. **检查覆盖补齐**：画风关键词检查覆盖基础/衍生所有合并文档（含裁头版）；描述文档增加「负面限制 + 类型必查字段」（人物=面部骨相/肤色，场景=景别+角度+布光，道具=材质身份）；基础/衍生负面段增加类型负面锁必查；H7 中文定性彻底纯中文（高精度 3D → 高精度三维）。
7. **文档口径**：景别八级/角度七种同步到描述补全模板与 CONTEXT；stdout 汇总行引用与实际输出一致；反推文件统一为 12 模块。
