## 二、工单 1：验收器口径（判错就是假证据）

改前的问题：`--python-list` 指定的解释器里只要有**一个**跑完，整体就退 0 —— 三版本验收会拿「1 个 PASS + 2 个 SKIP」冒充「Linux 三版本通过」。改后：

| 情形 | 退出码 | 结果表 `status` |
|---|---|---|
| 所有请求的解释器三步全 rc=0 | **0** | 每步 `PASS` |
| 任一步 rc≠0 | **1** | 该步 `FAIL`（带 rc 与日志路径） |
| 无 FAIL 但存在不可用解释器（缺失/缺 `pytest`+`flake8`） | **3** | `ALL SKIP`（**不算通过**） |
| 参数/完整性错误（缺 `--expected-sha256`、哈希不匹配、证据目录冲突） | **2** | 不产生任何解压与证据 |

- `--expected-sha256` **必填**：不做完整性比对的验收无效。哈希不符时**在解压前**退出，不留下半截证据。
- 证据隔离：每次运行在 `--out` 下新建唯一 `run-<UTC时间戳>-<pid>[-n]/`；`--run-dir` 复用非空目录会**拒绝**，除非显式 `--reuse-run-dir`（旧 `results.tsv`/`environment.txt` 归档为 `*.prev-<戳>.*`，**归档不删除**，且本轮结果表只装本轮行）。
- 真实验证（rc.3 包）：缺哈希 → 2；单解释器全 PASS → 0；`python python3.10 python3.11` → **3** 且表里 1 组 PASS、2 行 SKIP；连续两次运行 → 两个独立 `run-*` 目录，各自结果表无对方行。
