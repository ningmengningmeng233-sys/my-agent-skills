## 一、样本与前置

| 项 | 值 |
|---|---|
| 夹具 | `测试/fixtures/live_smoke/短文本.md`（合成剧本，约 330 字含标点，可公开） |
| 夹具字节数 / 非空白字符数 | 992 字节 / 330 字（含标点） |
| 夹具 SHA-256 | `24faa5331ac585d582843d7480b8835809b0f4f385345751cdcdec7c1f0c5190` |
| 主画风样本 | `A2`（仙侠奇幻风）→ 资产库 A |
| 防串用样本 | `H12`（儿童绘本粉彩插画风）→ 资产库 B |
| 环境要求 | Python ≥ 3.10；`requests`、`python-dotenv`；OpenAI 兼容接口可用 |

**三条硬规（漏一条本次验收作废）**：

1. **每次都建全新库**：每轮抽样用一个**带时间戳的唯一运行目录**（下文的 `$RUN`），A2 与 H12 在其中各占一个子目录——目录全新即库全新；**不得**对 `$HOME/asset_accept` 这类固定路径做递归删除，那是可能装着别人数据的路径。不复用上一轮的库，也不在旧库上 `--force` 重跑后拿旧清单充当结果。
2. **两个库必须互相隔离**：库 A 只跑 A2，库 B 只跑 H12；不得共用库目录、不得只用 `--style` 切换后复用同一库。
3. **源文件必须留在原位**：`--input-source` 指向的原始文件是签发门（E1）的核验对象；库 A/B 各存一份夹具副本，验收期间不得移动或改写。

### 失败退出规则（两种宿主一致）

1. **任一步退出码非零即停止**：先看该步 stdout 末段与 `stderr`，修好后重跑**同一命令**（断点续传会自动跳过已完成部分），不要跳步继续。
2. `verify` 非零时读 `<资产库>/.process/验证报告.md`：
   - `SOURCE_UNVERIFIABLE` → 原始输入被移动/删除，或 `.start-state.json` 丢失 → 用 `maintenance.py init` 指回真实源；
   - `STYLE_UNVERIFIABLE` / `STYLE_MISMATCH` → 状态文件无画风或与 `--style` 不同卡 → 统一为同一张卡（`A2` ≡「仙侠奇幻风」）；
   - `check_schedule` / `check_final` / `check_asset_index` 未通过 → 按报告逐条补齐后重跑 `verify`。
3. **失败不覆盖历史有效清单**：`verify` 失败只写验证报告，不改 `交付清单.json`；修复后重跑即可重新签发。
4. **库 B 必须用另一个资产库**：拿库 A 的清单、或 `--force` 覆盖库 A 再取数，本次验收作废。
