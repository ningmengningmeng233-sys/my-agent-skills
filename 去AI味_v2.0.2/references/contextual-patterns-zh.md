# 聚集型中文模式库

本文件定义在中文文本中呈现**聚集型、套路化、姿态化**的模型腔模式。本文件不在普通调用中加载，仅在满足以下条件之一时按需读取：
1. 用户明确指出“说人话 / 别像模板 / 像机器人 / 清理套话”；
2. 初步扫描发现强模板聚集（段落或篇章级别套路堆叠）。

---

## 1. 三联触发门（核心原则）

本文件中的词语或模式均不得单凭字面或单次出现机械替换。只有**同时满足以下三个条件**时才允许改动：
1. **聚集或重复**：同类模式在同一上下文或相近段落中出现 2 次以上，或与另一类模式复合叠加；
2. **场景不需要**：当前体裁（技术文档、汇报、散文等）并不要求此种姿态或礼貌修辞；
3. **保真无损**：删除或简化后，不损失任何独有信息、语义关系、限定条件或结构职责。

> **只观察不自动改**：单个词汇、孤立标点、行业标准术语、正式法律或技术定义，在未形成聚集前只作观察，严禁“见词就杀”。

---

## 2. 聚集型模式八族

### 模式一：空泛开场 / 元评论
- **典型特征**：在切入正题前填充无实质信息的客套垫话、自白或元评论。
- **代表词（最多六项）**：`值得注意的是`、`不可否认的是`、`毋庸置疑`、`众所周知`、`接下来我将为你`、`让我们一起来看看`
- **处理动作**：直接删去开场垫话，从核心主谓宾或客观事实切入。
- **边界例**：
  - *改*：“值得注意的是，系统吞吐量在夜间下降了。” -> “系统吞吐量在夜间下降了。”
  - *保*：“法律条文第3条明确规定，在当事人无争议时适用简易程序。”（正式依据，保留）

### 模式二：假深刻 / 价值拔高
- **典型特征**：对常规技术操作或业务变动赋予夸大、崇高或具有历史意义的修饰，缺乏数据支撑。
- **代表词（最多六项）**：`范式转移`、`颠覆性变革`、`深远影响`、`不可磨灭`、`发人深省`、`前所未有`
- **处理动作**：删去主观拔高评价，还原为具体改动内容与可衡量影响；如无具体数据，仅陈述动作。
- **边界例**：
  - *改*：“本次重构迎来了前所未有的颠覆性范式转移。” -> “本次重构调整了底层存储架构。”
  - *保*：“该论文首次提出了Transformer架构，被学术界视为深度学习领域的重大范式转移。”（客观引用学术共识，保留）

### 模式三：商业黑话 / 工程师表演
- **典型特征**：将日常工作、管理或编程行为过度抽象化，或在日常沟通中堆砌 SRE/排障戏剧化词汇。
- **代表词（最多六项）**：`赋能`、`打通底层闭环`、`细化颗粒度`、`稳稳接住`、`打掉问题根因`、`砍一刀`
- **处理动作**：换为具体工作动作（如“支持”、“整理”、“解决异常”）；如属正式系统架构名称则保留。
- **边界例**：
  - *改*：“本模块深度赋能业务，拉齐各方颗粒度，打掉所有性能卡点。” -> “本模块为业务提供统一接口，并解决了已知延迟瓶颈。”
  - *保*：“电机控制系统采用闭环反馈机制维持转速恒定。”（控制工程严谨定义，必须保留）

### 模式四：过度接住 / 心理判断
- **典型特征**：AI 扮演过度共情、心理辅导或情绪抚慰角色，擅自替用户做心理预设和情绪判断。
- **代表词（最多六项）**：`我非常理解您的感受`、`请不要焦虑`、`这确实令人头疼`、`您一定很辛苦`、`别担心我一直在`、`抱抱您`
- **处理动作**：直接删除情绪迎合与心理定性，直奔问题解决方案或事实说明。
- **边界例**：
  - *改*：“我完全理解这让您感到无比抓狂和无助。别担心，我们一步步来，第一步……” -> “第一步……”
  - *保*：“心理咨询师在会谈中记录患者的情绪反应为中度焦虑。”（客观引述，保留）

### 模式五：假口语 / 语域混搭
- **典型特征**：在严肃的论证或技术文档中，突然插入自媒体短视频或带货腔调的轻佻口语，造成语域严重失调。
- **代表词（最多六项）**：`保姆级教程`、`直接封神`、`可以说是相当炸裂`、`闭眼入`、`家人们谁懂啊`、`盘它就对了`
- **处理动作**：按上下文正式语域拉齐，剔除夸张的自媒体营销用语。
- **边界例**：
  - *改*：“本指南堪称保姆级硬核干货，配置步骤直接封神。” -> “本指南详细说明了服务的安装与配置步骤。”
  - *保*：“该博主在视频标题中使用了‘家人们谁懂啊’作为吸睛文案。”（作为分析客体引用，保留）

### 模式六：无源权威
- **典型特征**：使用含糊不清的“专家”、“业界”、“大家都知道”来替代具体论据，假装客观严谨。
- **代表词（最多六项）**：`业内专家普遍认为`、`大数据表明`、`无数实践证明`、`公认的最佳实践`、`研究表明`、`毫无疑问的事实`
- **处理动作**：如原文未给出具体出处，降级为主张本身或指出证据缺失；禁止自动编造研究机构或作者。
- **边界例**：
  - *改*：“业内专家普遍认为，该算法已经过时。” -> “有观点认为该算法已不适宜高并发场景。”
  - *保*：“Nature 2024 年发表的荟萃分析（Smith et al.）表明……”（有具体出处，保留）

### 模式七：同义词躲避 / 旁白复述
- **典型特征**：为了避免词汇重复而刻意轮换不自然的近义词，或在说明事实后追加一句毫无新意的旁白解释。
- **代表词（最多六项）**：`换言之这就意味着`、`不言而喻`、`通俗来讲就是`、`简而言之`、`这一举措充分彰显了`、`由此可见`
- **处理动作**：直接使用最贴切准确的术语，允许多次使用同一名词；删去纯粹拖沓节奏的同义复述。
- **边界例**：
  - *改*：“数据库执行了写操作。这一动作充分体现了系统对数据持久化的不懈追求。” -> “数据库执行了写操作。”
  - *保*：“通俗来讲，递归就是函数自己调用自己。”（面向入门读者的必要教学解释，保留）

### 模式八：连续同模具结构
- **典型特征**：连续段落或句子使用完全相同的句式套路（如连续“不是……而是……”否定式戏剧对比、连续排比反问）。
- **代表词（最多六项）**：`不是……而是……`、`与其说……不如说……`、`这不是……这恰恰是……`、`你以为……其实……`、`真正的……从来不是……`、`答案恰恰相反`
- **处理动作**：保留承载实际论证的必要对比，将其余套话还原为平实陈述或对比。
- **边界例**：
  - *改*：“这不是代码的问题，而是思维的问题；这不是工具的缺陷，而是认知的局限。” -> “相比工具选用，工程规范与团队沟通对项目影响更显著。”
  - *保*：“该协议不是基于 TCP，而是基于 UDP 构建的。”（技术事实澄清，必须保留）

## 3. 材料问题只能审计（不可代劳原则）

当发现原文存在以下缺陷时，**只在 Audit 模式中列出建议，Rewrite 模式严禁擅自补充**：
1. **缺具体数据**：如只有“性能大幅提升”，缺少百分比或毫秒数；
2. **缺真实案例**：如只有“许多公司已成功应用”，缺少具体企业名称；
3. **缺出处来源**：如只有“多项研究表明”，缺少文献或报告出处；
4. **缺背景与后果**：论证缺乏逻辑推导环节。
*禁令*：不得替原作者“编造”一个合理的数字、案例或论文引用来增强说服力！

---

## 4. 防御 humanizer 伪人味陷阱（反例规范）

严禁使用以下破坏真实性的“假人味”手法试图掩盖 AI 痕迹：
1. **禁止混入错别字或语法残缺**：不得为了“自然”刻意引入病句或字词错误；
2. **禁止生搬硬套生僻词与方言**：不得随机将普通词汇换成冷僻成语、晦涩词或地方方言；
3. **禁止虚构经历与第一人称叙事**：不得凭空添加“我记得上个月”、“笔者曾亲历”等虚假个人生活细节；
4. **禁止机械切碎句子破坏语法完整性**：不得把原本语义连贯的复合句强行拆散为“碎片词。一个词。一句。”的伪戏剧风格；
5. **禁止以绕过 AI 检测器为改写导向**：不追求任何检测工具的判定百分比，不进行破坏文意一致性的无谓轮换。
