# 保真契约 (Fidelity Contract)

自然度具有主观性，但保真是硬性约束。清理“AI 味”必须建立在事实、关系与语用信息绝对守恒的前提之上。

---

## 1. 现实 / 虚构 / 混合边界

文本处理前必须明确其文类属性，不同属性对应严格的守恒红线：

1. **现实文本（非虚构、工作、技术、学术、汇报）**：
   - 严禁新增任何事实、数据、背景、案例、地点、引语或来源。
   - 严禁脑补未提及的心理活动、动机、情感或对话。
   - 原文事实模糊时，只在 Audit 模式标注缺陷，Rewrite 模式严禁代填。

2. **虚构文本（小说、剧本、故事）**：
   - 守住既有角色设定、出场人物、时间线与因果链。
   - 守住既定物理规则与世界观设定，不随意篡改情节事实。

3. **混合文本（案例分析、非虚构叙事）**：
   - 明确区分“事实陈述区”与“修辞/叙事区”。
   - 事实陈述区按现实文本绝对保护，修辞区仅做句式与冗余清理。

---

## 2. 保护对象与逐字清单 (Protected Spans)

以下对象必须**逐字保护**，除非用户明确要求修改：

- **实体与标识**：人名、机构名、产品名、地名、代号、专有名词、统一社会信用代码。
- **数值与计量**：数字、百分比、金额、统计值、日期、时间、单位、版本号、区间范围。
- **引用与标题**：带引号的原话/引语、引文出处、法规条目、正式章节标题。
- **技术资产**：代码、命令行、文件路径、URL、参数名、配置项、环境变量、日志及报错输出。
- **正式术语**：特定行业术语与标准定义（不得擅自替换为泛义口语词）。

---

## 3. 语义关系账本 (Semantic Relations)

改写不得造成以下语义关系的倒置、漂移或泛化：

1. **主体—动作—对象**：谁做了什么、对谁产生影响，动作发起者与承受者必须与原文严格一致。
2. **数字—对象绑定**：数字修饰的目标对象不得偏移（例如：“营收增长 20%，利润增长 5%” 不得错位绑定）。
3. **来源—主张绑定**：观点、结论必须绑定到原文指定的来源，不可偷换为主观事实或他人观点。
4. **条件—结果**：“只有在...情况下才...”与“如果在...情况下则...”的先决条件与触发范围保持严密。
5. **原因—结果**：因果链条不可颠倒，间接相关不可夸大为直接因果。
6. **时态与状态**：“计划中”、“进行中”、“已完成”、“已终止”的状态切不可混淆。
7. **情态与确定度**：“可能、或许、据说、大概”不得强化为“必定、证明、已经”；反之亦然。
8. **比较关系**：基准、参照物、比较维度（更高/更低/相当）不可倒转。
9. **范围与所有权**：属于哪个系统、部门、版本或模块，归属关系不可模糊。

---

## 4. 双向复验机制 (Two-way Verification)

完成改写初稿后，必须执行双向无死角交叉检查：

### A. 正向找回（原文 ➔ 改写稿）
- 原文中的核心实体、事实、数据是否完整呈现？
- 原文中的限制条件、否定词（“未”、“不”、“非”）与情态限定是否遗漏？
- 原文中的因果、逻辑递进与状态是否依然成立？

### B. 反向回指（改写稿 ➔ 原文）
- 改写稿中的每一个实词、动作、事实结论，是否均能在原文中找到依据？
- 是否引入了原文不存在的新观点、价值评判、主观修饰或虚构细节？
- **铁律**：凡无法反向回指原文的改写内容，必须立即撤销。

---

## 5. 权限与授权边界

用户发起“去 AI 味”指令，默认**仅授权风格层面的最小必要编辑**：

- **未经明确授权，严禁**：
  1. 删除独有事实、有效背景或结构性结论。
  2. 大幅改变段落结构、拆分/合并文档章节。
  3. 执行大幅度摘要、过度压缩或删减细节。
  4. 补充原文缺失的事实、论据或背景信息。
  5. 修改引用原话或变更正式章节标题含义。
- 若文本缺乏材料导致表达空洞，正确做法是在 `Audit` 模式指出信息短缺，严禁在 `Rewrite` 模式凭空创作。
- **中文交付纪律**（正文与正文外那句说明都算）：不得出现原文、用户请求、保护项或必要技术术语
  之外的英文词——普通编辑概念一律用中文表达（「承载」「承担」「起承接作用」），不写对应的英文
  原形。机器 ID、文件名、代码与确有必要的行业术语可原样保留；**不设全局英文禁词表**，合法的
  文件名、代码、机器 ID 与术语不得被误判。

### 机械检查边界与四态约定
- 验证器 (`scripts/validate-rewrite.py`) 提供 `PASS_MECHANICAL`、`NO-OP`、`FAIL`、`REVIEW` 四态判定（异常态 `ERROR`，退出码 0/1/2/3）。`NO-OP` 只在改写前后**字节完全一致**、没有任何改写发生时给出（v1.2 Task 12 起如实报，退出码仍是 0，不再把它谎称成 `PASS_MECHANICAL`）；交付层 (`scripts/novel_output.py`) 的 `NO-OP` 与此同源：一个文件都不创建。规则本体的唯一权威是 `scripts/novel_validation.py` 的 L0/L1 判定表（四层验证合同的前两层），入口脚本只是它的前置层。
- 机械通过 (`PASS_MECHANICAL`) 仅证明下述覆盖项未发现漂移；**不代表语义等价**。因果逻辑、核心立场、情态与语气的语义等价性仍需在 S6 VERIFY 执行人工或模型级复核；整书通路还要求 L2 分段语义与 L3 全书一致性通过。
- 机械判定为 FAIL 的覆盖项（L0/L1 硬锁）：标题**文字/层级/数量/顺序**（只比级别会漏掉「重要结论→重要决议」）、表格行/单元格、代码围栏正文、**围栏语言标记**与行内代码、URL、**Markdown 链接目标**、日期/时间（新增或丢失）、版本号、**显式引用**逐字保真与无来源新增引语、数字修饰绑定（含实体换绑）、**数值多重集合**（同值出现次数减少或凭空新增）、登记过的专名在普通场景缺失、分段无法逐字符回拼。
- 机械判定为 REVIEW（无法机械定案，转语义门）的覆盖项：新增全量化/绝对化断言词、**限定词类别频次变化**、**否定/条件句级翻转或增删**、**否定极性翻转**、**限制条件被移除**、**凭空内容线索** `unsourced_new_content`（成稿片段在「原文 ∪ 已授权文本」的内容二元组里零来源，或覆盖率 < 0.20；**不再用「新增连续 12 字」判违规**——单纯调高阈值被设计方案第 72 行否定）、**整单元搬运线索** `verbatim_carryover_undocumented`（小说场景里整个内容单元逐字保留却无保护项或账本 `operation="preserve"` 解释；句内复用 ≥12 字的回环句不算违规）、**段落减少缺删除授权**（数量减少不再直接判 FAIL）、**未闭合代码围栏**、**Task 7 降级分段** `degraded_segment_needs_review`、Task 8 的复核码（`anchor_coordinates_stale`、`degraded_segment_anchor`、`indistinguishable_dialogue_citation`、`certainty_ambiguous`、`plot_sensitive_*_needs_second_review` 等）——这些码一律压住结论，**聚合不得把它们洗成通过**。
- 引号不再一律锁定：**显式引用**（带归属动词、出处家具、引用块或已登记保护项）逐字锁定；小说场景里未登记的引号按普通对白处理，可在说话人、对象、意图、信息、否定、条件与态度强度不变时编辑，区分不了时进 REVIEW。

### 否定与条件门（R2 加固，硬约束）

否定、条件与权限关系是**事实关系**，不是文风。它们一旦被改动，文本就换了意思。因此：

1. **否定与条件变化只能判 `REVIEW` 或 `FAIL`，绝不判 `PASS_MECHANICAL`。**
   典型危险改写（全部必须被拦下）：
   - `没有重试` → `会重试`（否定副词换成肯定情态）
   - `不会删除` → `会删除`；`未开启缓存` → `已开启缓存`；`尚未发布` → `已发布`
   - `无需登录` → `需要登录`；`不能访问` → `可以访问`；`不得外传` → `可以外传`
   - `并非全部完成` → `全部完成`
   - `只有管理员才能删除` → `用户可以删除`（限制条件被移除）
   - `除非审批通过，否则不执行` → `审批前也执行`（例外条件被移除且极性翻转）

2. **合法的否定同义替换不得被误杀。** 极性不变时应正常通过：
   `没有重试` → `未进行重试`、`尚未发布` → `目前还没有发布`、`不得外传` → `禁止对外传播`、
   `只有管理员可删除` → `删除权限仅限管理员`（语序调换）、`如果失败则回滚` → `失败时会回滚`。

3. **判定必须可解释。** 拦截理由必须写明是“否定极性被翻转”还是“限制条件被移除”，
   并给出骨架相似度，禁止只输出一个无法解释的分数。

4. **File 模式对 `REVIEW` 一律阻断写盘**，目标文件原始字节保持不变（含 BOM 与换行风格）。

5. **机械 `PASS_MECHANICAL` 不等于语义等价。** 它只证明已覆盖项未发现漂移；
   因果、立场与语气仍需 S6 VERIFY 的语义复核。

6. **人工确认不得绕过事实关系门。** `file_commit.py` 不提供 force 参数；
   凡否定/条件/权限判定为 `REVIEW` 的候选，必须回到改写环节修正，
   不允许以“已人工确认”为由强制落盘。

回归矩阵：`evals/negation-condition-matrix-v1.1.json`（10 个危险反例 + 6 个合法正例），
由 `tests/test_validate_rewrite.py` 与 `tests/test_release_package.py` 同时执行；
门槛为**危险反例零放行、合法正例零误杀**，不得修改期望值转绿。

### File 模式生产提交门（唯一写盘通道）
File 模式的落盘必须经生产模块 `scripts/file_commit.py`（`SafeFileCommitEngine.commit_rewrite`），不得绕过：

1. **验证前置**：候选先过机械验证器，`FAIL`、`REVIEW`、`ERROR` 一律不落盘，目标字节保持不变；`REVIEW` 需语义复核通过后才可再次提交。
2. **No-Op 原始字节判定**：候选与目标原始字节（含 BOM）完全一致时返回 `NOOP`，不触碰文件。
3. **哈希竞争防护**：调用方读文后若目标已被他人修改（传入 `expected_hash` 校验），提交中止（`ABORTED_RACE`）。
4. **备份唯一**：备份名 `.bak` / `.bak1` / `.bak2` 递增，绝不覆盖既有备份；提交后保留备份以供回滚。
5. **原子写入与复核**：候选写同目录临时文件并 fsync，经 `os.replace` 原子替换；落盘后立即重读目标比对候选哈希，不符即从备份恢复（`ROLLED_BACK`）。
6. **编码保持**：UTF-8 BOM 与 CRLF/LF 换行风格按目标文件原样保留。
7. **中断可恢复**：任何阶段异常均恢复原始字节，不留临时文件。

单元测试（`tests/test_file_mode_rollback.py`）必须直接 import 生产模块调用真实接口，禁止在测试内另写模拟引擎。
