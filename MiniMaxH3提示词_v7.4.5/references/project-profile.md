# Project Profile — 项目档案（一次确认，全集复用）

> 多镜/多集项目的唯一事实源：题材层、参考资产、项目定调一次确认，
> 之后每集生成自动读取复用。单次独立提示词不需要档案。

## 何时使用

- **多镜/多集项目**（短剧/长片）：首次生成时确认档案，之后自动复用
- **单次独立提示词**：不需要档案，直接走标准工作流

## 档案结构（markdown，存项目目录，如 `<你的项目目录>\v7-project.md`）

> 档案可用中文记录内部项目元数据；生成交付时必须转换为官方英文六字段与
> `<Subject N>` / `<Picture N>` / `<Video N>` / `<Audio N>` 标签。

```
# 项目档案：[项目名]（v7-project.md）
题材：[一句话，如 玄幻悬疑侦探剧]

## 题材层声明（每份提示词的题材层从此处取值）
服装体系：[按项目与参考图；非玄幻项目不写玄幻元素]
武器与道具：[按项目；特效默认关闭，启用见 guoman-3d §5d]
场景类型：[城市街景/室内/宫廷/宏大玄幻]
运镜倾向：[悬念剧→慢推+特写；打斗→冲击运镜；言情→环绕]

## 参考资产清单（每份提示词的参考声明从此处取值）
<Subject 1> [角色名] — 路径 + 继承范围 + 声音绑定 + voice_rights_status：[owned/licensed/user_supplied/unknown]
<Picture 1> [场景] — 路径 + 只取空间纹理
<Picture 2> [道具] — 路径 + 完全保留
<Video N> / <Audio N>（如有）

## 项目定调（自动推断+用户确认，进输出报告的定调段）
色调：[冷/暖/去饱和]
照度：[低照度/明亮]
节奏：[慢/快/起伏]
声音：[低频不安感/写实环境]

## 变体（开始界面/档案确认时由用户选择——一个剧本一个变体，全剧锁定）
变体：[基础风格 / 仙侠奇幻 / 权谋暗黑 / 山水田园 / 战场史诗 / 江南烟雨]
（通俗解释见 guoman-3d §1c——选择权在用户，技能只解释不预设推荐）

## 玩法档（打斗镜头专用维度——与变体同位置，全剧锁定）
玩法档：[A 终止构图版 / B 稳定版 / C 疯批版 / 未命中打斗镜头]
（仅命中打斗/动作/能量战斗镜头时确认；单次请求只当次锁定，不写入档案。）

## 画风层
国漫 3D（锁定，guoman-3d §1a，不在档案中重写）
```

## 创建流程

1. 识别为多镜/多集项目（输入含多镜或用户提到项目）
2. 检查项目目录有无档案文件（`项目名` 目录下 `v7-project.md` 或用户指定路径）
3. 有 → 读取复用：题材层/资产/定调/变体/玩法档直接取值，不再重复询问
4. 无 → 与用户确认档案字段（题材层 4 项 + 资产清单 + 定调 4 项 + 变体 1 项；
   命中打斗/动作/能量战斗时再确认玩法档 1 项），确认后写入项目目录
5. 之后每集：自动读取档案，逐镜提示词按档案取值；项目命中玩法档时不得重新选档

**完成条件**：档案存在且被读取（有档案复用成功）；或字段已确认且写入
项目目录（新建完成）。未确认前不进入步骤 2 以后的产出。

## 资产记录格式（来源：地狱 reference-asset-control）

```
asset_id: <Subject 1>（陆慎行）
identity invariants（换镜不变的身份事实）: 脸型骨相、核心体型、发型轮廓
state version: <Subject 1>@v003
state variables（剧情改变的当前事实）: 青白练功服、无伤势
inherit: 角色身份、脸型、发型、当前服装
exclude: 原图姿态、构图、机位、背景、光线、调色、景深、临时人物
rights_status: owned（项目自有）
```

**参考图质检（来源：seedance2-chinese-guoman 参考图使用规则 + remotion
纸片素材规范）**：只引用出镜角色、当前单一机位场景与必要道具——**不得
上传多视图整图、场景四宫格整图、带人脸照片或屏幕头像的参考图**；素材
验收=贴深色背景检查（描边连续/无残留底色/主体完整/不带文字/不带写实
阴影）；同一角色多状态多做几张（各状态独立资产，不重生成）。
**规则**：禁止把状态变化合并进新身份描述（否则「同名不同人」）；版本号
表达批准状态快照不表达镜头顺序；新状态不覆盖已被镜头引用的旧状态；变形
按阶段版本化；**权利状态五态**——owned（自有）/ licensed（有许可记录
范围）/ user_supplied（用户提供仍需确认用途）/ research_only（不进生成
交付）/ unknown（权利不明，不过生成前门）；批准状态 proposed →
reference_ready → approved → deprecated。
「多视图」比「三视图」准确：缺失角度必须登记，不假装存在（角色建议：
正面全身/左右侧面/背面全身/面部近景/关键材质近景/动作范围）。

## 文件路由（来源：地狱 Working Folders — Cherry Studio 适配）

- 项目文件（档案/台账/参考图/提示词批次）一律放项目目录，绝不散落
  工作区根目录
- 上传附件先归入项目目录再读（文件系统附件；聊天附件按平台机制处理）
- 用毕的输入归档（processed），**绝不删除用户文件**（缓存永不自动清理，
  清理权在用户）
- 产物写项目目录并告知路径

|---|---|---|

- 台账（shot-ledger.csv）随输出位置维护——**用于后期校验哪些镜头有问题**
- **四级目录 ↔ 台账状态机对应**：huancun=待生成素材 / zhuanhuanzhong=
  prompt_ready 或 needs_revision / daiheshen=awaiting_video_feedback 或
  needs_verification / chengpin=selected+locked——目录管文件、台账管状态。
  60-79 分只留在 daiheshen 并标注「需重点验证项」；<60 分回 zhuanhuanzhong。
- **chengpin 写入动作**：仅当有视频审核 gate 证据、四硬门通过且视频审核分 ≥80，
  技能才将定稿提示词写入成品区；这是归档动作，不是发布授权。用户推翻时记
  supersede/reject 并回 needs_revision，文件搬运权在用户。
- **只读降级**：无写权限或用户要求只读时，不伪造 mkdir/档案/台账/硬校验结果；
  输出行写「只读模式：未落盘」，档案与台账以文本附列，脚本可用 stdin 校验。
- **开始界面分两步**：第一步位置两项（界面本体）；第二步档案字段
  （题材/资产/定调/变体；命中动作镜头时含玩法档、角色声音绑定）——两者不混。

## 使用规则

- **槽位角色纪律（来源：地狱 Per-Image Role Convention）**：项目内参考
  标签槽位固定——`<Subject 1>` 恒为该剧主角、`<Subject 2>` 恒为配角、
  `<Picture 1>` 恒为场景……交付提示词使用官方英文标签。
- **冲突裁决**：输入优先于档案——本次输入明确写出的以输入为准；档案只
  在输入未提及处生效；冲突项在输出报告的「已替你补/假设」中标注
- 档案是唯一事实源：服装/资产/定调以档案为准；逐镜提示词**引用不重述**
  （描述段不重写服装细节，指向参考标签）
- 资产更新（新参考图/角色换装）：更新档案资产清单，不重建档案
- 换项目/换题材：重建档案
- 档案与技能分离：档案在项目目录，技能是通用工具
- 档案中不写 IP 名称、不写画风层细节（画风锁定全局）
