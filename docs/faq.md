# 常见问题与排查

## 仓库打不开、显示 404？

先打开[仓库根地址](https://github.com/ningmengningmeng233-sys/my-agent-skills)。目录升版后旧文件夹链接会失效，从首页重新进入。也可尝试[官方 ZIP 地址](https://codeload.github.com/ningmengningmeng233-sys/my-agent-skills/zip/refs/heads/main)。

若根页仍无法打开，分别检查浏览器、网络、代理和 GitHub 登录状态，记录完整链接及报错。根页打不开与技能运行失败是两类问题；不要据此直接重装 Python。仓库访问权限可能随时间变化，以当时 GitHub 页面为准。

## 为什么没有一键装完？

这些产品用途、依赖和宿主不同。规则型技能、Python 索引器、Node 本地服务和客户端钩子不能共用一份安装命令。选一套，按对应指南准备，能减少依赖冲突和不必要下载。

## 下载 ZIP 后只复制 SKILL.md 可以吗？

不可以作为完整安装。入口可能引用 scripts、references、schemas、vendor 或随包依赖。应复制完整技能目录，并按原安装说明保留分发结构。

## 代理说“已使用技能”，就说明可用了？

还要检查是否读取了正确入口、实际调用是否执行、退出状态是否正确、产物能否回读。显式加载、自然触发、离线演练和真实业务是不同证据。

## 为什么有 Python 版本或依赖说明冲突？

部分包保留历史文档。先看当前版本的实际环境检查器与依赖文件。例如 UMH 按 Python 3.12、Node 24.2 起准备；抖音当前按 Python 3.12 及 doctor 核对，旧说明引用的缺失锁文件不能直接执行。具体冲突见各技能指南。不要自己造一个空锁文件冒充完整安装。

## 免费吗？需要 API Key 吗？

下载代码与实际运行费用不同。纯规则流程可以不调用额外服务；索引摘要、改写、语音识别、生图和视频平台按实际配置使用本地算力或外部服务。不是每个技能都需要 Key，也不是每条流程都完全离线。代码和第三方组件的许可分别查看，不能统一认定为 MIT 或可商用。

## 没有 GPU 能用吗？

取决于工序。规则检查和部分本地脚本不需要 GPU；ASR、向量检索或生成模型需要按具体后端确认 CPU 支持、性能和内存。当前没有全产品无 GPU 等效性能承诺。

## 执行中断了，能直接删除目录重跑吗？

先不要。保留原始输入、任务 ID、状态数据库、日志与已完成产物。使用对应 resume、retry 或恢复工序；删除目录可能丢掉去重与断点证据，导致重复下载、重复计费或覆盖原文。

## 校验失败，可以更新哈希后继续吗？

不能用重算清单替代排错。先确认是否复制遗漏、文件损坏、版本混用或包本身缺项。尤其资产公开档的完整发布校验仍有已知缺口，不能自行修改清单就宣称正式发布通过。

## 哪些资料不要发到 GitHub 或公开问题单？

真实 `.env`、Key、Cookie、会话文件、聊天记录、原稿、客户端绑定、数据库、模型缓存和含隐私的完整日志。提交问题前脱敏，提供版本、系统、命令、实际错误与最小可公开样本即可。

## 怎么提交一个能定位的问题？

复制下方模板，填写后在仓库问题区反馈；先检查是否包含隐私：

```text
技能名称 / 版本：
仓库提交号：
系统 / 客户端 / Python 或 Node 版本：
操作步骤与命令（脱敏）：
期望结果：
实际结果与完整错误：
任务状态 / 退出码：
最小可公开输入：
是否能在独立目录复现：
```

## 测试通过为什么还标候选或待验证？

测试能证明所覆盖的场景。接收者机器的安装、真实账号、平台状态、模型效果、客户端自然触发与成片播放还需要独立检查。详见[验证范围与已知限制](verification.md)。
