# 柠檬思考

> 研发流程 · 阶段对齐 · **1.1.5** · [原始技能入口](../../柠檬思考_v1.1.5/SKILL.md)

根据工作区里的需求、设计、工单、测试和代码证据判断研发阶段，组织从设计到验证的推进。适合需要清楚范围和交接的研发任务。

[使用流程](#使用流程) · [示例](#示例) · [边界与注意事项](#边界与注意事项) · [遇到问题](#遇到问题)

## 输入与交付

输入：项目目标、当前工作区、授权范围、现有设计/工单。

输出：阶段判断、设计与工单、执行或验证记录，以及阻塞和下一步。

## 开始之前

安装完整技能目录，并保留其 modules 与 references。模块不是需要逐个注册的独立技能；所引用外部能力按原指南准备，不自动安装。

安装时完整复制 `柠檬思考_v1.1.5/`，由宿主按入口的 `name` 识别。宿主加载与脚本依赖是两件事；先看[通用安装说明](../getting-started.md)，再按下方原始文档准备。

## 使用流程

1. 说明项目路径、目标和本轮权限，例如“只设计，不改代码”。
2. 让代理检查物理文件与当前差异，判断真实阶段。
3. 形成可审阅设计与工单，明确验收、回滚和停止条件。
4. 获准执行后按工单推进，保留测试证据；交接时标明已完成与未验证。

这是代理流程入口，无需为“使用技能”直接运行一套脚本。先明确本轮授权和输出，再由宿主按入口流程执行。

## 交接应该留下什么

常用设计与工单位置在项目内 `文档/柠檬/设计/` 和相关工单目录，具体以当前入口规定为准。交接至少写出目标、范围、当前阶段、文件路径、验证结果、未完成项、停止条件和回滚方式。

检查器通过但尚未在真实宿主运行时，应明确写“工程验证通过，真实宿主未验收”，不能只留下“完成”。

## 边界与注意事项

- 阶段判断以工作区证据为准，不能只凭上一轮总结宣称完成。
- 流程推进不自动扩大用户授权；安装、真实服务操作和发布分别明确。
- 保留用户未提交改动；设计、工程检查、宿主验收和发布不能合并为一个“通过”。
- 单独点名某个 gstack 模式时按其适用入口处理，不强行接管整条流程。

## 遇到问题

| 现象 | 建议处理 |
| --- | --- |
| 代理跳到错误阶段 | 要求列出用于判定的实际文件与缺项，按证据重新对齐。 |
| 没有工单就开改 | 停止新增改动，先明确设计、执行范围和验收。 |
| 交接只有口头结论 | 写出路径、当前状态、原始证据和恢复方法。 |

恢复操作前保留原始输入、配置（脱敏）、日志和状态库；不要先删除现场。备份至少包含用户数据和工序状态，不能只备份技能文件。
