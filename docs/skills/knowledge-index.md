# 知识库转录

> 非虚构资料 · 可追溯问答 · **5.4.8** · [原始技能入口](../../知识库转录_v5.4.8/SKILL.md)

把长篇非虚构资料或独立文档切段建索引，结合原文做可追溯检索与问答。适合课程、书籍、手册与研究笔记。

[使用流程](#使用流程) · [示例](#示例) · [边界与注意事项](#边界与注意事项) · [遇到问题](#遇到问题)

## 输入与交付

输入：TXT / Markdown 资料、名称、作者和指定知识库。

输出：原文段、段索引、书导航、状态库及按配置建立的语义索引。

## 开始之前

按 QUICKSTART.md 准备 uv/Python、requests 与 python-dotenv，配置索引模型接口。PDF / Word / EPUB 需要对应转换能力和检查；不能假设扫描 PDF 已具备 OCR。

安装时完整复制 `知识库转录_v5.4.8/`，由宿主按入口的 `name` 识别。宿主加载与脚本依赖是两件事；先看[通用安装说明](../getting-started.md)，再按下方原始文档准备。

## 使用流程

1. 先选一份短资料，在独立库中 init 与 build。
2. 抽查 原文/、段索引/、书导航/ 的结构和引用。
3. 提问时先检索候选，再回读原文并给文件与行号。
4. 扩大库或启用可选向量能力前确认模型、数据路径与费用。

### 命令入口

在技能根目录执行，使用已准备好的对应运行环境。`<…>` 是必须替换的占位符；下面的业务命令不是安装完成后的自动动作，也不代表本轮已执行真实业务。

```powershell
uv run --with requests --with python-dotenv python scripts/orchestrate.py --lib "<知识库绝对路径>" init
uv run --with requests --with python-dotenv python scripts/orchestrate.py --lib "<知识库绝对路径>" build --source "<资料绝对路径>" --novel "资料名" --author "作者"
```

## 配置与数据位置

在本机 .env 中核对 `OPENAI_API_KEY`、`SUMMARY_API_URL`、`SUMMARY_API_MODEL`，明确 `INDEX_LIB_DIR` 或每次显式传 `--lib`。字段完整不等于接口已验证，先用小样本确认。

主要数据为 `原文/`、`段索引/`、`书导航/`、`.index_state.db` 与按配置生成的 `.semantic_index`。建库恢复要同时保留原文和状态库。可选向量服务按包内说明配置，不默认已经安装 Ollama 或模型。

## 边界与注意事项

- 名字中的“转录”不等于通用音视频识别；这套工具的核心是文档建库与回读。
- 与小说风格索引分工不同，也不能用“知识转录索引”直接替换。
- 默认精读预算有限：通常取少量候选段，不能声称读完未展开的整库。行号不确定保留 NEEDS_REVIEW。
- Web 控制台按本机用途配置，不直接暴露公网；索引服务可能传出文档片段。

## 遇到问题

| 现象 | 建议处理 |
| --- | --- |
| 无法解析 PDF | 先确认是否为扫描件和是否安装转换器，单独检查转换结果。 |
| 回答没有原文依据 | 回读命中段并检查行号，缺证据则保留未知。 |
| 建库中断 | 保留 .index_state.db、原文与日志，按原指南恢复，不先清空数据库。 |

恢复操作前保留原始输入、配置（脱敏）、日志和状态库；不要先删除现场。备份至少包含用户数据和工序状态，不能只备份技能文件。
