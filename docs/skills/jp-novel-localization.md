# 日系小说本地化

> 中文编辑 · 连载流程 · **4.5.6** · [原始技能入口](../../日系小说本地化_v4.5.6/SKILL.md)

处理带日式翻译腔的中文稿，将其整理为符合目标中文网文表达的章节。提供工作区、边界确认、改写、检查、审批和合并流程。

[使用流程](#使用流程) · [示例](#示例) · [边界与注意事项](#边界与注意事项) · [遇到问题](#遇到问题)

## 输入与交付

输入：中文稿、章节范围、风格要求、事件与专名约束。

输出：章节候选稿、检查记录、审批状态与合并/分章产物。

## 开始之前

当前入口面向 Windows PowerShell。按 INSTALL.md 准备模型路由、工作区与所需资产；先执行 doctor 检查，不默认启动整书改写。

安装时完整复制 `日系小说本地化_v4.5.6/`，由宿主按入口的 `name` 识别。宿主加载与脚本依赖是两件事；先看[通用安装说明](../getting-started.md)，再按下方原始文档准备。

## 使用流程

1. 检查环境与资产，创建独立工作区并导入原文。
2. 确认章节边界和事件决策，缺项先解决。
3. 逐章 rewrite → check，必要时 repair，人工比较原文与候选。
4. 对明确通过人工审阅的章节执行 approve，再 merge 或 publish-split。

### 命令入口

在技能根目录执行，使用已准备好的对应运行环境。`<…>` 是必须替换的占位符；下面的业务命令不是安装完成后的自动动作，也不代表本轮已执行真实业务。

```powershell
$skillRoot = "<技能目录绝对路径>"
& "$skillRoot/scripts/doctor.ps1"
& "$skillRoot/scripts/novel-localization.ps1" assets
```

## 工序顺序

工作区工序按原入口的参数调用：`init / ingest / confirm-boundary` → 事件解析与决策 → `rewrite / check / repair` → 人工 `approve` → `merge / publish-split`。

每步先确认章节 ID 与工作区路径。批量审批、整书改写和发布分章是不同操作，不应合成一次未经审阅的默认执行。

## 边界与注意事项

- 处理中文稿，不等于日文原文翻译服务。
- 检查通过与人工批准不同；不能把 approve-all 当作默认流程。
- 输入或候选稿变化可能使原审批失效，需重新检查确认，不能越过状态机。
- 模型调用可能发送章节内容；原文、工作区、配置与审批记录应备份。

## 遇到问题

| 现象 | 建议处理 |
| --- | --- |
| 边界未确认不能改写 | 先完成 ingest 与 confirm-boundary 对应工序。 |
| 合并被拒绝 | 检查未批准章节、过期指纹和质量问题，勿手工改状态。 |
| 资产或模型不可用 | 按 doctor 的实际缺项配置，避免回退到不明服务。 |

恢复操作前保留原始输入、配置（脱敏）、日志和状态库；不要先删除现场。备份至少包含用户数据和工序状态，不能只备份技能文件。
