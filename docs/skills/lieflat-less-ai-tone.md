# 去 AI 味

> 文本编辑 · 保留作者声音 · **2.0.2** · [原始技能入口](../../去AI味_v2.0.2/SKILL.md)

审阅和改写已有中文或中文为主的混合文本，减少模板化表达，保留事实、叙述视角与作者声音。可只审阅，也可对文件执行有备份的改写。

[使用流程](#使用流程) · [示例](#示例) · [边界与注意事项](#边界与注意事项) · [遇到问题](#遇到问题)

## 输入与交付

输入：原文、需要保留的事实和表达、改写强度。

输出：审阅意见或改写稿、机械校验结果；文件模式还需要预览与提交确认。

## 开始之前

Python ≥ 3.12、Node.js ≥ 20.18.0。按 USAGE.md 先准备独立运行副本，再装对应依赖与 Node 工具。核心锁与可选相似度锁分开，默认核心不拉入 torch；需要语义相似度时再准备可选依赖和指定模型快照。

安装时完整复制 `去AI味_v2.0.2/`，由宿主按入口的 `name` 识别。宿主加载与脚本依赖是两件事；先看[通用安装说明](../getting-started.md)，再按下方原始文档准备。

## 使用流程

1. 提供小段原文，选择 Audit 或 Rewrite，以及 conservative / balanced / deep 强度。
2. 列出不可改的事实、术语、专名与语气要求。
3. 先比较修改前后，再运行机械校验；合理时可以保持原文 NO-OP。
4. 文件模式先预览、备份并确认提交，不让代理直接覆盖唯一原稿。

## 选择运行方式

| 方式 | 适合任务 |
| --- | --- |
| Audit | 只找问题与给建议，保留原文 |
| Rewrite | 提供一份待比较的改写稿 |
| File | 对文件预览、备份并按确认结果提交 |
| Embedded | 在更大流程中按约定调用 |

运行副本创建、Python 核心锁安装、可选相似度锁和 `npm ci` 的完整顺序见 USAGE.md。上方 validate-rewrite 只执行对应机械检查，不能代替完整改写流程或语义模型。

## 边界与注意事项

- 这是编辑已有文本的工具；不承诺任何 AI 检测分数、规避检测结果或固定文学效果。
- 事实、引用和作者意图需要人工复核；机械校验不能判断一篇文章是否写得好。
- 核心与可选相似度功能不同；不能在缺模型时伪称相似度检查已执行。
- 不要在封存分发或现役安装目录随意 npm install / 改锁文件；按 USAGE.md 使用运行副本。

## 遇到问题

| 现象 | 建议处理 |
| --- | --- |
| 缺少模型或相似度不可用 | 确认是否真正需要可选功能，按锁文件和模型快照说明准备，不自动下载不明模型。 |
| 越改越像模板 | 降低强度，明确保留句，接受 NO-OP，逐段人工比较。 |
| 文件写入失败 | 保留原文和备份，查看提交状态，勿反复覆盖或删除备份。 |

恢复操作前保留原始输入、配置（脱敏）、日志和状态库；不要先删除现场。备份至少包含用户数据和工序状态，不能只备份技能文件。
