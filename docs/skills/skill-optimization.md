# 技能优化

> 工程审查 · 受控精简 · **1.0.1** · [原始技能入口](../../技能优化_v1.0.1/SKILL.md)

审查技能代码的结构、依赖与重复实现，按证据提出精简方案，再对获准范围执行和复核。适合复杂调用链或长期膨胀的代码库。

[使用流程](#使用流程) · [示例](#示例) · [边界与注意事项](#边界与注意事项) · [遇到问题](#遇到问题)

## 输入与交付

输入：明确仓库、优化目标、必须保留的行为与测试。

输出：结构证据、优先级问题、审查意见、获准改动及验证记录。

## 开始之前

这是流程技能，不附带所有审查工具。需要准备 Graphify-Jev、Ponytail 与 Reviewer；缺工具时说明阻塞，不把手工猜测写成工具结论。

安装时完整复制 `技能优化_v1.0.1/`，由宿主按入口的 `name` 识别。宿主加载与脚本依赖是两件事；先看[通用安装说明](../getting-started.md)，再按下方原始文档准备。

## 使用流程

1. 先确定工作区身份、未提交改动、排除范围和回滚方式。
2. 按 Graphify-Jev → Ponytail → Reviewer 的流程建立问题证据。
3. 只选择已审查且获准的少量问题，默认最多 3 项、上限 5 项。
4. 在隔离工作区执行，跑相关既有测试，并用同一结构依据复核。

## 如何界定成功

先选可衡量目标：减少某条重复调用、移除确认无用的依赖、保留错误语义或改善模块职责。体积和行数只是辅助指标。

执行前记录基线；执行后使用相关既有测试和同一结构检查复核。工具配置可能涉及外部服务，是否联网以实际工具设置为准。

## 边界与注意事项

- 不为减少行数删除公开接口、错误处理、安全边界或数据兼容逻辑。
- node_modules、vendor 与封存运行件不能当成自写冗余随意删除。
- 文案、配色和简单配置修改通常不需要整套优化流程。
- 结构报告或测试通过不能证明线上业务全部正常；验证范围要随影响面明确。

## 遇到问题

| 现象 | 建议处理 |
| --- | --- |
| 工具不可用 | 补齐工具或记录阻塞，不能虚构审查结果。 |
| 优化影响超出预期 | 停止扩散，保存差异并回退当前批次，重新确认范围。 |
| 测试通过但行为变了 | 补充真实触发场景，保留旧行为样本，按影响重新评估。 |

恢复操作前保留原始输入、配置（脱敏）、日志和状态库；不要先删除现场。备份至少包含用户数据和工序状态，不能只备份技能文件。
