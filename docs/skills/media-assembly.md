# 成片合成

> 媒体工程 · 计划与组装 · **0.1.4** · [原始技能入口](../../成片合成_v0.1.4/SKILL.md)

消费已有分镜、配音和资产账本，形成渲染计划，再分阶段执行视频、语音、口型与组装。适合已有结构化产线数据的用户。

[使用流程](#使用流程) · [示例](#示例) · [边界与注意事项](#边界与注意事项) · [遇到问题](#遇到问题)

## 输入与交付

输入：storyboard.json、dubbing.json、asset_ledger.json。

输出：render_plan、失败项记录及实际执行阶段的媒体产物；未接真实提供方时只能做离线演练。

## 开始之前

Python ≥ 3.10；真实合成需要 FFmpeg 与相应视频/TTS 服务凭据。先按 INSTALL.md 准备环境。默认 stub 用于离线流程，不能当作真实生成器。

安装时完整复制 `成片合成_v0.1.4/`，由宿主按入口的 `name` 识别。宿主加载与脚本依赖是两件事；先看[通用安装说明](../getting-started.md)，再按下方原始文档准备。

## 使用流程

1. 先对齐三份上游输入与资产路径，再生成计划。
2. 用包内 fixtures 熟悉离线工序，明确样例与真实业务分开。
3. 接入真实服务并确认费用后，按 video → tts → 可选 lip-sync → assemble 执行。
4. 逐阶段核对媒体文件与失败记录，最终实际播放视频并检查音画和字幕。

### 命令入口

在技能根目录执行，使用已准备好的对应运行环境。`<…>` 是必须替换的占位符；下面的业务命令不是安装完成后的自动动作，也不代表本轮已执行真实业务。

```powershell
python -m renderplan plan --storyboard tests/fixtures/storyboard.json --dubbing tests/fixtures/dubbing.json --asset-ledger tests/fixtures/asset_ledger.json --out .lemon/render_plan.json
# 下一条执行示例计划的 video 阶段；先确认提供方配置
python -m renderplan run --plan .lemon/render_plan.json --stage video --out .lemon/run
```

## 离线样例与正式输入

命令示例使用 `tests/fixtures/` 中的样例，只适合演练。正式任务应替换为自己的三份输入。需要指定输出目录，避免覆盖上次计划。

后续阶段在同一个计划下按 `tts`、可选 `lip-sync`、`assemble` 选择，查看每阶段的失败记录。更换资产或上游分镜后应重新检查计划，而不是继续消费旧计划。

## 边界与注意事项

- 不负责从小说直接写剧本或替代分镜/提示词技能。
- 缺凭据应保持 BLOCKED-CRED；离线 stub、文件存在和真实有效视频是不同状态。
- 口型同步默认关闭，可回退配音与字幕；需要口型时单独配置并验收。
- 不要删除失败项再签发成功；确认实际字节、媒体可解码与最终播放结果。

## 遇到问题

| 现象 | 建议处理 |
| --- | --- |
| 输入合同不一致 | 按原始分镜与账本修复字段和关联，勿只改合成侧 schema。 |
| 输出不能播放 | 检查真实提供方、下载完整性与 FFmpeg 诊断，保留失败文件和日志。 |
| 视频有了但配音缺失 | 查看阶段状态，完成并验证 TTS 后再组装。 |

恢复操作前保留原始输入、配置（脱敏）、日志和状态库；不要先删除现场。备份至少包含用户数据和工序状态，不能只备份技能文件。
