# RTK 压缩器

> 开发工具 · 输出压缩 · **92cc75f-r2** · [原始技能入口](../../rtk-token-reducer_v92cc75f-r2/SKILL.md)

为 Qoder CLI 的工具输出提供压缩钩子，减少可压缩文本占用；保留原文回读与用量记录。适合日志、构建和测试输出较多的工作流。

[使用流程](#使用流程) · [示例](#示例) · [边界与注意事项](#边界与注意事项) · [遇到问题](#遇到问题)

## 输入与交付

输入：Qoder CLI 的 Bash 工具输出。

输出：更短时才采用的压缩文本、本地原文 spool 与统计；异常时回退原输出。

## 开始之前

需要 Qoder CLI、可用的 `rtk` 二进制与 Python。它使用 PostToolUse(Bash) 和 PreCompact 钩子；其他客户端不能直接照搬。先备份客户端设置。

安装时完整复制 `rtk-token-reducer_v92cc75f-r2/`，由宿主按入口的 `name` 识别。宿主加载与脚本依赖是两件事；先看[通用安装说明](../getting-started.md)，再按下方原始文档准备。

## 使用流程

1. 阅读安装预览，确认目标是用户范围还是项目范围。
2. 只在确认预览修改范围后执行 --apply。
3. 运行小规模自检，再观察实际日志压缩与原文回读。
4. 不再需要时使用安装器的移除功能，保留其他钩子配置。

## 项目范围与原文回读

只想影响一个项目时，按 README 使用 `--scope project --root .` 预览，再确认是否加 `--apply`。不要在不清楚当前目录时写入项目设置。

压缩后需能回读 spool 中原文；日志涉及凭据时同时管理 spool 的权限、保留周期与备份范围。统计表示观察到的输出变化，不是费用账单。

## 边界与注意事项

- 不承诺所有输出都能缩短，也不保证固定压缩比例或费用降幅。
- 保留真实退出码；错误、二进制及不适合压缩的输出应安全回退。
- 默认数据在 ~/.qoder/rtk-reducer/，可用 RTK_REDUCER_HOME 指定；spool 可能含日志中的敏感内容。
- 安装成功、钩子实际触发、压缩有效是三项检查；不要只看安装器退出码。

## 遇到问题

| 现象 | 建议处理 |
| --- | --- |
| 自检提示缺少 rtk | 先安装并确认二进制可用；缺依赖不能算自检通过。 |
| 看不到节省 | 查看统计与钩子触发记录，短输出或不可压缩输出可能保持原样。 |
| 配置冲突 | 保留现有设置，用预览定位差异；不要整体替换客户端配置文件。 |

恢复操作前保留原始输入、配置（脱敏）、日志和状态库；不要先删除现场。备份至少包含用户数据和工序状态，不能只备份技能文件。
