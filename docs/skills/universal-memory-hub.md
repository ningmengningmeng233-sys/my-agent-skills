# 全局记忆 UMH

> 跨客户端 · 本地记忆 · **1.0.2** · [原始技能入口](../../全局记忆UMH_v1.0.2/SKILL.md)

在同一台机器的多个 AI 客户端之间维护共享记忆，提供本地服务、接入管理与诊断。适合希望跨工具延续项目上下文的用户。

[使用流程](#使用流程) · [示例](#示例) · [边界与注意事项](#边界与注意事项) · [遇到问题](#遇到问题)

## 输入与交付

输入：明确允许保存的记忆与客户端接入配置。

输出：本地记忆数据、检索结果、连接状态与运行记录。

## 开始之前

需要 Node.js ≥ 24.2、Python ≥ 3.12。使用完整分发目录，保留随包运行件和依赖；不要只复制 SKILL.md，也不要先运行 npm install 改写分发。已有 Windows 分发验证不等于其他系统已验收。

安装时完整复制 `全局记忆UMH_v1.0.2/`，由宿主按入口的 `name` 识别。宿主加载与脚本依赖是两件事；先看[通用安装说明](../getting-started.md)，再按下方原始文档准备。

## 使用流程

1. 运行 bundle 校验和 setup --check，先解决环境缺项。
2. 确定独立数据目录，默认 ~/.umh；使用 UMH_HOME 或 --umh-home 时所有命令保持一致。
3. 按包内说明初始化、启动服务，再逐个配置客户端连接并审阅信任范围。
4. 用一条可删除的测试记忆验证写入与回读；备份真实数据后再长期使用。

在技能根目录执行，使用已准备好的对应运行环境。`<…>` 是必须替换的占位符；下面的业务命令不是安装完成后的自动动作，也不代表本轮已执行真实业务。

# 以下命令在初始化并启动后查看服务状态

## 初始化与服务管理

环境与分发检查通过后，以下操作会创建数据或启动服务，先确定数据目录：

```powershell
node scripts/setup.mjs --init
node scripts/umh.mjs start
node scripts/umh.mjs status
node scripts/umh.mjs stop
```

客户端接入按 README 和 INSTALL 的对应流程配置并审阅信任范围；不要把别人的绑定文件复制到自己的客户端。初始化与服务启动不等于已经接入客户端。

## 边界与注意事项

- 支持说明涉及 Cherry、Qoder、ZCode、Codex、MiniMax、DSH；每个客户端仍须在接收者机器上验证，Claude 保持未验证。
- 随包分发校验通过不等于客户端自然触发、持久化与恢复全部通过。
- 记忆可能含私人信息；接入前审核权限，避免无选择地收集所有对话。
- 数据备份不能用 Git 回退替代。不要删除运行件、改校验清单或共享个人客户端绑定来消除报错。

## 遇到问题

| 现象 | 建议处理 |
| --- | --- |
| 环境检查版本不足 | 以当前检查器和分发要求为准，升级 Node/Python 后重新检查。 |
| 服务有数据但客户端读不到 | 确认服务状态、数据目录、连接地址与客户端信任配置一致。 |
| 包校验失败 | 重新取用完整分发，排除复制遗漏；不要直接更新哈希让损坏包通过。 |

恢复操作前保留原始输入、配置（脱敏）、日志和状态库；不要先删除现场。备份至少包含用户数据和工序状态，不能只备份技能文件。
