# Telegram 归档

> 消息归档 · 附件整理 · **1.0.2** · [原始技能入口](../../tg转录_v1.0.2/SKILL.md)

导出、导入和整理 Telegram 消息及附件，生成可检索、可阅读或可分享的归档。支持任务状态、断点恢复、增量更新与预设。

[使用流程](#使用流程) · [示例](#示例) · [边界与注意事项](#边界与注意事项) · [遇到问题](#遇到问题)

## 输入与交付

输入：明确的聊天对象、时间范围、消息类型和输出选择；或已有 Telegram Desktop / tdl JSON。

输出：原始导出、附件、阅读视图、检索库或分享副本，取决于任务配置。

## 开始之前

在线导出需要自行安装 tdl 并准备合法登录会话、存储与代理配置。离线导入已有 JSON 不等于在线账号验证。先按 SKILL.md 的字段定义准备 task.json。

安装时完整复制 `tg转录_v1.0.2/`，由宿主按入口的 `name` 识别。宿主加载与脚本依赖是两件事；先看[通用安装说明](../getting-started.md)，再按下方原始文档准备。

## 使用流程

1. 选定单个对象、小时间窗与附件类型，说明是否下载媒体。
2. 校验任务配置，再检查会话与输出位置。
3. 执行所需 export / import / download / render 工序，保存状态目录。
4. 检查消息及附件是否齐全后再分享；分享副本先脱敏。中断后使用 resume，不盲目重建。

## 示例

可向已加载该技能的代理这样描述任务；请替换成自己的资料和范围：

> 用 tg-transcript 归档我指定聊天最近 7 天的文字和图片。先列对象、范围、预计操作与输出位置，等我确认范围；不要默认导出全账号或全部媒体。

### 命令入口

在技能根目录执行，使用已准备好的对应运行环境。`<…>` 是必须替换的占位符；下面的业务命令不是安装完成后的自动动作，也不代表本轮已执行真实业务。

```powershell
python -B -X utf8 scripts/archive.py --help
python -B -X utf8 scripts/archive.py validate --job task.json
python -B -X utf8 scripts/archive.py status --job task.json
```

## 任务选择与恢复

任务至少明确：对象、范围、消息/媒体类型、输出形式、组织位置。`task.json` 的字段与取值按原入口定义填写，不用猜测 JSON 结构。

归档完成要分别检查消息、附件和所选视图。`status` 用来查看已准备任务的状态；`validate` 校验配置，不替代真实会话检查。对现有归档恢复前保存任务配置和状态目录。

## 边界与注意事项

- 这里的“转录”指消息归档，不是语音识别，也不负责向 Telegram 发送消息。
- 未知媒体类型保留 unknown，不把没有下载的附件标成完成。
- 账号会话、聊天内容、附件和数据库是私人数据；不要提交 GitHub。
- 分享文件与原始归档分开保存；删改原始库前备份配置、状态和附件。

## 遇到问题

| 现象 | 建议处理 |
| --- | --- |
| 账号或会话不可用 | 检查 tdl 的登录和 namespace/storage 配置，不在聊天里粘贴会话密钥。 |
| 附件缺失 | 核对任务选择、下载状态及原始媒体字段，不只看阅读页。 |
| 中断或限流 | 保留任务目录，按状态恢复；不要无限重试或扩大导出范围。 |

恢复操作前保留原始输入、配置（脱敏）、日志和状态库；不要先删除现场。备份至少包含用户数据和工序状态，不能只备份技能文件。
