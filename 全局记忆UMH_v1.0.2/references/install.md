# 安装、运行、迁移

1. 解压整个目录到稳定路径。`scripts/setup.mjs --check` 使用相邻 package 里的依赖，不会从原电脑取文件或联网下载。
2. 已安装 Node >=24.2 和 Python >=3.10；Python 在 PATH 中，或为 setup 指定 `--python <可执行路径>`。自定义 Python 启动服务时也要传 `--python`。
3. `setup.mjs --init --umh-home <绝对数据根>`。已有数据不清空；不要指向他人的备份、演练根或其他应用目录。
4. `umh.mjs start --umh-home <相同根>`；另开终端执行 status。服务是前台进程，保持运行。停止使用 `umh.mjs stop`，不要按 node/python 名称批量杀进程。
5. 先做真实客户端接入与测试。此分享包没有已配置的 MCP、模型或身份凭据。

本分发版没有任何自动自启动脚本或注册表文件。若接收者希望开机运行，确认授权后按其系统创建当前用户级隐藏启动项，并固定已经验证的 Node、技能脚本、数据根路径。不要复用他人的注册表文件。

搬移目录前，保留旧目录、计划及回执，先逐连接disconnect并核实removed，手工端先移除UI条目；再停服务、搬移、校验整包并从零生成计划。不得对活动连接重新preview，否则核心旧回执可能被覆盖；分享入口为此加了拒绝闸。若已经搬移，应先把旧运行目录恢复到原路径完成撤销，再迁移，不手写binding文件。升级/回退不应覆盖数据根；停服务后backup，恢复必须先在新的临时根用restore preview/apply验证。

分享时不要打包本机数据根、候选、记忆、日志、模型配置、认证文件或配置备份。默认家目录只是运行时解析值，不是发行包内硬编码路径。

故障：缺 Node/Python→手工准备依赖；缺文件/哈希错误→重新解压完整 ZIP；SERVICE_UNAVAILABLE→核实服务存活、数据根一致，服务重启后重连 MCP；BINDING_UNKNOWN→核实本次 apply/trust 已建立受信绑定。不得通过绕过信任校验解决。
