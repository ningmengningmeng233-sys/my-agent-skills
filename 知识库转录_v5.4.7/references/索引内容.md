# 知识库问答与检索：执行协议 v5.0

> **何时读取**：进入“问答(核心)”“精准定位”“跨资料对比”“知识创作”分支时读取本文件。
> **核心原则**：**精度优先（准一些、贵一些，回答到点子上），带精确原文行号与逐字引用**。

---

## 0. 问答授权与预算协议（核心硬门禁）

### 0.1 概括性授权
用户针对知识库提出任何问答需求，即默认构成对知识库已索引资料（`书导航/`、`段索引/`）的检索以及对相关段落 `原文/` 的深入核查授权。

### 0.2 核查预算上限与熔断规则（宋氏思考决议 2、7、13）
为了在保障极高精度的同时避免失控的全量阅读，严格执行**原文核查预算**：
- **单次问答原文核查上限**：最多核对 **最相关的 3 个段落原文**，或累计不超过 **30,000 行原文**。
- **超限暂停与询问话术**：
  当检索召回的相关段落超过 3 个（或总行数超过 3 万行）时，编排器在完整核查完最相关的 3 个段落后，**必须立即暂停核对**，并原样输出以下固定话术向用户汇报：
  > **「涉及 N 个段落，已核对最相关的 3 个，继续读完吗？」**
  （其中 N 为实际召回的相关段落总数）。
  - 用户回复“继续/是/读完”后，方可调阅剩余段落原文；
  - 用户若未要求继续，则基于已核对的 3 个最相关段落和其余段索引输出最高质量回答，并注明未深核段落。
- **严禁越界**：严禁读取知识库工作区外的任何文件。

## 一、四级渐进式读取层级

```text
用户提问
  ↓
【第1级：元数据与导航定位】
  读取《书导航/》对应资料概况与导航表，或调用本地向量双路召回：
  `python scripts/semantic_search.py "提问词" --lib "<知识库>"`
  快速锁定最相关的 Top-3 段索引文件（免 Token、毫秒级意图召回）
  ↓
【第2级：段索引（知识提取卡）】
  深入读取候选段索引文件的 `### 知识点条目`（[概念]/[方法]/[数据]/[观点]）、`### 关键引用`、`### 实体`
  提取段文件内精准行号。若段索引已完全满足提问要求，可直接形成高可信回答
  ↓
【第3级：多段关联与交叉验证】
  若问题涉及多处定义、全书/全文档对比，关联读取多个段索引，梳理知识脉络与实体链条
  ↓
【第4级：原文深核（受预算约束）】
  依据段索引中的精确行号，打开对应 `原文/` 段文件，核对上下文前后 20~50 行
  确保引用的逐字准确性，确认无断章取义后组织最终回答
```

## 二、回答结构与交付规范

精准问答的最终输出必须包含三要素：

### 1. 核心回答（回答到点子上）
直截了当地回答用户提问的核心，语言严谨精炼，消除套话和废话，优先使用结构化小节展开论述。

### 2. 精准出处（精准至行号）
每个核心结论或论点必须后附可点击的原文路径与行号：
- 格式：`[资料名 原文/路径/文件名.md:行号]`
- 示例：`根据《系统架构设计》[原文/架构设计-张工/架构设计-第1章~第5章-001.md:128]`

### 3. 逐字关键引用（字字对齐）
列出支撑结论的原文原句（保留原貌）：
```markdown
> "分布式事务采用两阶段提交协议时，协调者单点故障可能导致参与者资源长期锁定。"
> —— 出处：[原文/架构设计-张工/架构设计-第1章~第5章-001.md:135]
```

## 三、跨资料比对与多书检索

当知识库包含多本长书及《独立文档集》时：
1. 先查各书导航及《独立文档集.md》书导航；
2. 如启用向量辅助检索（`INDEX_ENABLE_SEMANTIC=true`），调用 `semantic_search.py` 给出跨书候选章节/小节分数；
3. 比对时注明不同资料或作者的观点差异、数据指标口径差异；
4. 严格遵守单次最多深入核对 3 个段落原文的预算限制。

## 四、知识创作（轻量入口）

基于知识库已有索引产出衍生材料（如技术综述、核心概念速查表、主题大纲）：
1. 必须在产物末尾附带《知识溯源与引用清单》；
2. 清单列出涉及的书导航、段索引及关键原文出处；
3. 杜绝无中生有的幻觉，知识库无记载的内容明确声明“资料未提及”。
